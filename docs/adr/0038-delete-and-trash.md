# 0038 删除与回收站：项目、任务、笔记和对话

- 状态：Accepted（2026-11-06 人类批准；D1-1 契约已实现）
- 日期：2026-11-06
- 领域：数据 | AI 协作与权限
- 影响：新增契约（向后兼容的新增，不改已有字段）：`work.task.delete`、`work.project.delete`、
  知识笔记删除请求、助手对话删除请求，以及回收站的 `trash.list` / `trash.restore` / `trash.purge`；
  `docs/design/work.md`、`knowledge.md`、`assistant.md`、`security.md`、`web.md` 随实现同步修改。
- 实施说明：[D1-0](../tasks/D1-0-delete-and-trash.md)

## 背景

现在项目、任务、笔记和助手对话都只能新建和修改，不能删除。试用中会产生测试任务、建错的项目、
写到一半放弃的笔记和无用的对话，只能留在列表里。人类在 2026-11-06 要求为这四类对象提供删除按钮，
并在同一次对话中选择：删除后进回收站、可以恢复；删除有任务的项目时只删项目；
有 agent 正在执行这一轮的任务，先停止这一轮再删除。

## 决定

### 1. 删除就是移入回收站

- 四类对象的「删除」都是**移入回收站**：从列表、搜索、引用候选、相关推荐、今日概览和助手工具结果中消失，
  但数据保留，可以恢复。
- 回收站里的对象保留 **30 天**，到期由 Hub 永久删除；人也可以在回收站里立即「彻底删除」。
  彻底删除不可撤销，界面要二次确认。
- 回收站按删除时间倒序列出，显示类型、标题、删除时间、删除者和到期时间。

### 2. 各类对象的规则

**任务**
- 有 agent 正在执行这一轮时，删除在**同一事务**里先按 `work.task.finish outcome=cancelled` 的语义停掉这一轮，
  再移入回收站；确认框必须写明「会先停止 X 正在进行的一轮」。
- 其他任务的 `parent` / `dependencies` 指向它时不级联修改，保持原 ID；界面把它显示为「已删除的任务」。
- 它的执行记录（Job、日志、产物）属于审计记录，删除和彻底删除都**不删除**执行记录；执行页面显示「任务已删除」。
- 恢复后结局保持删除时的状态；删除时被停掉的那一轮不会自动重新开始。

**项目**
- 只删项目本身。项目下的任务在同一事务里把 `project` 置空（各自 revision 递增），变成「无项目」。
- 回收站记录被移出的任务 ID。恢复项目时，其中**仍然没有项目**的任务重新挂回；已被移到别的项目的任务不动。

**笔记**
- 笔记文件从原位置移到 vault 根目录的 `.trash/` 下（保留原相对路径；同名冲突时加后缀），由 Hub 的自动提交记录这次移动。
  以 `.` 开头的目录本来就不参与索引和链接图，所以移入后自然从知识库中消失。
- 原文件内容不改，`id` 不变；其他笔记指向它的链接变成悬空链接（现有行为），恢复后自动恢复。
- 恢复时移回原路径；原路径已被占用时恢复到同目录下加后缀的文件名，并告诉人。
- 彻底删除时删除 `.trash/` 中的文件并提交；Git 历史仍保留旧版本，这是 vault 的一般性质，不是 Lumio 的恢复手段。
- 只能删除 Lumio 认识、有稳定 ID 的知识笔记；`life/` 下的私密内容与旧格式的 Task/Project/Routine 笔记不在此范围。

**对话**
- 正在生成回复的对话先停止生成，再移入回收站。
- 从对话中保存的记忆是独立的显式记录，删除对话不删除记忆。

### 3. 契约与幂等

- 所有删除、恢复、彻底删除都是带 `request_id` 的写操作，重复提交返回同一结果，不产生第二次删除。
- 任务、项目、笔记的删除都带 `expected_revision`；版本已变时返回 `CONFLICT`，让人看过最新内容再决定。
- 已在回收站的对象，普通读取返回 `NOT_FOUND`，`error.reason` 为 `trashed`（不新增错误码），界面据此显示「已删除」；
  回收站接口返回摘要（类型、ID、标题、删除时间、删除者、到期时间），恢复后对象回到删除前的状态。
- 具体字段由实现切片 D1-0 在 `packages/schema` 中起草，本 ADR 批准后按切片实现，不另写 ADR。

### 4. 权限

- 删除、恢复、彻底删除**只有人**可以做。agent（包括内置助手和外部 agent）请求时直接拒绝，也不生成提议，
  与现有「删除归档拒绝」的规则一致（ADR 0029、0031、0032）。这些操作不加入 agent 可见的能力目录。

## 后果

- 好处：误删可以恢复；执行记录与链接不会因删除而悬空或丢失；笔记仍是 vault 里的普通文件，用户在外部编辑器里也能看到 `.trash/`。
- 代价：多了回收站这一份状态和到期清理；项目删除会修改其下任务的 revision，正在打开这些任务的页面会遇到版本冲突提示。
- 以后若要批量删除或按项目整体删除（连同任务），在本 ADR 的回收站上增加新操作，不改变本 ADR 的语义。
