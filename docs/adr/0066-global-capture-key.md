# 0066 全局捕获键：一个键 + 光标指点 + 语音，在任何 App 里存资料或问助手

- 状态：Accepted（2026-11-15 人类同意方向，要求写成 ADR 与开发文档后直接合入主线、交 Codex 开发。契约在 C1-1 起草，按 AGENTS.md 第 1 条由人批准后才合并）
- 日期：2026-11-15
- 领域：契约、安全与隐私、客户端、Assistant、知识
- 关联：ADR 0002（全 TypeScript）、0027（原生 Mac App 以后另写 ADR）、0041（AI 配置底座）、0055（语音）、0057 / 0065（Inbox 与资料）、
  0059（单入口助手）、0060（工作台焦点与展示）、0061（判断闸门）；任务 C1-0

## 背景

人在小红书上看到一段话想记下来，要截屏、识字、复制到笔记 App、整理格式，才算记完。讨论中归纳出阻力的两个来源：
**切换页面打断状态**，**支线操作太长打断状态**。只要有一个不切页面、一两秒就能做完的操作，人就愿意用。
参照物是游戏里的轮盘信号（LoL）和情境信号（Apex：只有一个键，意思由准星指着什么决定），以及"Put-That-There"式的语音加指点。

Lumio 里已经有：浏览器插件（只在浏览器里）、主对话能看到人在 Lumio 里看什么（ADR 0060 的焦点）、内置语音（ADR 0055）、
Inbox 存下即入库不分拣（ADR 0065）。缺的是 **Lumio 和浏览器以外**：任意 App 里的内容。

2026-11-15 人提出并确认的方向：

- 一个专用键。按一下就把当前看到的内容存进知识库；类型、标签、关联交给 AI 判断，人不做任何选择。
- 用截图获取内容，不给任何 App 做适配。
- 用**鼠标光标的位置**表示"这里"，不用画批注。
- 以语音为主：按住说"记一下，这和 wrapper 那篇有关""这段什么意思""把这里发给某某"，复用前台主对话。

讨论中补充、人认可的要点：截图只做兜底，能从系统拿到结构化信息（选中文字、网址、窗口标题）就一起拿；
选中文字比光标更准；轻点静默收藏、按住说话；只截当前窗口；按下要有即时反馈。

## 决定

### 1. 一个独立的 macOS 原生小助手，是 human 客户端，不是 Runtime

- 新增 `apps/desktop`：常驻菜单栏的 macOS 小程序。它和 Web、浏览器插件一样是**人的入口**，用配对得到的 human 令牌直连 Hub，令牌存在 macOS 钥匙串。
- 截屏、全局按键、读光标与选中文字需要系统的屏幕录制、辅助功能权限，PWA 拿不到，所以必须是原生程序。
- **不放进 Runtime**：Runtime 是给 agent 干活的执行器。把截屏能力放进 Runtime，就等于给 agent 留了看屏幕的路径；
  ADR 0055 已经因同样的理由否决了让 Runtime 模拟系统按键。
- **Hub 不能让小助手截屏**：小助手不接受 Hub 下发的任何截取或录音指令，只在人按下物理按键时采集。agent、runtime 身份没有任何途径触发采集。
- **用 Swift 写**，这是 ADR 0002"全部 TypeScript"的唯一例外。理由：ScreenCaptureKit、辅助功能 API、全局按键、Vision 文字识别、麦克风都是系统原生接口，
  Swift 直接调用最省事，产物小，常驻内存低。小助手只做采集、本地文字识别和 HTTP 调用，**所有业务规则留在 Hub**，Swift 代码保持薄。
  用 SwiftPM 构建，不提交 Xcode 工程文件。
- 首版只支持 macOS。手机上 iOS 不允许这类全局采集，以后用分享菜单或"轻点背面 + 快捷指令"做弱化版，另行决定。

### 2. 交互：轻点存，按住说

| 操作 | 结果 |
|---|---|
| **轻点**（按下到松开短于阈值，默认 250 ms） | 静默收藏：采集一次"所见"（第 3 节），建一条捕获进入 Inbox 与知识库。不说话，不打开任何窗口 |
| **按住** | 采集"所见"，同时开始录音；松开后把识别出的话和"所见"一起作为一条人的消息发给主对话 |
| 按住时按 Esc | 取消，什么都不发，已上传的"所见"按第 5 节清理 |

- 触发键可以设置：键盘上的某个键（默认一个 F 键），也可以是鼠标侧键或其他鼠标按键。用鼠标侧键时，指点和触发在同一只手上，最符合"指着说"。
- **即时反馈**：按下时有提示音，屏幕角落出现小浮层（HUD），显示正在录音或正在保存；完成后显示一行结果（"已收藏 · 标题"、助手回复的前几句、"需要你确认"），几秒后消失。失败时同样显示原因，不静默失败。
- 不说话也能用：在实验室、图书馆等不方便说话的地方，轻点就够了。

### 3. "所见"（Glance）：截一张图，同时尽量拿到结构化信息

每次按键采集一份**所见**，内容如下：

| 字段 | 来源 | 说明 |
|---|---|---|
| 截图 | ScreenCaptureKit，**只截最前面那个窗口** | 不截整个屏幕，不截小助手自己的浮层；长边缩到上限（默认 2048 px） |
| 指点 | 按下那一刻的光标位置，加按住期间的光标轨迹（定频采样，点数有上限） | 换算成截图像素坐标；光标不在该窗口内时记为无指点 |
| 选中文字 | 辅助功能 API 读当前焦点元素的选中文字 | 有选中时以选中为准，比光标更准；长度有上限 |
| 本地识字 | macOS Vision 框架在小助手上识别截图中的文字（中英文），带每块文字的位置 | 本地完成，不花钱，不发给第三方 |
| App 与窗口 | 前台 App 的 bundle ID、名称，窗口标题 | 辅助功能 API |
| 网址 | 前台是已知浏览器（Safari、Chrome、Arc、Edge）时用 AppleScript 读当前标签页网址 | 需要"自动化"权限；拿不到就没有，不影响其余部分 |

- 截图在 Hub 上存为**托管文件**（ADR 0025），不进 vault；所见记录（新前缀 `gln_`）存在 `hub.sqlite`，属于 Hub 的跨模块协调数据，与捕获记录同级。
- **"指着哪里"的解析在 Hub 做**：有选中文字用选中文字；否则按光标位置和轨迹，从识字结果里取最近的、连成一段的文字块作为"指向的段落"；
  轨迹围出一块区域时取区域内的文字。发给模型的上下文里，在截图上标出光标位置，并附光标周围的局部放大图（只在第 6 节允许发图时）。
- **前台是 Lumio 自己时不截图**：网址属于本 Hub 的 Web 地址（或 Lumio 的 PWA 窗口）时，小助手只送网址，Hub 把路由解析成 ResourceRef，
  按 ADR 0060 的焦点处理。在 Lumio 页面里，现有的焦点快照比截图更准。

### 4. 去向：收藏走 Inbox，说话走主对话

**轻点 → 捕获**

- 捕获新增来源渠道 `desktop`，新增输入"所见 ID"（与网址、正文并列，三者至少有一个）。
- 生成的资料为 `source`（有网址时 `kind` 为 `web`，没有时为 `text`）。原文层（ADR 0057 第 1 节）写成 Markdown：
  开头是"指向的段落"，下面是整窗识字结果；frontmatter 照常记 `url`（有的话）、`captured`、`extractor`，并加记截图的托管文件 ID、App 与窗口标题。
  AI 卡片照常生成（ADR 0065 的四项），以指向的段落为重点。
- **同一网址不去重**：从同一页面截不同的段落是正常用法，所见捕获不按网址合并，每次都是一条新资料。
- 网址是 arXiv、DOI 等论文链接时，照常走论文路径（ADR 0004 的去重与元数据），所见作为附带的"当时看的是哪一段"记在捕获里。

**按住说话 → 主对话**

- 语音沿用 ADR 0055 的 `/v2/speech/transcribe` 协议：小助手采 16 kHz 单声道 PCM16 直连 Hub，用 human 令牌，热词与隐私规则不变。
- 识别结果和所见 ID 一起作为**人的消息**发给主对话（ADR 0059）。主对话请求新增可选的 `glance` 字段，与 `focus` 二选一。
  助手每轮的上下文中放入：App、窗口标题、网址、选中文字、指向的段落、整窗识字的摘录（有预算上限），并标明这是屏幕内容。
- 主对话里新增一个助手工具 **`capture.glance`**：把本条人的消息所附的所见存为资料（等同轻点）。
  它和 `ui.*` 展示工具一样，只注册给 human 拥有的主对话里的内置助手，不进入外部 agent 的能力目录；
  **只能指向当前这条人的消息所附的所见**，不能存任意内容。存资料只是新增、可移除，人在同一句话里说了"记一下"，所以不需要另外确认。
- "发给某某"这类有对外副作用的动作照常走能力目录、提议与批准（ADR 0029、0056、0061）。现在没有对应能力的，助手直接说做不到，不另开通道。
- 回复显示在小助手的浮层里（只显示文字，可展开），提供"在 Lumio 中打开"。需要确认的提议，浮层只提示"需要你确认"并带人去 Lumio；
  首版不在小助手里做批准。工作台展示动作（`ui.*`）不在小助手里执行。语音合成以后按 ADR 0055 第 7 节接入。

### 5. 隐私与保留

- **只截前台窗口，只在按键时截**，没有后台持续采集，没有录屏。
- **排除名单**：前台是排除名单里的 App 时不截图、不识字，只在浮层提示"这个 App 不截取"。默认名单含密码管理器、钥匙串访问、系统设置；人可以增删。
  浏览器的隐私窗口能识别时同样不截。
- **截图保留**：变成资料的截图随资料保存，资料移除时一起进回收站（ADR 0038）。只用于对话、没有存成资料的截图，托管文件在保留期（默认 30 天）后删除；
  请求快照里记录实际发给模型的内容（文字原样保留，图片只记文件 ID 与 sha256），文件删除后快照仍在。取消的按住（Esc）立即删除。
- **只有 human**：`/v2/glances` 只授予 human。agent 和 runtime 能读的只有已经存成资料的部分（按现有原文读取规则）以及主对话上下文里实际放入的文字。
- **屏幕内容不可信**：截图里可能有别人写给 AI 的指令。识字结果、指向的段落、窗口标题都作为数据放在明确的边界内，和 ADR 0057 第 4 节对原文的处理一样；
  屏幕上出现"同意"之类的字样**不能作为人批准任何事的证据**（同 ADR 0060 对选中文字的规定）。批准只来自人的话（ADR 0061）或点击。
- 设置页写明：截图与识字在本机完成；开启第 6 节的发图后，截图会发给哪个服务商。

### 6. 模型：默认只发文字，看图是可选项

- **默认不把截图发给任何模型**：识字在本机完成，Hub 用识字结果和指点挑出段落，卡片与主对话都只用文字。成本最低，屏幕图像也不出本机与 Hub。
- **可选：看图**。新增 AI 用途 `knowledge.vision`（沿用 Connection / Profile / 用途绑定，ADR 0041），绑定了支持图像输入的模型后：
  - 捕获时把截图（标出光标）交给它，整理出更干净的 Markdown（表格、公式、排版混乱的页面识字效果差时有用），替换识字结果作为原文；
  - 主对话里有所见时，把截图与局部放大图附给助手模型（需要模型适配层支持图像输入，作为后续切片，见 C1-7）。
- 没有绑定时一切照常，只是没有看图这一步。

### 7. 契约变化（C1-1 起草，人批准后合并）

- 新文件 `packages/schema/src/glance.ts`：`Glance`（`gln_`）、`GlanceCreate`（元数据：App、窗口、网址、选中文字、指点与轨迹、识字块）、
  `GLANCE_LIMITS`（截图字节与尺寸、轨迹点数、选中文字与识字总长、保留天数默认值）、上传接口 `POST /v2/glances`（multipart：元数据 JSON + 截图）。
- `CaptureChannel` 增加 `desktop`；`CaptureCreate` 增加可选 `glance`，"网址或正文至少一个"改为"网址、正文、所见至少一个"。
- `AssistantChatRequest` 增加可选 `glance`，与 `focus` 不能同时出现；非主对话带 `glance` 返回 INVALID。
- `KnowledgeAIPurpose` 增加 `knowledge.vision`。
- 主对话工具名单增加 `capture.glance`，不登记进 `CAPABILITIES`（测试保证）。
- 小助手发出的请求由 Swift 测试写成固定样例文件，Bun 契约测试用 `@lumio/schema` 校验这些样例，保证两边一致；不引入代码生成工具。

## 后果（好处 / 代价）

- 好处：
  - 任何 App 里看到的东西，一个键就进知识库，不切页面、不做选择；想问或想办事时按住说一句。
  - 不需要给任何 App 做适配；网页、PDF 阅读器、微信、小红书网页版、论文阅读器都一样。
  - 默认本机识字、只发文字，成本与隐私都可控；看图是可选增强。
  - 复用 Inbox、主对话、语音三套现有机制，Hub 只多一个所见记录和一个助手工具。
- 代价：
  - 仓库第一次出现非 TypeScript 的代码（Swift），构建与 CI 需要 macOS 环境；`bun run check` 在非 macOS 上跳过它，另有 macOS 专用检查。
  - 系统权限（屏幕录制、辅助功能、自动化、麦克风、输入监控）要逐个引导授权；签名身份变化会让 macOS 要求重新授权，开发时必须用固定的签名身份。
  - 只截一屏：长文章只能拿到当前可见部分。要整篇时用浏览器插件，这是两条互补的路径。
  - 光标并不总在注意力所在的位置（看文章时鼠标常停在别处）。靠"选中优先"和语音补充；指错时人在对话里一句话纠正。
  - 契约变更：见第 7 节。
- 否决的方案：
  - **把采集做进 Runtime**：给 agent 留了看屏幕的路径，且 Runtime 不应依赖桌面会话；ADR 0055 已因同样理由否决让 Runtime 注入按键。
  - **只做浏览器插件**：覆盖不了浏览器以外的 App，而这正是这次的问题。
  - **只截图、不取结构化信息**：OCR 有错字，丢失网址与出处，违背"读资料回原链接"（ADR 0065 第 4 节）。
  - **默认把截图发给云端看图模型**：每次按键都花钱，屏幕图像离开本机；本机识字对大多数文字页面已经够用。
  - **截整个屏幕**：会把通知、聊天、其他窗口一起带走。
  - **Electron / Tauri 写小助手**：两者拿辅助功能里的选中文字、ScreenCaptureKit 窗口截图、Vision 识字仍要写原生桥接，最后核心还是原生代码，却多一层运行时和体积；
    小助手不需要复杂界面，浮层用原生控件就够。ADR 0027 设想的"复用同一套前端"的原生 Mac App 仍可以以后另做，与本小助手不冲突。
  - **轮盘式多选项**：讨论中确认类型、标签、关联 AI 都能推断，AI 推断不了的"为什么存、想拿它干嘛"由语音补充，不需要人在采集时做选择。
