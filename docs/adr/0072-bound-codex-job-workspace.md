# 0072 按已登录 Codex Job 的工作目录启用交互

- 状态：Implemented
- 日期：2026-11-17
- 领域：执行器权限与沙箱
- 关联：ADR 0019、0069、0070

## 背景

人已在任务或项目指定工作目录，并在委派时确认。复用同机 Codex 登录的交互 Job 还要求管理员在执行器重复登记同一目录。一次工具批准仍只允许当前工具调用，工作目录是启动时独立校验的沙箱范围。

## 决定

- 人显式派出且复用自己同机 Codex 登录的交互 Job 使用现有的 owner、连接、Job 与 lease 绑定。执行器据该 Job 的工作目录建立沙箱。没有配置 `LUMIO_INTERACTIVE_JOB_ROOTS` 时，按已绑定 Job 的具体目录判断。配置了该变量时，目录还须落在明确允许的根下。
- 仅用 API 密钥的 Codex Job，以及 Claude Code 和 Pi 交互 Job，继续由已有的 Runtime 目录限制约束。本项规则沿用 Job 活动与交互接口和现有契约。
- Runtime 在启动前解析实际目录，拒绝整个用户家目录及其祖先、执行器状态、已知私有凭据目录和引擎所在目录。Git 授权路径也经过受保护目录检查。启动引擎前再次验证实际路径，前置钩子替换目录或符号链接后须重新派出。会话继续绑定原目录和登录代次。
- 同机 Hub 在派出交互 Job 前检查工作目录，拒绝与知识目录或 Hub 状态目录重叠的路径，包含原路径或符号链接指向的路径。该规则覆盖按任务派出的轮次与独立 Job。
