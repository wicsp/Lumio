# 0071 API 余额的监控阈值

- 状态：Accepted（2026-11-17 人类批准）
- 日期：2026-11-17
- 领域：契约
- 关联：ADR 0052

## 背景

侧栏用量指示器给订阅额度画「剩余百分比」细条，但 DeepSeek 这类 API 余额只有金额，没有上限，现在只能画虚线细条。
实际关心的是「余额够不够用一阵子」：每天只花几块钱的人，余额 100 元和 1000 元没有区别，余额跌到几块钱才要紧。

## 决定

- `AIQuotaSettings` 增加可选字段 `full_balance: AIDecimal`，非负，只填一个数字，不分币种：按侧栏显示的那笔余额计算（一个 API 连接实际只用一种货币）。界面名称为「监控阈值」，与已有的「余额低于」提醒阈值并列。
- 设了监控阈值时，细条长度 = min(余额 / 监控阈值, 1)：余额不低于监控阈值时一直是满的，低于时按它的百分比缩短。没设时画满格实线。
- 虚线细条只用于读不到读数的连接（凭据、出错、不支持等），表示没配置好。
- 颜色沿用现有规则，不新增判断：低于已有的「余额低于」提醒阈值变黄，DeepSeek 报告余额不足变红，其余灰色。
- 监控阈值只影响显示，Hub 只做校验和保存；修改它不重置已发出的提醒记录，也不触发通知。
- 字段可选，旧数据没有该字段即视为未设置，不需要迁移；旧 Web 不认识该字段时照常显示。

## 验收

1. Schema 测试：接受合法金额与缺省，拒绝负数和非法格式。
2. Hub 测试：保存并原样返回 `full_balance`，只改它时提醒去重记录保持不变。
3. Web 测试：余额高于、等于、低于监控阈值及未设置四种情况的细条长度；颜色与阈值、不可用状态的对应不变。

## 修订记录

- 2026-11-17：人类批准，界面名称定为「监控阈值」；未设置时画满格实线，虚线只表示读不到读数。
- 2026-11-17：人类要求只填一个数字，不按币种区分，`full_balance` 改为单个金额。
