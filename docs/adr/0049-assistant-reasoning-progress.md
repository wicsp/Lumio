# 0049 Assistant 的思考状态与流式展示

- 状态：Accepted（2026-11-10 用户批准）
- 日期：2026-11-10
- 接续：ADR 0041 的模型与思考配置、ADR 0042 的原生会话

## 问题

DeepSeek 开启思考模式后，Chat Completions 流可先返回 `delta.reasoning_content`，再返回正文或工具调用。Hub 已接收并保存成功调用的思考内容用于续接，只将正文发送到网页。原生 Codex 已通过 app-server 发布可展示的思考摘要，但使用独立的渲染路径。等待模型、确认收到思考输出和等待工具是不同状态，网页需要让用户区分。

## 提议

### 网页行为

- 发送消息后显示「等待模型」。每次工具执行结束并开始下一次模型请求时，重新进入「等待模型」。首个非空思考片段到达后显示「正在思考」。在没有收到片段时，等待时长和思考档位都不能证明模型已经开始输出思考。
- 首个片段到达时，在该轮回复内建立一个默认折叠的区域。展开后按顺序实时追加纯文本，保留用户的展开状态。DeepSeek 标为「思考过程」，原生 Codex 标为「思考摘要」。同一轮内多次模型调用的思考内容按调用分隔。
- 正文开始、进入工具阶段、等待审批或结束时，退出「正在思考」，由现有界面显示正文、工具、审批或结果。新的思考片段可以让同一轮再次进入思考状态。完成、失败、停止或断流后，当前页面上已收到的片段仍可查看，等待状态停止更新。纯正文模型不会创建空的折叠区。

### API 与存储

- 在 `packages/schema` 的 `AssistantEvent` 中增加两种严格事件。两者都带 `turn`，由 Hub 在该轮的事件流中按顺序交付。
  - API Assistant 在每次模型调用开始时发送 `model_waiting`，包括工具调用后的续接。
  - `reasoning` 承载非空、限长的 `delta`。本期只转发已验证的 DeepSeek 官方 Chat Completions 端点返回的 `reasoning_content`，沿用适配器已有的总响应体上限。模型端口新增可选的思考片段回调，其他适配器可维持原样。
- 客户端用请求头 `X-Lumio-Assistant-Progress: 1` 明确选择接收新增事件。旧客户端继续得到原有事件，新客户端连旧 Hub 时仍能显示正文与工具。非流式 JSON 响应结构、正文 token、工具执行顺序、终态、取消与重试规则沿用现有契约。进度事件只在当前已授权的聊天响应中发出。
- DeepSeek 折叠区首版只展示当前页面收到的片段，刷新或重开时不重放。已保存的续接状态保持原有内部用途，历史接口不新增原文读取路径。密文状态不出现在网页事件中。思考文本独立于回答正文，也不自动写入任务描述、讨论或 Job。

### Codex 与其他引擎

- 在 Lumio 内选择原生 Codex Profile 时，复用现有带序号的原生会话事件读取路径，将 `reasoning` 摘要映射到同一套进度状态和折叠组件。实时更新和历史恢复共用这一事件来源，按会话序号避免重复追加。等待状态由已提交的轮次驱动，只有公开摘要到达才显示「正在思考」。原生事件协议、摘要历史、恢复和审批沿用现有规则。
- 外部 Codex 桌面或 CLI 对话独立运行。即使通过 Lumio skill 读写任务，也没有向网页提供聊天思考事件的入口。后台 Job 同样有独立的执行记录。本提议只覆盖 Lumio Assistant 内的对话。其他引擎日后可以接入同一组件，前提是其适配器能提供可展示的思考事件或摘要。

## 取舍与验收

直接把思考片段当正文 token 会把思考混入可保存的聊天正文，也会让界面无法区分等待、思考和回答。按轮次发送独立事件可以保留这些边界，并让严格校验的旧客户端继续工作。

- 先确保聊天传输可以跨过思考期间的静默。进度事件只报告应用已观察到的状态，不能用来取代聊天空闲超时的修复。
- 使用合成 DeepSeek SSE，覆盖首片段前静默超过 10 秒、先输出思考再开始正文、工具前后多次思考、关闭思考模式、取消、截断和失败。验证事件顺序、终态、限长、新旧客户端与 Hub 混用、JSON 兼容，以及正文和历史接口不含思考字段。
- 使用合成 Codex 原生事件，覆盖摘要实时追加、历史恢复、工具与审批切换，以及没有摘要时正常完成。核对折叠控件可用键盘操作，渲染不会把思考文本当作 HTML。
- 实现前批准本 ADR。批准后的实现 PR 同步更新 Assistant 和 Web 设计分册，并用 `@lumio/schema` 验证事件契约。测试使用合成数据，运行 `bun run check`。
