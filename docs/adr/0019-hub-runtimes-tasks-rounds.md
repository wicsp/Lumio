# 0019 P2 架构：Hub 与执行器、任务与轮次、例行任务

- 状态：Accepted（P2 实现）
- 日期：2026-10-26
- 领域：Hub 与运行、AI 协作与权限、数据、安全
- 影响：ADR 0005（修订）、ADR 0007、ADR 0016、ADR 0017、ADR 0018（第 3 节在 P2-4 执行）；`packages/schema` 的 task、routine、job、actor、operation

## 背景
人类现在的做法是在 Mac 上让 agent ssh 到服务器干活：改代码、跑实验、配环境、装软件。这要求 Mac 一直开着。
P2 要做到：把活交给服务器（或任何设备）上的 agent，它自己干完；定时工作流也不依赖 Mac。
同时要能在一个任务上和 AI 来回协作，以后还要支持多个 agent 之间交接，以及自研的 agent 执行框架。

走查设计时确定的几个事实：
- 笔记库不是一种"外置能力"，而是 Hub 自己的数据：Hub 派出的每件活最后都写回笔记库（ADR 0017 不变）。
- Hub 不一定一直在线（Hub 在 Mac 上时会被合上）。Hub 和执行器"失联"是正常情况，但通常不长；目标是中断后能接上。
- 现成的 agent（Codex、Claude Code、pi）是黑盒：主循环、上下文、权限、模型都在它们手里，从外面只能递指令、收结果。
  精细控制（每一轮的权限、上下文管理、模型路由、跨设备调用工具）只有自己掌握 agent 主循环才做得到。
- 实验结果怎么记录，是每个项目自己的事（写在项目的 `AGENTS.md` 里），不是 Lumio 的事。

## 决定

### 1. Hub 是中心，每台设备上有一个执行器
- **Hub** 管身份、任务、笔记库、派活计划、结果汇总与审计；**Hub 与笔记库永远在同一台机器上**（ADR 0017）。
- 每台设备上运行一个**执行器**（`apps/runtime`，`lumio-runtime`），向 Hub 登记能力：装了哪些 agent、版本、
  隔离级别，以及人配置的标签（如 `gpu:4`）。某台机器上的特殊资源就是那台执行器的特殊能力。
- **只有 Hub 能派活**；执行器不接受别处的任务。
- **执行器主动连接 Hub**（定时轮询，同时作为心跳），Hub 不连接执行器。Hub 仍只讲 HTTP（ADR 0007）。

### 2. 任务的两个字段：`status` 与 `turn`
- `status`：任务本身的生命周期，人和 AI 的任务通用，**只由人改**：
  `todo`（待办）、`active`（进行中）、`waiting`（等外部条件）、`paused`（主动搁置）、`done`（完成）、`cancelled`（不做了）。
  唯一例外：Hub 第一次派出时把 `todo` 改成 `active`。
- `turn`：现在轮到谁，只有负责人是 agent 的任务才有：`agent`（请 AI 开始或继续）、`human`（轮到人）。
  **人只能把它改成 `agent`，Hub 只能把它改成 `human`**；改成了不该自己改的值，Hub 忽略并在状态里提醒。
- 以后多个 agent 交接时，`turn` 可以扩展为具体的身份名（如 `codex@server`），结构不变。
- 执行中把 `status` 改成 `paused` 或 `cancelled`：Hub 取消正在执行的这一轮，并把 `turn` 改回 `human`。

### 3. 一个任务，很多轮
- **任务**是笔记库里的一篇笔记（`plan/tasks/`），由人写。**一轮（Job）**是让某个 agent 为它执行一次。
- 每一轮的汇报摘要写进任务笔记里的一个 AI 区块，标题写明第几轮、结果（完成 / 有问题等你回答 / 失败：原因）。
  人的意见写在 AI 区块外面。
- **AI 有问题时，这一轮以"等你回答"结束**，不让进程挂着等；人回答后派出下一轮，接着同一个会话继续。
- **派出下一轮的三种方式**都走同一个操作 `task.dispatch`（ADR 0016，经授权并留审计）：
  1. 在 Obsidian 里把 `turn` 改成 `agent`。Hub 等这篇笔记**安静 30 秒**再派；这期间改回去就算取消。
  2. `lumio task continue <任务>`。
  3. 以后飞书里的按钮（P3）。
- **不重复派**：任务已有一轮在执行时不再派；只在 `turn` "刚变成 `agent`"时派一次。
- **给 agent 的上下文**：能接着原会话时，只发人这次新写的内容（与上一轮派出时 Hub 存下的版本比较得出）；
  接不上时，发人写的部分（AI 区块以外）加最近一轮的汇报，不发更早的。
- 每一轮默认沿用上一轮的配置；实际用的配置（agent 与版本、执行器、目录、模型、隔离级别）原样记在 Job 记录里。

### 4. 结构化记录与笔记分开存放
- **笔记库**放给人看的：任务的要求与意见、每一轮的汇报摘要、少量平铺字段（`status`、`turn`、`assignee`、`workdir`、
  `model`、`gpus`、`timeout_minutes`、`project`、`due`）。
- **Hub 数据库**放给程序用的：每一轮的完整记录（配置、状态变化、时间、退出码、会话编号、开始与结束时的 git 提交、
  完整汇报、问题）、执行器登记、例行任务计划。
- **执行器本地文件**放完整的过程日志；数据库里只存路径。
- 项目的汇总（下面有几个任务、各到哪一步）由程序实时算出，不手写。

### 5. 执行器与 Hub 之间：一轮只执行一次，断开后能接上
- **身份**：执行器是新的身份角色 `runtime`，只能领取派给自己的活、回报结果、登记能力，**不能查询笔记库**。
- **指派**：派活时 Hub 就决定交给哪个执行器（任务写了设备就用它；没写就挑一个在线、装了该 agent 的；都不在线就在 Hub 排队）。
  每次指派生成一个 lease；Hub **只接受被指派的执行器、带着正确 lease 的回报**。
- **先存本地再确认**：执行器把 Job 写进本地队列之后，才告诉 Hub"收到"。确认后这一轮就归它负责；
  失联时 Hub **不会**把它转给别的执行器，只显示"失联"；要换人由人决定。
- **结果先存"待交回"**，Hub 确认收到后才删除；同一结果交回多次只记一次。
- **执行器重启**：未开始的继续排队；执行到一半的标为 `unknown`（情况不明），任务 `turn` 改回 `human`，由人决定。
- **一轮只执行一次，不自动重试**（修订 ADR 0005）：派给 agent 的活几乎都有副作用；想重试由人派出新的一轮。
- 每个执行器同时执行的轮数可配置，默认 1。

### 6. 例行任务
- 新的笔记类型 `routine`，位于 `plan/routines/`：一份模板，写要求、`schedule`（5 段 cron）、负责的 agent 和执行配置。
- Hub 把计划和例行任务的最新内容同步给执行器；**到点由执行器自己触发**，Hub 离线也照常执行，连上后再交回。
- **每次触发都是独立的新会话**，只看到模板里的要求；写了 `context: previous` 才带上上一次的摘要。
- 每次的结果**追加到这篇例行任务笔记里**（一个 AI 区块，标题是日期），不另建文件。
  想就某一次追问：`lumio routine followup <例行任务> <日期>`，从那一次开出一个普通任务。
- 每次触发的 Job 编号由"例行任务 + 计划触发时间"确定，重新同步不会产生重复。

### 7. P2 只用现成 agent 的非交互模式；安全底线
- 适配器：`codex exec`、`claude -p`、`pi -p`。接着上次的会话继续：pi 用 `--session-id`（由 Hub 起名）、
  Claude Code 用 `--session-id` / `--resume`、Codex 用 `codex exec resume`。适配器锁定验证过的版本范围（ADR 0005）。
- **每个适配器如实声明隔离级别**（`os`：agent 自带系统级沙箱已启用；`none`：没有沙箱）。没有沙箱也允许执行，
  但每一轮的记录里写明。
- **不做**：跨设备调用工具、每一轮单独的权限、上下文管理、模型路由（只保留"指定模型"）。
  这些留给以后自研的 agent：它作为执行器里的一种"引擎"接入，每一步经 Hub 授权与记录。
- 安全底线：
  - 执行器用普通账号运行，不用 root；**工作目录不能在笔记库里**；能用 agent 自带沙箱的就打开。
  - 高权限命令只能经 `lumio sudo <命令>` 发起，成为一个"需要批准"的操作 `exec.privileged`。
    P2 中只能由人在 Mac 上用命令批准；P3 加入飞书批准与审批模型。审批模型只看命令本身和人写的任务要求，
    不看 agent 的解释、不看 agent 读过的内容（防止被注入）。
  - AI 的汇报只是资料：不能改 `turn`、不能派新活、不能改状态。
  - 写回笔记前检查疑似卡号（ADR 0012）和常见密钥格式；命中的不写入，只提醒人去看日志。
  - 每一轮有最长运行时间（默认 2 小时）；取消时杀掉整个进程组；`gpus` 只把指定的 GPU 暴露给这一轮。

## 后果
- 好处：Hub 在 Mac 还是服务器都能用；Mac 合上时执行器照常工作；任务的完整过程留在笔记里；
  程序记录精确、可查询；以后的多 agent 交接与自研 agent 都有现成的位置。
- 代价：多了一个常驻进程（执行器）和一套同步协议；执行器失联期间取消不了、也读不到笔记库；
  现成 agent 的隔离能力参差不齐，P2 只能如实记录、无法强制；高权限命令在 P3 之前只能等人在 Mac 上批准。
