# 0033 项目工作目录、提议撤回与执行目标查询

- 状态：Accepted（2026-11-05 人类批准；R4-7 人工验收的反馈）
- 日期：2026-11-05
- 领域：数据 | AI 协作与权限 | Hub 与运行
- 影响：补充 ADR 0025（项目字段）、ADR 0031 第 2 节（委派提议）、ADR 0029（能力目录）；不改变 ADR 0032 的任务模型。
  契约：`WorkProject` 增加 `workdir`；`ProposalStatus` 增加 `withdrawn`，`Proposal` 增加 `superseded_by`；
  新增 `ExecutionTarget` 与 `ExecutionTargetListArgs`（R4-8a）。能力目录里的 `execution.target.list` 与撤回能力
  随实现由 R4-8b 机械加入（只登记名称、参数与结果，不改其他契约）。均为向后兼容的新增。
- 实施说明：[R4-8](../tasks/R4-8-acceptance-fixes.md)

## 背景

R4-7 验收（用 Lumio 开发 Lumio）中，人和 agent 各碰到三个问题：

1. **项目没有工作目录。** 任务只能各自设置工作目录，否则一律用执行器的 `~`；项目只有「仓库」字段（路径或 URL），
   系统不把它当工作目录用，人也不知道新建在项目里的任务会不会继承。
2. **agent 提议错了收不回。** Claude Code 把委派目标写成不存在的 `codex@mac`，改正后只能再提一条，
   旧提议仍挂在待批准里，人要逐条拒绝，容易混淆。
3. **agent 不知道有哪些执行目标。** 能力目录里没有查询执行器的能力；Hub 接受指向不存在目标的委派提议，
   直到人批准或执行时才失败。

## 决定

### 1. 项目工作目录，委派时继承

- `WorkProject` 增加可选的 `workdir`，规则与任务的 `workdir` 相同（绝对路径或以 `~/` 开头，指执行器上的目录）。
- 一轮实际使用的工作目录在**委派那一刻**确定：任务的 `workdir` → 所属项目的 `workdir` → `~`。
  不在新建任务时复制：改项目目录后，没有单独设置的任务随之改变；已经派出的轮次不受影响（Job 记录的是当时的目录）。
- 「vault 内的目录不能作为工作目录」等现有检查对最终目录生效。
- 每一轮的输入（ADR 0032 第 6 节）增加一行项目的 `repo`（如果有），让 agent 知道 PR 开在哪里。
- `repo` 保留，含义收窄为「代码仓库的 URL 或路径，只供参考」；不再承担工作目录的作用。

### 2. 提议撤回与自动取代

- `ProposalStatus` 增加 `withdrawn`（已撤回）。撤回的提议不能再被批准或拒绝，不出现在待批准列表与提醒数里，也不发通知。
- **自动取代**：同一作者对同一任务再提交同类的 Work 提议（委派对委派、设置计划对设置计划）时，
  它之前还在待批准的那一条在同一事务里改为 `withdrawn`，并记录 `superseded_by` 指向新提议。
- **主动撤回**：作者可以撤回自己还在待批准的提议（新命令，agent 与人都可以，只能撤回自己的）；人仍然可以拒绝任何提议。
- 已经发出的推送不撤回；点开后看到「已撤回」。撤回与取代都写审计。

### 3. 查询执行目标，提议时校验

- 新增只读能力 `execution.target.list`：返回所有可委派的目标 `ExecutionTarget`
  （`target` 如 `codex@macsp`、执行器名、引擎名与版本、是否在线）。agent 与人都可以读；不含令牌、标签以外的配置。
- 委派（`to`）与交接计划里每个 agent 步骤的 `agent`，在**命令或提议提交时**就校验：
  必须是已登记执行器上已登记的引擎；不带 `@` 的写法指 Hub 所在机器的执行器（与现有规则一致）。
  不存在时返回 INVALID，并在说明里列出可用的目标。离线的目标允许提交，但结果里注明离线。
- 计划模板不校验目标（模板可能在别的环境使用），套用到任务时随 `plan.set` 校验。

## 不在本 ADR 内

- CLI 帮助、skill 文档的完整性、连接错误的说明属于实现质量，在 R4-8 任务说明里列出，不需要决定。
- Web 的实时刷新先在网页内完成（重新获得焦点、收到推送、可见时定时刷新）；Hub 的事件流以后需要时再立 ADR。

## 后果

- 好处：同一项目的任务不必逐个设置目录；agent 改正提议不再留下垃圾；错误目标在提议时就被拦下，并告诉 agent 有哪些可选。
- 代价：契约新增字段和状态；Hub 的委派与计划路径多一次目标查询；Web 与 CLI 要显示「已撤回」和继承来的目录。
- 风险：执行器改名后，引用旧名字的计划在下一次 `plan.set` 或委派时才会报错；已保存的计划不会被自动改写。
