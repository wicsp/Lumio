# 0032 任务模型：结局、轮到谁、事件；交接计划取代流程

- 状态：Accepted（2026-11-04 人类在对话中提出按第一性原理重新梳理，并批准起草与方向）
- 日期：2026-11-04
- 领域：数据 | AI 协作与权限 | Hub 与运行 | 客户端
- 影响：取代 ADR 0025 中任务的 `status` 与 `assignee`（负责人）、ADR 0029 第 3 节对任务状态的限制、
  ADR 0030 第 1、3 节（「需要你处理」的推算方式与「已查看」）、ADR 0031 第 3 节（流程，改为本 ADR 第 5 节的交接计划，0031 同步修订）。
  项目的状态不在本 ADR 内，暂不改变。契约：`WorkTask` 升到 schema_version 3，由 R4-1b 起草、R4-2 切换。
- 实施说明：[R4-0](../tasks/R4-0-workflows-delegation-push.md)

## 背景

到 R3 为止，任务的「状态」分散在七处：任务状态（待办 / 进行中 / 等待中 / 暂停 / 完成 / 取消，人手动设置，委派时还会被自动改成进行中）、
负责人（改了不会执行）、轮次状态（八种）、轮次的「已写回」与「已查看」、推算出来的「需要你处理」、流程运行状态、提议状态。
它们互相重叠：三种「等待」、三种「谁」（负责人、实际在跑的 agent、流程步骤里的 agent）、两种「暂停」；
「已查看」是在弥补一个缺失的状态（这件事在我手里，但我暂时不处理）；「进行中」不说明是谁在做。作者认为这套设计不够简洁，要求按第一性原理重新梳理。

DeepSeek Harness 团队 2026-10-31 的《Super-agent 设计探索》提供了参照：任务是一串只追加的事件（Thread），状态从事件推出；
上下文用 Inline & Spill 与链式召回按需取回；只在需要人决定或验收时才打扰人；用独立的 Watchdog 检查进展。本 ADR 吸收其中适合个人系统的部分，
但调度与权限保持确定、可审计，不交给 LLM 决定。

## 决定

### 1. 任务只回答三个问题
任务存在是为了达成一个只有人能判断是否达成的结果。任何时刻只需要回答：

| 问题 | 字段 | 取值 | 谁能改 |
|---|---|---|---|
| 结束了吗？ | `outcome` | `open` / `done` / `cancelled` | 只有人 |
| 现在轮到谁？ | `turn` | 持有者 + 原因 + 时间 | 见第 3 节 |
| 发生过什么？ | 事件 | 讨论、轮次、交接记录，只追加 | 由各自的操作产生 |

原来的 `status` 与 `assignee` 不再存在；其他一切从这三样推出或不再需要。

### 2. 轮到谁
`turn` 由持有者和原因组成：

| 持有者 | 原因 | 含义 |
|---|---|---|
| 你（human） | `todo` | 你自己要做的事（新建任务的默认值） |
| | `answer` | agent 提了问题，等你回答 |
| | `review` | agent 交付了结果，或交接计划走到检查点，等你看 |
| | `failed` | 这一轮失败或结果不明，等你处理 |
| 某个 agent（如 `codex@mac`） | `working` | 正在执行第 N 轮（排队、运行等细节属于执行层） |
| 外部（external） | `waiting` | 在等别人或别的事（附一句说明，例如「等导师回复」） |
| 无人（nobody） | `on_hold` | 搁置，谁都不动 |

- 「需要你处理」就是**轮到你且原因是 `answer`、`review` 或 `failed`** 的任务；`todo` 出现在「今天 / 接下来」里，不催你。
- 「已查看」（ADR 0030）取消：在需要你处理的卡片上点「我自己来」，就是把原因改成 `todo`，任务仍在你手里但不再催。
- 前置任务未完成时，任务照常可以轮到你，界面标出「被前置任务阻塞」；不把依赖关系变成持有者。

### 3. 谁能改变「轮到谁」

| 动作 | 结果 | 人 | agent | 交接计划 |
|---|---|---|---|---|
| 委派 | 轮到某个 agent（开始新一轮，可附评论：回答并继续） | 可以 | 只能提议（需要你批准，ADR 0031 第 2 节） | 只能交给计划里写明的 agent |
| 一轮结束 | 按第 4 节交给下一个持有者 | — | — | 自动 |
| 交回 | 轮到你（`todo`）、外部（`waiting`）或无人（`on_hold`） | 可以 | 只能交给你或外部（低风险） | — |
| 完成 / 取消 / 重新打开 | 改 `outcome` | 只有人 | 不能 | 不能 |

- 一个任务同一时间只有一个持有者；轮到 agent 时，同一任务不能再开新一轮（与现有「同一任务只有一轮待完成」一致）。
- 完成或取消时，正在进行的一轮被取消；重新打开后轮到你（`todo`）。

### 4. 一轮 = 交出去再交回来
- 委派开始一轮：轮到该 agent（`working`）。一轮的结果只看四种：**交付**（done）、**提问**（waiting_for_human）、**失败**（failed / unknown）、**取消**。
- 一轮结束时：
  - 提问 → 轮到你（`answer`），不论有没有交接计划；你回答并继续后回到同一个 agent。
  - 失败 → 轮到你（`failed`）；你可以重试（再委派）或自己处理。
  - 取消 → 轮到你（`todo`）。
  - 交付 → 没有交接计划时轮到你（`review`）；有计划时按第 5 节交给下一阶段。
- 轮次的排队、领取、运行、日志、执行器等细节留在执行层；任务层只记录这一轮的结果与交接。

### 5. 交接计划（取代 ADR 0031 第 3 节的「流程」）
- 交接计划只回答一件事：**一轮交付之后交给谁**。它是有序的阶段列表，阶段只有两种：
  - **agent 阶段**：交给谁、这一阶段要做什么（说明）；可以声明「打回到」哪个 agent 阶段（agent 在汇报中写 `<lumio-outcome>changes</lumio-outcome>` 时走这里）。
  - **检查点**：轮到你（`review`），附一句提示，例如「是否合并？」。你在检查点只有固定的几种处理：**继续**（下一阶段）、**打回**（带评论回到某个 agent 阶段）、**完成**、**搁置**。
- 计划走完之后轮到你（`review`），验收由你标记完成。所以计划不需要单独的「验收步骤」，也不需要带选项的分支。
- 生效与保护：你设置的计划立即生效；agent 提出的计划是一条提议，你批准后生效。批准的是整个计划（阶段、执行者、轮数上限）。
  计划内的 agent 阶段之间自动委派，不再逐次批准。轮数上限缺省 8；达到上限、失败或提问时都会轮到你，并写明原因。
  没有单独的「流程停止」状态：停下就是轮到你，任务里记着计划走到哪一阶段，你选择「继续」即可接着走。
- 你描述的开发方式写成计划是：`codex@mac 实现` → `claude-code@mac review（可打回到实现）` → 检查点「是否合并？」→ `claude-code@mac 合并` → 结束（轮到你验收）。
- 常用计划可以存成模板。

### 6. 每一轮的输入：Inline & Spill
- 交给 agent 的输入只放必要的内容：任务标题与描述、这一阶段的说明（有计划时）、你上次交回以来的评论、上一轮汇报的摘要，
  以及更早轮次、相关笔记、关联 PR 等对象的 **ID 与一行摘要**。
- agent 需要更多时，用 Lumio skill 沿 ID 取回（链式召回，ADR 0029 的能力目录已提供 `work.task.show`、`execution.job.show`、`knowledge.note.show` 等）。
- 这替代「把整个讨论都塞进输入」，任务变长时 token 不会失控；讨论设计的结论应写进任务描述（如 ADR 与实现说明）。

### 7. 事件与交接记录
- 任务的历史只追加：讨论（评论）、轮次（开始与结果）、交接（谁在何时把「轮到谁」从谁改成谁、原因）、结局变化。
  界面的时间线按时间合并展示这些事件。
- 以后的扩展（不在本 ADR 实施）：任务可以关联外部线程（GitHub PR、CI），外部事件（review 评论、CI 结果、合并）作为事件追加到任务，
  并可以按确定的规则改变「轮到谁」（例如 PR 合并后轮到你验收）；独立的 Watchdog 定时检查轮次是否真的在推进，必要时把轮次交回给你。

### 8. 迁移
旧任务按以下规则一次性迁移到 schema_version 3，不需要人工干预：

| 旧状态 | 新的结局 | 新的轮到谁 |
|---|---|---|
| todo | open | 你（`todo`） |
| active | open | 有未结束的一轮 → 该 agent（`working`）；否则按最新一轮的结果（提问 → `answer`，交付 → `review`，失败 → `failed`）；没有轮次 → 你（`todo`） |
| waiting | open | 外部（`waiting`） |
| paused | open | 无人（`on_hold`） |
| done / cancelled | done / cancelled | 无人 |

负责人字段丢弃；它原本「下一轮默认交给谁」的作用由最近一轮的 agent 或交接计划承担。已标为「已查看」的轮次迁移为轮到你（`todo`）。

## 后果

- 好处：七处状态收敛为三个问题；每个页面都只回答「轮到谁、为什么」；「需要你处理」、推送、提醒数用同一个条件；
  交接计划比流程简单（没有带选项的分支和单独的停止状态），而人的拍板点不变。
- 代价：任务契约升版本并迁移数据；Hub、CLI、Web 都要改；ADR 0030 的部分实现（已查看、推算方式）被替换。
- 风险：迁移规则对「进行中但没有轮次」的任务做了猜测（轮到你 `todo`）；迁移前自动完整备份，迁移结果可以在界面上逐个调整。
