# 0023 补全时把"开关"字段写出来

- 状态：Implemented（P2-11）
- 日期：2026-10-28
- 领域：数据
- 影响：DESIGN 第 3.3 节"默认值不写进文件"增加例外；ADR 0008、0009 不变

## 背景
验收 P2-5 时，人要暂停一个例行任务，却在文件里找不到 `status`：它没写时默认为 `active`，按"默认值不写进文件"的规则从不出现。
需要人手动拨动的字段，看不见就不知道能拨。

## 决定
- 补全器在补全**任务**与**例行任务**时，`status` 缺失就写上默认值：任务 `todo`，例行任务 `active`。
- 负责人是 agent 的任务，`turn` 缺失时写上 `human`（派活的开关）。
- 只在字段缺失时写；人写了空值（`status:`）也视为缺失并写入默认值；已有的值不动。
- 其他类型与其他带默认值的字段仍按原规则：默认值不写进文件。
- `status` 与 `turn` 两个字段的含义不变（ADR 0019）：一轮结束后 `turn` 回到 `human` 就是"轮到你"，不另设状态。

## 后果
- 好处：开关在文件里看得见。
- 代价：已有的任务与例行任务在下次被 Hub 处理时会多出一两行（由 Hub 自动提交）。
