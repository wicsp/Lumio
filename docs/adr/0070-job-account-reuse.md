# 0070 交互 Job 复用 Codex 登录

- 状态：Implemented（2026-11-17 人类批准）
- 日期：2026-11-17
- 领域：契约、凭据授权、执行边界
- 关联：ADR 0042、0052、0069
- 任务：[Job 实时进度与同轮人工介入](../tasks/job-live-progress-and-control.md)

## 背景

Codex 的官方设备登录已在「AI 模型 → 连接」中管理，并由指定的 Runtime 保管和刷新。普通 Job 已能上报实时活动。ADR 0069 的首版交互适配器从本机环境读取专用 API 密钥，使已有 Codex 登录的用户仍需再配置一份提供商凭据才能同轮问答和审批。任务委派时只需选择执行器和引擎，并按需启用同轮交互。

## 决定

- 延用原有 AI 连接与登录入口。用户选择 Codex 执行器且显式要求同轮交互时，Hub 只考虑派出者自己在该 Runtime 上已认证的 Codex 连接。候选唯一时复用该连接。多个候选时，在原委派表单里选择一个已有连接。CLI 同样可在派出命令中指定已有连接。显示所选连接和 Runtime，便于确认使用的账号。用户不需要为 Job 再登录一次。
- 使用现有 AI 配置、委派、Job 活动和 Runtime 同步接口。委派的现有输入契约接受可选连接 ID。Job 的 Runtime 下发快照可携带 `connection`、`owner`、认证账户及代次、连接修订。Hub 从自己的连接和认证状态构造快照并核对人、引擎和 Runtime 身份，拒绝不匹配或缺少可用连接的请求。账户绑定仅发送给原来已验证的 Runtime 身份，授权快照仅限 Job Runtime 同步，对通用 Job 查询不输出。由 Runtime 通过已有活动协商报告新能力后，Hub 才能下发带绑定的 Job，旧执行器继续使用其已登记的认证方式。
- 同一 Runtime 进程由一个 `ConnectionAuth` 管理登录和刷新。原生 Assistant 与交互 Job 共用该实例，并各自维护独立的引擎进程、线程、工作目录、日志和权限。Job App Server 经私有 stdio 使用 `chatgptAuthTokens` 的认证和刷新协议。Runtime 启动与刷新时重新检验连接所有者、已批准的账户和登录代次，注销或切换账号使旧代次失效。账户的 refresh token 只保留在原认证通道。访问令牌经过 Runtime 内的私有进程通信交给 worker，再通过私有 stdio 交给引擎。登录票据和访问令牌均排除在 Hub、浏览器、业务日志、环境及子命令之外。
- 可在无现成 Codex 连接的设备上保留已启用的专用 API 密钥路径。界面明示适用认证方式。选定的连接失效、被注销、账户改变或无法确定归属时，明确失败。禁止在绑定失效时自动改用 API 计费或机器上的其他账户。已经开始的交互 Job 收到撤权信号后停止接收新的工具授权，并使用原有停止流程；刷新失败只交回当前轮次。
- Runtime 管理员保留对沙箱、允许访问的项目根和二进制版本的控制。Job 连接复用只向显式发起交互轮次的人开放。原有定时运行和普通轮次的认证及行为保持不变。工作流执行阶段沿用同一派出者核验和能力协商。
- Claude Code 的订阅连接目前用于额度和状态。当前基于 Claude Agent SDK 的交互路径继续使用提供商 API 密钥。复用个人 Claude Code 官方登录作为同轮执行的后续工作，需要先验证经过用户官方登录的未修改 CLI 能同时满足同轮审批、问答及现有 OS 隔离边界。[Anthropic 官方认证说明](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)

## 验收

1. 合成已登录 Codex 连接并部署可用沙箱。没有额外 API 密钥时，同一已登录连接用于 Assistant 与交互 Job。派出后能在现有执行详情看进度、答复和处理审批。
2. 现有普通轮次、离线设备、旧 Runtime、没有连接、多个连接及鉴权暂不可用均有单独测试。验证用户只能选择自己的同机连接，并验证定时和非 human 的派出路径不能获得用户订阅凭据。
3. 验证 Hub 快照和注册协商的 Schema，以及 Job 启动、并发刷新、登出、账号切换、过期、旧 Job 请求和失败路径。覆盖不会跨账户恢复，并验证访问票据只经 Runtime 内私有进程通信和引擎的私有 stdio。
4. 用隔离的引擎替身覆盖端到端协议。使用已获准的真实同机 Codex 登录验收问答和审批时，只执行合成任务和已允许的测试目录。
