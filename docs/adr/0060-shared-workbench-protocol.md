# 0060 共用工作台：助手操作页面的协议

- 状态：Accepted（2026-11-11 人类同意方向并要求先做着试用；同日 Codex 核实技术问题，按核实结果补充权限与投递规则）
- 日期：2026-11-11
- 领域：Assistant、Web、权限
- 关联：ADR 0029（能力目录）、0042（原生会话）、0050（聊天流事件）、0059（单入口助手）、0061（判断闸门）

## 背景

人希望界面基本保持现在的样子，也就是人熟悉的事项管理页面；所谓 AI 原生，是助手和人在同一个工作台上协作，就像对面坐着一个人，人自己不动手。
助手在讲解时要能"翻 PPT"：跳到相关页面、高亮几项待办、把搜到的资料、相关任务、依赖图摆出来，一边讲一边展示。
反过来，助手也要知道人此刻在看什么。

## 决定

### 1. 焦点：浏览器告诉助手人在看什么
- 每条发往主对话的消息附带**焦点快照**：当前路由、页面上的主对象 ResourceRef、选中的对象，以及选中文字。
- 上限：整包 UTF-8 不超过 8 KiB，选中文字不超过 512 个字素簇；浏览器按字素边界截断，Hub 收到后复验，超限拒绝。
- 不上传整页内容。助手要细节时按 ID 用现有读取工具取，照常受 agent 权限与私密规则约束。
- 焦点一旦发给模型，就按实际发送的内容计入请求快照（兼容 API 为模型请求快照，原生会话为交付快照），留存规则与对话相同。
- 选中文字是上下文数据，**不能作为人批准任何事的证据**（ADR 0061）。
- 焦点标签显示在输入框上方，人可以去掉或固定。

### 2. 展示动作：助手让页面动起来
- 新增一组**展示工具**，只在 human 拥有的主对话里提供给内置助手，不进入外部 agent 的能力目录：
  - `ui.navigate`：打开某个路由或对象。
  - `ui.highlight`：在当前页面高亮若干对象，可附一句说明。
  - `ui.show`：在侧滑面板里展示一组 ResourceRef、本轮工具结果中的搜索结果（标题、URL、摘要）或依赖图视图。
  - `ui.clear`：清除高亮与面板。
- **权限边界由 Hub 保证，不靠"只传 ID"**：浏览器用人的凭据读取内容，人能看到的比助手多。
  所以 Hub 在发出事件前逐项校验：路由在允许名单内；每个 ResourceRef 助手的 agent 身份都可见（私密实体、助手无权读取的对象一律拒绝）；
  搜索结果必须来自本轮已经返回给助手的工具结果。校验不通过的动作整体拒绝，并作为工具错误返回给助手。
- 校验通过后，Hub 经发起该轮的聊天流以事件下发（沿用 ADR 0050 的事件通道），由浏览器执行。
  兼容 API 助手直接调用；原生会话经 MCP 薄适配层调用，Hub 按 MCP 调用所属的活跃轮次找到对应聊天流。
- 原生会话的工具集合在创建时确定（ADR 0056），已有会话需要新建后才能使用展示工具。
- 展示动作不修改任何业务数据，不需要审批；对话里保留调用记录。

### 3. 投递与不抢屏幕
- 首期只投给**发起该轮的标签页**（NDJSON 流本身属于发消息的请求），不投给"最近活跃"的其他标签，避免动作落到另一个工作场景。
- 该标签页失焦、断线，或人在最近几秒内有输入、编辑、滚动、正在填写表单时，跳转降级为对话里的"带我过去"按钮；高亮与面板照常显示。
- 每次跳转都可以用后退键回到原页面。窄屏上面板改为底部抽屉。

### 4. 确认也发生在工作台上
- 需要人确认的事（ADR 0061 判断不了或不允许用对话授权的），在当前页面原地弹出确认卡片，展示完整操作内容；点击确认写入现有批准记录。

## 不做
- 不重做现有页面结构；不做画布式或多窗口的界面。
- 助手不能代替人点击按钮、填写表单或提交任何操作；它能做的数据修改只走能力目录。
