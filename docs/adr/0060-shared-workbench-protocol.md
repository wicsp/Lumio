# 0060 共用工作台：助手操作页面的协议

- 状态：Proposed（2026-11-11 人类同意方向，先做着试用；待 Codex 核实技术问题后转 Accepted）
- 日期：2026-11-11
- 领域：Assistant、Web
- 关联：ADR 0029（能力目录）、0050（聊天流事件）、0059（单入口助手）、0061（判断闸门）

## 背景

人希望界面基本保持现在的样子，也就是人熟悉的事项管理页面；所谓 AI 原生，是助手和人在同一个工作台上协作，就像对面坐着一个人，人自己不动手。
助手在讲解时要能"翻 PPT"：跳到相关页面、高亮几项待办、把搜到的资料、相关任务、依赖图摆出来，一边讲一边展示。
反过来，助手也要知道人此刻在看什么。

## 决定

### 1. 焦点：浏览器告诉助手人在看什么
- 每条发往主对话的消息附带**焦点快照**：当前路由、页面上的主对象 ResourceRef、选中的对象，以及选中文字（有长度上限）。
- 不上传整页内容。助手要细节时按 ID 用现有读取工具取，照常受 agent 权限与私密规则约束。
- 焦点标签显示在输入框上方，人可以去掉或固定。

### 2. 展示动作：助手让页面动起来
- 新增一组**展示动作**，只给内置助手（兼容 API 与原生会话）在 human 拥有的主对话中使用，不进入外部 agent 的能力目录：
  - `ui.navigate`：打开某个路由或对象。
  - `ui.highlight`：在当前页面高亮若干对象，可附一句说明。
  - `ui.show`：在侧滑面板里展示一组 ResourceRef、搜索结果（标题、URL、摘要）或依赖图视图。
  - `ui.clear`：清除高亮与面板。
- 展示动作经聊天流以事件下发（沿用 ADR 0050 的事件通道），由浏览器执行。
  **动作里只带路由和 ID**，内容由浏览器用人的凭据读取，因此助手不能借展示动作让人看到助手自己看不到的内容，也不能借它读取任何内容。
- 展示动作没有数据权限，不修改任何业务数据，不需要审批，不写审计（对话里保留记录即可）。

### 3. 不抢屏幕
- 人在最近几秒内有输入、编辑、滚动，或正在填写表单时，浏览器不执行跳转，改为在对话里显示"带我过去"按钮；高亮与面板照常显示。
- 每次跳转都可以用后退键回到原页面。窄屏上面板改为底部抽屉。

### 4. 确认也发生在工作台上
- 需要人确认的事（ADR 0061 判断不了或不允许用对话授权的），在当前页面原地弹出确认卡片，展示完整操作内容；点击确认与对话里说"可以"写同一条批准记录。

## 待 Codex 核实
1. 原生 Codex 会话能否通过 MCP 适配层发出展示动作，并以事件形式送达浏览器。
2. 焦点快照的大小上限与选中文字的截断方式；焦点是否计入模型请求快照（ADR 0029）。
3. 多个浏览器标签同时打开主对话时，展示动作发给哪一个（建议：最近活跃的标签）。

## 不做
- 不重做现有页面结构；不做画布式或多窗口的界面。
- 助手不能代替人点击按钮、填写表单或提交任何操作；它能做的数据修改只走能力目录。
