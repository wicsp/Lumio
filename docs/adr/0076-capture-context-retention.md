# 0076 捕获上下文的相关性保留

- 状态：Implemented（2026-11-18，人类预先授权 Accepted 后实施）
- 批准：人类已授权直接接受所需 ADR，完成后合并并部署。本轮要求沿用 OCR 与图片一起发送的方案，只保留原话和相关内容。
- 领域：捕获、助手、持久化与恢复
- 关联：ADR 0066、0074、0075

## 决定

- 捕获消息继续在当前模型调用中同时提供 OCR 与可用图片。最终回复使用 `GlanceAssistantReply` 携带答复和 `GlanceContextRetention`，在同一轮决定应保留的原文摘录、图片与页面来源，不增加独立的前置判断调用。
- 新捕获绑定消息时标记为 pending。Hub 只接受当前所见里能验证的逐字摘录。模型明确选择相关图片时保留该图片，选择来源时保留窗口、网址或 Lumio 对象。其余 OCR、选区、轨迹和无关来源在本轮结束时清理，无关图片删除托管文件。显式收藏为资料的所见仍由资料生命周期管理。
- 语音 Idea 先保存原话和原讨论链接。模型完成后才通过既有知识编辑回执附加已筛选的摘录和来源；使用版本检查，避免覆盖人的编辑。当前页面仅是候选背景，无关页面不作为本轮话题锚点。
- 捕获轮的持久模型快照只记录原话、所见 ID、模型设置和工具目录；完整 OCR 和页面候选只供当前模型调用。捕获轮的思考续接不长期保存，中间回复正文不作为人的笔记写入。这是模型快照不可变规则的捕获最小化例外，其他对话沿用原有快照。
- 模型失败、取消或未给出有效保留决定时，保存原话并清理临时所见。pending 决定支持重启后恢复清理；过滤后的待附加状态也可恢复，不必保留原始 OCR 等待 Idea 写入。旧的已完成所见不做历史重分类，不需要离线业务数据迁移。

## 边界

- 保留决定由模型作语义判断，摘录须通过原文校验。清理是 Hub 当前业务记录与托管文件的清理，不声称删除已有备份、SQLite 历史页或模型服务商已接收的内容。
- 此规则用于 Mac 与 iPhone 捕获消息，保持现有客户端 HTTP 请求及事件可用。`Glance.context_retention` 为可选字段，旧客户端可忽略。
