# 0030 一轮里的提问与验收：回答并继续、等你验收、需要你处理只看最新一轮

- 状态：Accepted（2026-11-04 人类在对话中确认方案与两处选择：要「已查看」，回答后默认派给同一个 agent、可改）
- 日期：2026-11-04
- 领域：Hub 与运行 | AI 协作与权限 | 客户端
- 影响：补充 ADR 0019、0025 的分轮执行（不改变「agent 不替人决定任务完成」）；DESIGN 第 4.7、4.8 节；
  `packages/schema` 的 `WorkTaskDispatch.args.comment`、`WorkTaskAcknowledge`、`WorkExecution.acknowledged`、`WorkAttention` 与能力 `work.attention.list`。
- 实施说明：[R3-0](../tasks/R3-0-capabilities-agent-access.md)（并入 R3-1、R3-2、R3-4、R3-5）

## 背景

作者用真实任务测试「agent 做到一半向人提问或二次确认」：底层已经可以，agent 在汇报里用 `<lumio-question>` 提问，
这一轮以 waiting_for_human 结束；人在任务讨论里回答，再派下一轮，agent 带着回答接续原会话。但界面没有闭环：

- 执行详情没有回答入口，要回到任务里评论、再点「下一轮」并选择 agent；
- 下一轮完成后，旧一轮的「等你回答」仍留在需要处理的列表里；
- 一轮正常结束后没有「等你验收」的状态，人不知道哪些结果在等自己看。

作者确认的逻辑：一轮成功只表示这一轮结束，整个任务是否完成由人决定（与 ADR 0019、0029 一致）。

## 决定

### 1. 「需要你处理」由 Hub 按每个任务最新的一轮计算
- `GET /v2/work/attention` 返回 `WorkAttention[]`，不存储、每次计算。只看每个任务**最新的、结果已写回的一轮**：
  - 在提问（waiting_for_human）→ `question`，带问题原文；
  - 正常结束（done）→ `review`，等人验收，带汇报开头；
  - 失败或结果不明（failed / unknown）→ `failed`。
- 以下任一情况发生即不再出现：派出新一轮；任务变为 done、cancelled 或 paused；这一轮被标为已查看。
  旧轮次因此不会残留。仍在运行或排队的轮次不出现。例行任务的轮次没有任务，不在此列（仍在执行页按 Job 显示）。
- 同时是一项读能力 `work.attention.list`，内置助手和外部 agent 都能回答「现在有什么要我处理」。

### 2. 回答并继续：一个操作
- `work.task.dispatch` 增加可选的 `comment`：先以调用者身份发表评论，再在同一事务里派出，下一轮的输入包含它；
  派出失败时评论也不保存。重试同一 `request_id` 不会重复评论。
- 界面在执行详情、任务页和「今日」的卡片上直接提供回答框，默认派给上一轮的同一个 agent，可以改。

### 3. 等你验收与「已查看」
- 验收卡片（review）提供三种处理：**标记完成**（人把任务改为 done）、**补充意见并继续**（回答并继续）、
  **已查看**（`work.task.acknowledge`，记录在 `WorkExecution.acknowledged`，不改任务状态；适合人要自己接着做或稍后再处理）。
- 执行失败的卡片提供「重试」（再派一轮）与「已查看」。
- `work.task.acknowledge` 只有人能用；agent 一律拒绝，也不在能力目录里（ADR 0029 第 3 节）。

### 4. 给 agent 的固定说明
- 需要补充信息或确认时，用 `<lumio-question>` 提出一个明确的问题并结束这一轮，不要猜测后继续做有风险的事。
- 做完时按「结果 / 改动 / 验证」汇报；不要宣布任务完成，完成由人决定。

## 后果

- 好处：提问、回答、验收形成闭环；需要处理的列表只反映现在真正要人做的事；任务完成仍由人确认。
- 代价：attention 每次计算，需要按任务取最新一轮（数据量小，必要时加索引）；派活命令多一个可选参数。
- 不做：一轮内部的实时问答（agent 进程不中断等待人），仍按「提问 → 结束本轮 → 回答后下一轮」进行。
