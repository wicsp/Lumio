# 0011 P1 的 Hub 设计：状态存放、链接、搜索、令牌与写入路径

- 状态：Accepted（P1 实现）
- 日期：2026-10-23
- 相关：ADR 0006、0007、0009、0010、0012

## 背景
P1 要实现 Hub：文件监听与自动补全、索引、搜索、提议队列，以及供 AI 使用的 CLI 查询命令。
开工前需要定下几个会影响数据和接口的设计。

## 决定

### 1. Hub 的状态与 vault 分开存放
- **vault**：知识的唯一事实来源，只放 Markdown（ADR 0007）。
- **Hub 状态目录**：默认 `~/.local/share/lumio/`，可配置，不在 iCloud 中。包含：
  - `index.sqlite`：**派生**索引（实体、链接、全文），可随时删除重建。
  - `hub.sqlite`：**运行状态**（令牌、提议队列，P2 起还有 job），不是知识，无法从 vault 重建。
- 理由：提议、令牌、job 是 Hub 的工作数据，不该出现在 Obsidian 里，也不该跟着 iCloud 同步到手机。
- 代价：`hub.sqlite` 需要单独备份（P1 中提供 `lumio hub backup`，复制到指定位置即可）。

### 2. 什么算"链接"
- 两种来源都计入链接图：frontmatter 的 `related`（列出 ID），以及正文中的 `[[名称]]`
  （按文件名解析；可带 `|别名`、`#标题`，解析时去掉）。
- 两者都属于人（ADR 0006）。**接受一条 AI 的链接提议时，Hub 只写 frontmatter 的 `related`，
  永远不修改正文。**
- 无法解析的 `[[名称]]` 记为"悬空链接"，在 `links` 结果中标出，不报错。

### 3. 搜索
- SQLite FTS5，`trigram` 分词器，覆盖中文和英文的子串搜索。
- **查询少于 3 个字符时退回 `LIKE` 子串匹配**：实测 trigram 对两个汉字的查询（如"来源"）返回空结果。
- 搜索范围：标题、正文、作者、citekey、tags。

### 4. 令牌分为两种角色
- `human`：所有操作，包括接受、拒绝提议。
- `agent`：查询与提交提议，**不能接受或拒绝提议**。这样 ADR 0006 由 Hub 在接口层强制执行，而不是靠 AI 自觉。
- **私密实体**（ADR 0012，`life/` 下）：`agent` 令牌在任何情况下都查不到；`human` 令牌须显式传入
  `--include-private`（API 参数 `include_private=true`）。本地模式（不经过 Hub）只能做到默认排除。
- 令牌只在创建时显示一次，Hub 只保存 SHA-256 哈希；可以单独吊销。

### 5. 写入路径（修订 ADR 0007 中"P0 的过渡"）
- **AI 的修改性写入必须经过 Hub**：P1 中唯一的此类写入是提议（`lumio propose …`），没有 Hub 时无法使用。
- **新建笔记和元数据补全**（`lumio new …`、`lumio sync`）在 P1 中仍可本地执行：它们只新建文件或补全缺失的
  元数据，不改动已有内容，性质等同于人在 Obsidian 中新建文件；Hub 的文件监听会照常处理这些文件。
- **查询**（`search`、`show`、`links`）两种模式都支持：设置了 `LUMIO_HUB_URL` 时走 Hub，否则直接读本地 vault。
  查询逻辑实现在 `packages/core`，Hub 与本地模式共用同一份代码。

### 6. 自动提交
- Hub 在 vault 无变化达到一段时间后（默认 5 分钟，可配置）自动提交一次，提交信息形如
  `lumio: auto-save 3 files`。vault 没有 git 仓库时跳过，不报错。
- Hub 启动时先完整执行一次补全与索引，覆盖 Hub 未运行期间（Mac 休眠、iPad 编辑）的改动。
- **提交前检查疑似卡号**（ADR 0012）：含疑似卡号的文件不提交、不进入全文索引，在状态中提醒人删除；
  提醒中只给出文件路径，不回显数字。其余文件照常提交。

## 后果
- 好处：知识与运行状态分离；中文短词也能搜到；AI 权限在接口层强制；不需要 Hub 也能用全部查询功能。
- 代价：多了一份需要备份的 `hub.sqlite`；P1 中仍有两条写入路径（Hub 与本地），直到以后把新建也收归 Hub。
