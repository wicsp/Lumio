# 0061 判断闸门：用 Jev 做对话授权、提醒分级与巡检判断

- 状态：Proposed（2026-11-11 人类同意方向，先做着试用；待 Codex 核实技术问题后转 Accepted）
- 日期：2026-11-11
- 领域：权限与安全、Assistant
- 关联：ADR 0016（操作与授权）、0029、0046（TypeSafe Jev 连接）、0049（阶段权限）、0056（助手提议）、0059、0060
- 参考：[TypeSafe Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[OpenAI Codex Auto-review](https://alignment.openai.com/auto-review)

## 背景

1. 人希望授权能在对话里完成：助手讲完一项问"这个可以做吗"，人说"可以"，这就是一次以人的身份做出的授权；
   说不清楚时在页面上弹框点确认。两种方式底层是同一件事。
2. 主对话里需要大量小判断：一个事件要不要打断人（ADR 0059 第 4 节）、一轮执行是在推进还是在空转（Watchdog）。
3. 这些判断如果交给主助手自己做，就是自己判断自己有没有被授权；读过的网页、邮件、执行输出里一旦有注入内容，
   主助手可能"以为"人同意了。业界已有把审批交给独立模型的做法（OpenAI Codex 的 Auto-review 用独立审核 agent 决定越界操作）。
4. TypeSafe 的 Jev 是一个"System One"决策模型：输入状态和带类型的问题（是非、选项、打分），只返回带概率的答案，不生成文字；
   厂商称延迟约 0.1–0.5 秒，每百万输入 token 0.042 美元，并声称概率经过校准，但目前公开的准确率数据主要是厂商自测。
   Lumio 已经可以保存 Jev 连接（ADR 0046），还没有使用。

## 决定

### 1. 判断闸门是 Hub 里的独立组件
- Hub 新增**判断闸门**：一个确定性的代码入口，内部调用决策模型。首个实现用 Jev；连接用统一 AI 配置的新用途绑定 `decision.gate`。
- 主助手（兼容 API 或原生会话）**不能调用、也不能看到**闸门的输入与结果，只能看到最终结论（已批准 / 待确认 / 未授权）。
- 闸门的输入受限：只给它判断所需的最少内容，**不给网页、邮件、资料原文、执行输出等外部内容**。

### 2. 对话授权
- 适用对象：主对话里助手提出的、仍待批准的提议（ADR 0056 的委派、设置计划，以及 ADR 0049 的阶段权限申请）。
- 提议在对话里显示为 **Hub 根据结构化操作渲染的卡片**，不用助手写的文字。人要看到卡片，才能用对话批准它。
- 人发出下一条消息时，Hub（不是助手）把以下内容交给闸门：
  - 状态：Hub 渲染的提议卡片文字、人的这条原话。不包含助手的任何文字。
  - 问题：这句话是否批准这项提议（是非）；批准的范围是否与提议一致（是非）；这句话是否拒绝这项提议（是非）。
- 结果按阈值处理（初始值，按实际数据调整）：
  - 批准概率 ≥ 0.95 且范围一致：Hub 以人的身份批准提议，对话里显示"已按你的回复批准"，附撤销入口（执行开始前可撤销）。
  - 拒绝概率 ≥ 0.95：Hub 以人的身份拒绝。
  - 其他情况：在页面上原地弹出确认卡片（ADR 0060 第 4 节），由人点击。
- 批准记录新增来源信息：`via: chat | button`，对话授权时记录人的消息 ID、决策模型版本与概率。审计照常记录 `decided_by` 为 human。
- 闸门只认 **role=user、来自 human 自己拥有的主对话**的消息；工具结果、助手消息、执行汇报里的"同意"一律无效。
- **永远只能点按钮**：`exec.privileged`、删除与彻底删除、`full` 访问范围或附带密钥的权限申请、修改或删除计划模板。
- 闸门不可用（未配置 Jev、超时、出错）时，退回按钮确认，不阻塞对话。

### 3. 提醒分级与巡检判断
- ADR 0059 第 4 节的事件分级：闸门对规则判断不了的事件回答一个三选一问题（重要 / 待处理 / 静默）；只给事件类型、对象标题和 Hub 生成的结构化摘要。
  置信度低时按"待处理"处理，不打扰人也不丢失。
- Watchdog 判断一轮是否在推进：给出同一轮相邻两次进度事件的结构化摘要（工具调用计数、改动文件数、最近错误类型），问"是否有实质进展"（是非）。只用于写巡检报告，不自动停止任何东西。

### 4. 数据去向
- 闸门的输入会发给 TypeSafe 的服务；设置页在 Jev 连接旁写明会发送的内容：提议卡片、人的原话、事件结构化摘要。
- 私密实体的内容不进入闸门；提议卡片里涉及私密实体时只显示类型，不显示标题。

## 待 Codex 核实
1. TypeSafe System One 接口的请求与答案格式、版本固定方式、超时与错误码；Hub 适配器按 ADR 0046 的固定地址实现。
2. 撤销窗口如何与"批准后立即派出"衔接（建议：对话授权的委派延迟几秒再派出，期间可撤销）。
3. 批准记录新增字段属于契约变更（`packages/schema/src/proposal.ts`），按 AGENTS.md 第 1 条另行批准。

## 不做
- 不用闸门替代 Hub 的 `authorize`：闸门只决定"人是否已经表态"，能不能做仍由现有权限表决定。
- 不让闸门处理高风险操作（第 2 节"永远只能点按钮"的清单）。
- 不把决策模型的结论当作对人的解释；需要说明理由时由主助手根据结论另外说明。
