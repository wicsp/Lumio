# 0080 个人日程、待办与生活日志

- 状态：Accepted（2026-11-18）
- 领域：Personal、Hub、Assistant、Storage、Web、CalDAV
- 任务：`task_01M7MYJRY2J4ZW91Z0Z8F14WJH`

## 背景

同一 HTTPS CalDAV 账户的两个集合已在真实 iPhone 上通过验证。日历拉取了 `VEVENT`，提醒事项拉取了 `VTODO`。用户在 Apple 日历勾选测试跑步待办，服务器收到 `PUT` 并返回 `204`，随后读回原 UID、`STATUS:COMPLETED`、`PERCENT-COMPLETE:100` 和 `COMPLETED:20261118T081630Z`。对应时间块仍为 11 月 19 日 18:00–19:00（新加坡时间）。明文 HTTP 连接时 iPhone 的验证请求以匿名身份到达，改用受信证书的 HTTPS 后认证通过。验证范围为两个集合的读取和单条普通待办的完成回写。

需要在 Lumio 聊天中安排个人日程、管理个人待办，以及把实际发生的事记录下来。现有 Work 管理项目、Agent 委派与验收，继续使用原任务模型。业务日志与个人经历各有自己的保留和访问规则。

## 1. 模块与数据归属

新增 **Personal** 业务模块，Web 提供「日程」「个人待办」「生活日志」三个视图。Personal 按现有业务包模式定义用例和存储端口，Hub 组装认证、审批及同步，Storage 负责 SQLite，CalDAV 适配器置于应用层。Today 可以并列展示日程和个人待办，开发任务、审批与 Agent 执行状态仍从 Work 和 Execution 读取。人可显式把 Work Task 关联到个人时间块，关联不推进 Work 状态。

| 对象 | 提议 ID 前缀 | 主要字段与语义 | 权威来源 |
|---|---|---|---|
| 个人日程 | `pev_` | 标题、起止、时区、全天标记、版本，可选关联待办或 Work Task。全天区间结束日为排他上界 | 独立 Radicale `VEVENT` 集合 |
| 个人待办 | `ptd_` | 标题、可选截止日期或时间、未完成/已完成、可用时的完成时间、版本。未指定日期的事项继续保留在清单 | 独立 Radicale `VTODO` 集合 |
| 生活日志 | `jrn_` | 发生时间或日期、记录时间、内容、版本、来源、修正或撤回关系。来源区分人工记录、聊天提议、从 CalDAV 观察到的完成/撤销 | Hub SQLite，独立于系统诊断日志、审计和知识库 |

日期类型保留 `YYYY-MM-DD`，日期时间用带偏移的 ISO 8601，并保留需要的 IANA 时区。待办的截止要求与日程占用的时间分别保存。改动、删除时间块和日程结束都不改变待办完成状态。CalDAV 不能原样表达的 Lumio 关联由 Personal 保存，按稳定 ID 查找。

第一版使用已经过真机验证的 Radicale，控制在 Lumio 专用的账户和两个集合内，以受信 HTTPS 接入。Hub 保留可重建投影、UID 到 Lumio ID 的持久映射、同步进度、待执行命令与回执。业务备份同时包含该专用 CalDAV 数据和对应的 Hub 数据，映射、日志和写入回执随 Hub 一同恢复。备份时暂停两端写入或使用受控一致快照，恢复先校验账户与集合映射，再对账。既有 Work 和 Apple 账户无需迁移。具体部署、版本固定、证书续期和备份演练放在实施任务验收。

采用这一分工，可用经过实测的协议服务处理 Apple 发现集合、条件写入和增量同步。将 CalDAV 直接实现于 Hub 会带来另一套客户端兼容与一致性验证，暂不采用。只读订阅无法记录 Apple 的完成回写。

## 2. 同步与日志事实

1. 仅同步由 human 配置的 HTTPS 账户与集合。持久化映射键为连接身份、集合身份、组件类型与 UID。`href` 是当前位置，ETag 是远端版本。未知集合中的相同 UID 不自动合并。重复日程的实例按组件 UID 加原始 `RECURRENCE-ID` 区分。
2. 首次扫描建立基线，既有完成事项默认不批量进入日志。随后以每集合的 `sync-token` 增量对账，提交投影、日志、去重回执与游标使用同一事务。遇到失效 token，完整对账后恢复增量。部分失败或分页中断保持未处理对象可重试，完整对账确认前不将暂时缺失的对象判为删除。
3. Hub 写入前持久化命令及唯一请求 ID。创建使用稳定远端 UID/路径与 `If-None-Match: *`，修改用批准时对应的 ETag 做 `If-Match`。收到 `412` 后重读状态，有冲突交给人重新确认。响应丢失时按原 UID、原请求和目标状态核实，不能确认就保留待核实状态。确认成功后保存回执，避免重启重试产生副本。审批状态与外部写入结果分别呈现。
4. 待办实际从未完成变成已完成时追加生活日志，并标明“标记为完成”及来源。优先用 `COMPLETED` 作为勾选时间，缺失时仅记录同步观察时间。重复拉取和同一状态的元数据变化不重复生成日志。观察到撤销完成时追加更正并关联原记录，界面显示更正后的状态。删除不产生完成记录。增量对账只承诺记录读到的状态变化，两次拉取之间被覆盖的变化可能不可见。
5. 用户可手工记录经历、结果或更正。到期的时间块仍是计划；用户确认参加、到场或完成后才写成实际经历。受影响的日志条目支持 human 更正或撤回。默认保存在私密生活日志；后续可由人选择条目，预览可沉淀的内容和来源，经确认走知识写入能力。首版不自动写 vault、扩充私密笔记权限或公开日志引用。

第一版写入覆盖单次日程和普通待办。读到重复规则、单次例外或不认识的属性时保留原条目，未验证的复杂对象保持只读，禁止通过普通编辑丢弃规则。重复待办要等 Apple 真机能识别并回写单次完成后，再为每次发生写入完成日志。日程邀请、共享日历、自动挪动其它日程另议。

## 3. Agent 接口与权限契约

在 `packages/schema` 能力目录新增以下接口，复用 Hub 授权、提议服务与前台展示。命令使用 `request_id`，更新使用 `expected_revision`；命令结果区分待批准、待同步、已确认、冲突与待核实。更新中缺失的字段保持原值，可清空字段显式传 `null`。`ResourceRef` 增加 Personal 对象类型；引用和来源解析始终先检查权限。

| 能力 | 首版参数与用途 | Agent 行为 |
|---|---|---|
| `personal.event.list` | 有界时间区间、时区、可选游标。返回时间表和可见范围的忙闲 | 已开启的前台所有者对话可查，默认只给排程所需字段 |
| `personal.todo.list` | 可选日期区间、完成状态、是否含无日期项、游标 | 同上 |
| `personal.event.create` / `.update` | 标题，起止/时区或全天范围，可选关联。更新附对象 ID 与版本 | 生成可审阅提议 |
| `personal.todo.create` / `.update` | 标题，可选截止日期/时间。更新附对象 ID 与版本 | 生成可审阅提议 |
| `personal.journal.list` | 有界日期范围、记录类型、游标 | human 可读。前台对话需要人当前轮显式选择可读取的范围 |
| `personal.journal.create` | 日期或时间、用户明确描述的内容，可选来源引用 | 生成可审阅提议，禁止用此能力伪造系统观察到的完成事件 |

人可通过 Apple 客户端或 Lumio 完成和撤销个人待办，Hub 对这两项另设 human 命令。删除、移动账户、取消和撤回日志保留 human 入口。首期的个人能力关闭时不进入工具目录，开启只作用于该所有者已授权的前台聊天。Hub 在能力注册、调用、批准执行和历史回放重新核对授权及可见范围。个人提议只能由所有者及获准提出它的前台对话读取，只有所有者能批准。默认提议列表、后台预读、通知及执行输入不携带个人内容。外部 Agent、后台 Watchdog 和 Runtime 默认没有个人数据权限。配置的 URL、口令、ETag、同步 token 及内部日志绝不交给模型。专用账户使用可撤销凭据，远端重定向或返回的路径不能把认证带到未配置的来源。

聊天示例为“明晚六点留 45 分钟跑步，另外提醒我周五前完成报销”。助手按用户时区查询空闲时间，展示分别可批准的日程和待办，注明日期、时间和所属集合。时区或日期不明确时请用户澄清。冲突提示包含时间范围，已有条目的详细内容仅按授权展示。批准后 Hub 写入并显示同步结果，任何来自日历标题、说明、旧消息或模型输出的字符串都不授予写权限。敏感的个人数据不进入默认知识检索或后台摘要，低层审计只留对象 ID、来源、动作与结果。

## 4. 实施顺序与验收

1. 人类批准 ADR 后，先提交 Schema 切片，补能力目录、严格请求和返回类型、个人资源引用及审批载荷。类型与生成物按现有流程更新，维护设计总览及 Personal、Assistant、Security、Hub、Web 分册的现行边界。
2. 实现 Personal 用例与 Storage，随后接入 Hub 的 HTTPS CalDAV 测试适配器、同步和回执。使用合成数据验证时区/全天/无日期、普通待办完成与撤销、异步失败及重启重试、`412` 冲突、游标失效、备份恢复、既有已完成事项不重复入日志。存在数据库迁移时单独交人确认上线。
3. 接入 Web、聊天工具与提议卡，验证开关关闭、外部 Agent 被拒、提议过期或版本过时、重复批准、历史回放均不泄露或误写。接受从聊天创建日程和待办后，在 iPhone 两个应用中看到正确条目，再从 Apple 日历勾选并撤销，核对 Hub 生活日志一条事实及一条更正。验证个人事项不出现在开发委派队列，重跑 `bun run check`。

第一版完成标准是「聊天创建 → 人确认 → iPhone 收到 → 勾选后回写 → 生活日志有来源」。iPad、Apple 端改期、重复待办单次完成、并发与离线重新连接分别验收，首轮 iPhone 的完成回写不代替上述验证。
