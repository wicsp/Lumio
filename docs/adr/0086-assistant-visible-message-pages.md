# 0086 助手对话按页读取可展示消息

- 状态：Implemented（2026-11-25，人类批准并实施）
- 涉及模块：Assistant、Storage、Hub、API Client、Web
- 关联：ADR 0025、0059、0060

## 背景

工作台主对话只显示最后 40 条有正文的用户消息或助手回复。现在打开主对话会先下载完整会话、所有消息和轮次，再在浏览器筛选。工具返回值也随历史一起传输。对话越长，打开其他工作台页面的成本越高。

## 决定

新增只读 `GET /v2/assistant/conversations/<conv_id>/messages`，沿用 `assistant.read` 与完整详情相同的所有者、删除状态和可见性校验。完整详情仍供需要轮次、工具消息或整段历史的调用方读取。

- 查询接受可选的 `limit` 和 `before`。`limit` 为 1 到 40 的整数，默认 40。`before` 是上一页返回的最早可展示消息的 `amsg_` ID，边界不包含该消息。首个请求省略游标。
- 每页只包含 `user` 或 `assistant` 角色且正文经 `trim()` 后非空的消息，保留原始正文。按现有持久化顺序选取边界以前最近的消息，在结果中从旧至新排列。同一时间戳的消息使用相同的存储顺序。
- 响应是严格对象 `{ messages, next_before? }`。`messages` 中每项只有 `id`、`role`、`content`，其中 `role` 为 `user | assistant`。还有早一页时返回本页最早的消息 ID 作为 `next_before`。空历史返回空数组且省略游标。
- 查询参数格式非法、游标不存在或不属于当前会话的可展示消息时返回相同的 `INVALID`。会话不存在、已删除、所有者不同的处理沿用完整详情。存储层从已有会话索引逆向读取，找到一页和判断有无下一页所需的记录即停止。数量上限按消息条数计算，单条正文保留完整。
- Web 打开主对话只读第一页，在会话顶部可以继续加载更早的消息。普通会话详情、CLI、模型上下文和已有记录继续使用原有接口与格式。无数据迁移。

## 验收

使用合成历史覆盖多页、工具和空白消息、相同时间戳、超大工具结果、非法和跨会话游标以及删除或无权访问的会话。翻页期间追加新消息时，读取旧页仍能接续原边界。用 `@lumio/schema` 校验请求及响应，并验证主对话首次加载走有上限的读取路径。
