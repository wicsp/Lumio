# 0034 知识新建入口、类型模板与后续写作

- 状态：Accepted（第 1–5 节；2026-11-06 人类批准，实施中）
- 日期：2026-11-06
- 领域：数据、Hub 与运行、AI 协作与权限

## 背景

用户希望在 Lumio 里直接新建论文、视频、网页和想法，自动准备字段与正文模板，后续在 Lumio 中写作、阅读和标注 PDF。
目前 Web 知识库只读；CLI 只提供 `new paper` 与 `new idea`。其他资料需要在外部编辑器中选择目录、填写 frontmatter，
补全器只补缺失字段，也不会展开全部可选属性。这使创建笔记的成本明显高于创建任务。

知识仍以 vault 的 Markdown 为权威；任务、项目与例行任务已在数据库中独立管理。
引入 Lumio 写作界面不等于迁移知识到数据库，也不意味着旧任务笔记已被导入或可以直接删除。

## 提议

本 ADR 第 1–5 节申请批准第一期「新建笔记」。第 6 节只记录后续方向，正文更新、附件与标注的契约另行起草批准。
批准之前不修改 `packages/schema`，不实现尚未批准的写接口；具体契约按仓库分工由 Claude 起草。

### 1. 新建入口与表单

- 知识库页增加「新建笔记」，命令面板也提供入口。第一屏选择「论文 / 视频 / 网页 / 想法」。
- 视频与网页分别映射为现有 `source` 的 `kind: video` 与 `kind: web`，不新增实体类型。
- 界面使用中文/英文名称，不要求用户填写目录、类型、ID、时间或 YAML。
- 选择类型后展示对应字段和可编辑的正文模板；保存成功后进入新笔记阅读页，可搜索到新笔记。
- 关闭未保存的表单时提醒保留草稿；保存失败或断线时保留本次输入。切换类型若会丢弃输入，必须明确提示。
- 第一期可在创建表单内撰写正文；修改已保存笔记的通用编辑器由后续切片提供，界面明确说明这一边界。

| 入口 | 用户填写或确认 | 自动处理 | 正文初始模板 |
|---|---|---|---|
| 论文 | arXiv/DOI 导入，或手填标题、作者、年份；标签可选 | 元数据解析、citekey、目录、ID、时间；有来源数据时生成 BibTeX | 一句话、核心方法与证据、局限、与我的研究的关系、待验证问题、BibTeX（有数据时） |
| 视频 | 标题、视频链接；作者、平台、标签、阅读状态可选 | `source` + `video`、目录、ID、时间 | 内容摘要、关键时间点、我的理解与疑问、下一步 |
| 网页 | 标题、网页链接；作者、站点、标签、阅读状态可选 | `source` + `web`、目录、ID、时间 | 核心观点、摘录与出处、我的理解与疑问、下一步 |
| 想法 | 标题；标签可选 | `idea`、目录、ID、时间 | 问题、当前想法、依据、尚不确定的地方、下一步验证 |

标题必须明确填写，禁止空白标题；来源链接允许后补，已填写时必须有效。可选字段按需展开。
论文手工模式不猜作者、年份；资料缺失时说明需要补充哪些字段。
第一期仅论文提供已有 arXiv/Crossref 来源的元数据获取，视频与网页不承诺自动抓标题、字幕或全文。
用户手工输入的字段优先，联网结果不静默覆盖；表单明确展示待保存的值。

### 2. 字段、模板与存储

- 数据类型及合法字段继续由 `packages/schema` 唯一定义；普通字段的校验与默认值复用现有实体定义。
- 补齐 `id/type/title/created/updated` 等基础字段，source 的 `kind` 显式保存，避免视频回落到 web 默认值。
  标签和其他默认值沿用现行存储规则；界面可以显示默认值，不要求所有可选字段写进文件。
- 内置模板由 Knowledge 统一生成，Hub/API Client/Web 与后续 CLI 入口复用，避免每个客户端维护一份正文模板。
  第一期不提供自定义模板执行、脚本、用户模板管理或模板自动升级。
- 模板只包含空标题和填写提示，不调用模型生成摘要，不自动建立链接。用户在表单中写下的内容作为人写的正文保存。
  模板升级不重写已有笔记；外部创建的笔记仍只补元数据，不自动插入模板。
- 路径通过 `VAULT_LAYOUT` 派生。普通标题清理为安全文件名；同名文件要求换名或由服务端返回明确冲突，不覆盖。
  论文沿用 citekey、arXiv/DOI 去重与撞名规则。客户端不得提交任意磁盘路径。
- 未配置知识目录时禁用保存并显示配置说明；不在默认或猜测的目录里创建笔记。

### 3. 新契约与权限边界

需要新增知识创建、模板读取与论文元数据解析的请求/响应契约。拟定语义如下，最终字段与接口由契约切片落实：

1. **读取模板**：按受支持的类型/来源类别返回可编辑的初始正文及模板版本，不产生笔记。
2. **解析论文**：接受 arXiv/DOI 输入，返回待确认的元数据与 BibTeX，不写 vault；超时或上游错误可切换手填。
3. **创建笔记**：接受唯一请求 ID、类型对应的可写元数据、已编辑正文；返回稳定笔记 ID、路径和实际保存的元数据。
   请求是严格的可辨识联合；拒绝客户端伪造 ID、程序时间、任意路径和未支持的类型。持久化笔记仍保留现有宽松实体规则。

写入通过 Hub 的知识命令入口，先鉴权、再校验与执行；HTTP、CLI 或未来客户端共享规则。
第一期的新增创建/解析/模板接口面向 human，agent/runtime 不获授这些新写权限。
不会因为人在 Web 能写正文，就让助手能够修改人的正文、创建链接或访问私密内容。
新增能力若进入统一能力目录，必须由同一授权表约束；私密类型不在本期表单或创建契约内。

网络元数据获取放在 Hub 适配器，Knowledge 不做网络或文件 I/O。Hub 不 import CLI 的论文抓取实现；
复用纯解析规则，按依赖方向提供适配器。请求限制大小与时限，只访问受支持的论文元数据来源，并校验重定向目的地；
不把用户 URL 变成任意网页抓取入口。

### 4. 保存与恢复

- 创建需防止路径穿越、符号链接越界和并发同名覆盖；正文及元数据经实体校验和现有敏感数据检查后写入。
- 请求 ID 去重：重复提交同一请求返回同一笔记；同一请求 ID 携带不同内容返回冲突。双击、超时重试不能创建多份。
- Markdown、请求回执、审计与派生索引不能假定属于同一数据库事务。
  存储切片须提供可恢复的创建记录，预先确定稳定 ID 与目标路径，并在短暂进程中断后核对文件状态。
  任何恢复过程都不能覆盖外部编辑后的文件；有歧义时明确返回需核对的状态，不重新创建。
- 保存后刷新知识索引，并经现有 Hub 写入审计及自动提交约定记录操作。
  响应失败时区分「尚未创建」与「可能已经保存」，客户端沿原请求 ID 查询或重试。

### 5. 实施顺序与验收

| 切片 | 范围 | 验收重点 |
|---|---|---|
| K1-1 | 契约起草与审阅；批准后修改 schema、生成物 | 四种入口的合法/非法输入与响应；人、agent、runtime 权限定义 |
| K1-2 | Knowledge 模板/创建规则与 Storage 文件、回执适配 | 类型目录、字段和模板正确；去重；并发同名；写入中断恢复 |
| K1-3 | Hub 知识写接口与元数据适配、API Client | 契约校验、鉴权、上游失败/超时、审计与即时查询 |
| K1-4 | Web 新建入口、字段表单、正文输入与草稿保护 | 四种类型浏览器验收；断线保留输入；重复点击；中英文与窄屏 |

每个 package/app 按切片单独提交，跨包变动限于已批准契约的连带修改。后端由 Codex、契约与前端按现行分工由 Claude 承担。
不因为本 ADR 同时描述多个模块，就在尚未批准时跨包实施。

测试仅使用 `fixtures/` 的合成数据与临时目录，论文来源使用合成响应，不读写真实 vault。
完整验收必须覆盖：四种类型创建后立刻能 search/show；必要字段无缺失；模板不会覆盖用户正文；
论文导入失败后手填；同 DOI/arXiv 重复；路径与符号链接防护；重复请求与恢复；越权写入拒绝。
每次提交前运行 `bun run check`；本提案不引入依赖，实际实现如需新增依赖须说明理由与替代方案。

### 6. 后续写作与 PDF 路线（不随本期批准实施）

1. **知识正文与属性编辑**：先做 Markdown 编辑/预览、显式保存与未保存提醒。
   更新以内容版本或摘要检查外部修改，冲突时保留草稿并让人选择，不能静默覆盖 Obsidian 的编辑。
   保留未知 frontmatter 字段、稳定 ID、AI 区块边界与人的链接。改标题和改文件路径分开；改名及引用更新单独设计。
2. **PDF 附件与内嵌阅读**：上传或关联 PDF，在论文笔记旁阅读、跳页，并可从笔记跳回 PDF 页码。
   附件归属、授权、大小限制、文件备份和浏览器隔离需要专门契约；查看器选型到该切片再评估。
3. **PDF 标注与引用**：选中文字高亮、写评论、从标注创建带出处的笔记片段。
   标注需绑定文档版本、页码、文本及位置；更换 PDF 时检测锚点失效，不能错贴到另一版正文。
   标注的权威存储、与 PDF 内嵌批注的兼容及导出形式另写 ADR，确保备份恢复与可迁移性。

上述阶段保持知识 Markdown 的权威地位，不重复开发完整 Obsidian 插件生态。
现行「Web 知识只读」在对应功能被批准并实现前仍生效。

### 7. 旧 Obsidian 内容的定位

- 新 Task/Project/Routine 的状态、交接、讨论与运行由 Lumio 数据库负责；用户可以停止维护旧笔记里的工作流开关和重复任务面板。
- 旧 `plan/` 内容先作为历史保留：退役只停止控制，不等于导入全部描述、汇报、附件或关系。
  将来清理前先核对迁移回执、独有内容、引用与备份；清理属于另一个用户明确授权的数据操作。
- 项目里的研究背景、决策理由、论文笔记、来源资料、想法、实验记录和附件继续有用。
  如需拆分旧项目笔记，工作状态进 Work，知识正文仍留 Knowledge，两者用稳定引用关联。
- Obsidian 可逐步成为可选编辑器。它打开的 vault 仍是 Lumio 的知识数据；停用编辑器不等于删除 vault。
  业务数据库及托管文件另行完整备份，只备份 Markdown 无法恢复新任务与执行记录。

## 后果（好处 / 代价）

- 好处：创建笔记时无需学习目录与 YAML，类型字段和正文模板一致；为后续写作提供统一入口，仍可外部编辑和导出。
- 代价：新增知识写接口、文件与回执的一致性恢复、浏览器草稿处理和权限测试；PDF 标注需要独立的数据模型与维护成本。
- 取舍：第一期交付四种新建流程；正文编辑和 PDF 分期验收，避免把完整编辑器与附件系统作为新建入口的前置条件。
