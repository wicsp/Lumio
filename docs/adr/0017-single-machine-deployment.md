# 0017 部署：Hub 与 vault 在同一台机器上，只有一份

- 状态：Implemented（P1）；第 1 节"不存在两边各有一份"、第 4、5 节已由 ADR 0022 取代
- 日期：2026-10-25
- 领域：Hub 与运行、安全
- 影响：ADR 0007「部署（当前）」一节

## 背景
ADR 0007 允许 Hub 运行在 Mac 或服务器上，并设想过 Hub 迁到服务器后再为手机、iPad 换一种同步方式。
讨论后确定：同步第二份 vault 会重新带来多写入方的冲突问题，而这正是 ADR 0007 要消除的。
另外，Lumio 现在只给一个人用。

## 决定
1. **一套系统只有一个 Hub，vault 只放在 Hub 所在的那台机器上，不维护第二份 vault。**
   - **单机模式**（现在）：Hub 与 vault 都在 Mac 上，Mac 开着才能用。
   - **服务器模式**（以后）：Hub 与 vault 都在服务器上，其他设备都是客户端。
   不存在"两边各有一份、互相同步"的模式。
2. **现在只做单用户、单机模式。** 多用户、托管服务不是目标。
3. 单机模式下，iPad、手机经 iCloud 同步到 Mac 的修改，对 Hub 来说等同于人直接改文件，照常补全、索引、提交。
4. **远程访问用 Tailscale。** Hub 仍然只监听 `127.0.0.1`；需要从其他设备访问时用 `tailscale serve`
   转发到本机端口（它同时提供 HTTPS）。公网反向代理（ADR 0007）留到真正使用公网服务器时。
5. **服务器模式下 Obsidian 怎么用，还没决定。** 备选：不用 Obsidian 作主编辑器而用 Lumio 自己的客户端；
   写一个通过 Hub 读写的 Obsidian 插件；本地只放只读副本。到要上服务器时再另立 ADR。

## 后果
- 好处：没有第二份数据，就没有同步冲突；部署简单；Tailscale 不需要公网端口、域名和证书。
- 代价：单机模式下 Mac 关机时，飞书和服务器上的 AI 用不了 Hub；迁到服务器时要解决 Obsidian 的编辑问题。

## 修订记录
- 2026-10-28：经人类批准，第 1 节"不存在两边各有一份、互相同步"、第 4 节（Tailscale）、第 5 节（服务器模式下的 Obsidian）由 ADR 0022 取代：只有一个 Hub 这一点不变，vault 文件夹可以被外部工具同步；网络由部署者负责；编辑器无关。
