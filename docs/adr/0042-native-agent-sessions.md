# 0042 原生 Agent 会话：执行器上的 Codex 作为 Assistant

- 依赖：ADR 0041；依据 V0-0 报告和 codex-assistant-adr-revision-notes

## 背景

用户希望没有 API key 时，也能在 Lumio 界面与自己登录的官方 Codex 会话连续聊天。Lumio 管理业务历史、配置与业务工具；官方引擎运行模型与工具循环。这里不实现订阅凭据反代、共享账户或服务端通用模型代理。技术接口可用不等于获得商业、地区或托管授权；本切片只验证用户主动交互的本机客户端接入，不对外推销订阅额度。

## 决定

### 1. 运行与模块边界

- 一份 Lumio conversation 绑定一个 Runtime Session；每个 Session 独占 app-server、持久 CODEX_HOME、托管 workspace、临时目录与监督范围。不同 Session 可并行，不共享官方 thread、审批实例或 MCP 凭据。
- Hub 的组合适配器负责身份、会话绑定、运行状态与交付；Assistant 领域保留对话/轮次与端口，Storage 保留新增业务表；Runtime 管理官方进程与本地 outbox。首版未把会话实现扩入 Execution 领域包，避免业务包互相导入实现；公开原生通道与 Job 并列。
- 原生一轮只由官方引擎负责循环，Lumio 不再套 API 工具循环，不应用 Job 的摘要汇报模板。
- 实测启用基线仅为 macOS + Codex CLI 0.166.0。其他平台/版本拒绝启动，须重新验证；Claude 原生订阅接入不在本次范围。

### 2. 登录与配置隔离

- 官方 app-server `account/login/start(chatgptDeviceCode)` 完成登录，界面展示官方地址和一次性设备码。正式部署不复制个人 auth.json，不把全局 CODEX_HOME 的配置、密钥或 MCP 列表带入 Session。
- 从白名单重建子进程环境；官方认证使用 Session 私有文件存储，不使用全局钥匙串。Hub 不获得原生认证令牌。
- thread/start 或新进程首次 thread/resume 直接带完整冻结配置：on-request/user、托管 cwd、workspace-write、命令网络关闭、排除系统 tmp、开发者说明和唯一 Lumio MCP。恢复后校验账户、版本、目录、沙箱和工具集合，完成前不发 turn。
- apps/connectors/plugins、hooks、子 agent 与未开放工具来源关闭；个人 AGENTS/项目配置不会被工作区发现。线程已加载后不靠再次 resume 热补安全策略。
- Profile 只切模型和 effort；换设备/账户/安全绑定开新会话。账户漂移或不符合策略冻结，不悄悄降级。

### 3. 双向 HTTP 与持久事件

Runtime 主动发起经 runtime 身份认证的 NDJSON 命令流 GET，事件经独立 POST 上报；两条 HTTP 腿绑定随机 channel ID。浏览器只连接 Hub。该原生协议独立版本为 1，Job 协议仍为 2。

事件先落 Runtime SQLite，带 Session 连续序号；Hub 事务接收并去重后确认，确认才清理本地 outbox。重连只补交事件，不重发用户消息/工具；序号缺口拒绝继续。修复发送期间新事件的唤醒竞态，防止最终事件滞留。

Hub 发送前保存 command/turn 交付快照和 sent 状态，Runtime 持久 command 去重。进程/通道断线时不以“没收到响应”推断未执行；受理或结果不明进入 unknown，而不是重投递。

### 4. 恢复与上下文

- Hub 业务历史是显示权威；官方 thread/本地原生状态是引擎续接状态，两者互不冒充。恢复同一个 thread；本地状态丢失时明确失败，不在旧业务对话内偷偷建新 thread。
- 初次注入获授权的显式记忆，之后只发新用户消息。保存每轮消息与交付上下文。记忆内容/来源权限变化使上下文摘要变化，停用该会话并要求新建；不声称旧引擎已忘记。
- 仅显示官方正文、公开思考摘要、工具过程与数值用量，不收集隐藏推理。原生压缩由官方引擎执行，Lumio 不覆盖其历史。
- 浏览器断开只中断显示，不自动取消引擎；明确停止按钮发送 interrupt。Runtime 闲置断线可恢复；活跃断线、崩溃或中断结果不明则冻结。

### 5. 工具权限与副作用

- 每个 Session 使用独立 agent 身份及短范围 MCP 令牌；令牌仅能访问自身 `/v2/native-mcp/...`，不能认证一般 human/runtime 入口。关闭、删除、未知状态使令牌失效。
- MCP 从现有能力目录生成；每次调用经过 Hub 授权、审计与持久操作回执。原生不继承内置 API 助手的 private 进程内例外；模型拿不到 human/runtime 凭据。
- MCP 调用只在对应活跃轮次内允许。request ID 绑定参数与工具，已完成重复请求返回原结果；不明写入冻结，不用换 ID 再执行。工具结果和整个引擎轮次状态分开记录。
- on-request 不代表每个工具都弹窗。原生审批绑定原进程 instance、请求 ID 与期限，只回答一次，不创建永久规则；5 分钟未回答拒绝，断线/换代不得沿用旧审批。
- Codex 的 workspace-write 不限制所有文件读取，因此另加 macOS Seatbelt 外边界，限定 Session 与执行所需系统文件；合成 vault、凭据、其他 Session 和指向外部的 symlink 读取必须被拒绝。命令网络关闭只描述命令沙箱，官方模型/MCP 通信仍需要外层网络。
- 监督并终止已观察到的后代及原进程组，不能把父进程退出当作副作用撤销，也不声称能证明没有未观察到的逃逸进程。unknown 阻止同一所有者继续原生写入和新会话；人核对工具结果、明确确认相关进程已停止并填写核查结论后，保留旧会话关闭记录，再开新环境。该确认是操作者的检查记录，不是系统对未知外部副作用的证明。

### 6. 试用、退出与后续

默认隔离验证使用独立端口与合成数据。用户明确要求部署现有实例时，先备份程序、配置与业务库，再更新原服务，保留原有数据和已有功能；部署检查不对真实 vault 做测试写入。原生功能由 `LUMIO_NATIVE_SESSIONS=1` 显式启用。试用后由用户决定是否合并；停止试用服务不会删除数据。普通旧 API 对话和 Job2 保持兼容。

后续再评估 Job/Profile 接线、Linux 隔离、Claude 原生会话、共享执行器资源限额、上下文分支与多机托管。不能从本机试用结论推导这些能力已交付。
