# 0007 Hub 是唯一的写入裁判，git 只做历史与备份

- 状态：Accepted（部分实现：「没有 Hub 时」「部署与安全」两节已实现（P1-2）；其余由 P1-3、P1-4 实现）
- 日期：2026-10-22
- 领域：Hub 与运行、安全
- 影响：ADR 0001、ADR 0014（原 0006）、`docs/DESIGN.md`

## 背景
原设计中 vault 的 git 仓库是事实来源，手机、Mac、服务器上的 AI 都直接向它写入，靠 git 合并。
这是多写入方模型，有三个问题：
1. 同时修改同一文件时，git 只报冲突，没有任何一方负责裁决。
2. ADR 0014 第 1 节（AI 只能提议）只能靠事后 review 保证，无法在写入时执行。
3. Runtime 的结果要经过 commit、分支、PR 才能回到 vault，对单人使用太重。

另一方面，此前一版项目采用"Core 是唯一权威、外部改文件即冲突"的设计，导致 Obsidian
无法使用、所有界面都要自己做，最终失控。本 ADR 要同时避开这两个问题。

## 决定
1. **Hub 是唯一的写入裁判。** AI、CLI、飞书、Runtime 等**程序**的写入一律通过 Hub API。
   Hub 负责校验（`@lumio/schema`）、执行 ADR 0014 第 1 节、写文件、更新索引。
2. **数据格式仍是 Markdown 文件。** Hub 的数据目录就是 Obsidian vault，SQLite 只是派生索引。
3. **人可以直接编辑文件。** Hub 监听数据目录的变化，自动校验并重建索引。frontmatter 不合法时
   提示人修正，**不拒绝、不覆盖**人的改动。
4. **git 只做历史、备份与撤销。** 由 Hub 定期或在写入后自动提交，不再作为协作或同步协议。
   `.git` 放在同步目录之外（例如 `~/Projects/lumio-vault.git`），vault 内只留指针文件。
5. **AI 的提议存在 Hub 中**（提议队列），由人在客户端接受或拒绝，不再使用 git 分支或 PR。
6. **Hub 的位置可配置。** 代码不假设自己运行在哪台机器上，数据目录通过配置指定。

## 部署（当前）
- Hub 运行在 Mac 上，数据目录为 iCloud 中的 Obsidian vault `Lumio`；手机、iPad 通过
  Obsidian + iCloud 访问，无需额外开发。
- 服务器上的 Runtime 通过 Tailscale 调用 Mac 上的 Hub。
- 已知代价：Mac 离线时，服务器与其他设备用不了 Hub。Hub 与 vault 始终在同一台机器上、不维护第二份 vault，
  迁到服务器时的做法见 ADR 0017。

## 部署与安全（从 P1 第一版 Hub 起就必须满足）
目标：Hub 今后从 Tailscale 内网迁到公网服务器时，**代码不用改**，只在前面加一层反向代理。
1. **Hub 不处理 HTTPS。** 加密由前面的反向代理负责（Caddy 自动申请证书，或 Cloudflare Tunnel，
   后者不需要开放服务器端口，还可以叠加 Cloudflare Access）。Hub 只讲 HTTP。
2. **所有 API 都要求 token，内网也不例外。** CLI、每台设备的 Runtime、飞书 Bot 各用独立的 token，
   可以单独吊销。不依赖"能连上就是自己的设备"这种网络层信任；事后补认证要改所有客户端，代价最大。
   token 不出现在日志和 job 中，按 AGENTS 第 7 条以占位符配置。
3. **地址全部可配置。** Hub 默认只监听 `127.0.0.1`；客户端里的 Hub 地址是完整 URL
   （如 `https://lumio.example.com`），代码中不写死协议、主机或端口。
4. **只信任配置过的代理。** Hub 通过配置指定可信代理，只从它转发的请求头中读取客户端真实 IP 和协议，
   用于日志和限流；其他来源的这类请求头一律忽略。
5. 飞书 Bot 使用官方 SDK 的长连接接收事件，不需要公网回调地址，不受部署位置影响。

## 没有 Hub 时（由 ADR 0014 第 7 节细化）
- `lumio new …`、`lumio sync` 只新建文件或补全缺失的元数据，性质等同于人手动编辑，**不需要 Hub**，P1 之后也保持本地执行。
- 查询可以走 Hub，也可以直接读本地 vault。
- **修改已有内容的程序写入**（接受提议、程序字段的更新）必须经过 Hub。

## 后果
- 好处：写入有唯一裁判，冲突与 AI 权限都在写入时处理；Obsidian 照常可用；git 历史完整。
- 代价：Hub 必须在线才能接受程序写入；Hub 需要实现文件监听与"外部修改"的处理逻辑。
