# 0024 负责人写成一行、工作目录有默认值、frontmatter 里看得到上一轮的结果

- 状态：Proposed
- 日期：2026-10-29
- 领域：数据 | Hub 与运行 | 安全
- 影响：修订 ADR 0019 中任务与例行任务的 `assignee`、`workdir`；DESIGN 第 3.2、4.6、6 节；`packages/schema` 的 `Assignee`、`Task`、`Routine`

## 背景
打磨期第一次在 iOS Obsidian 上给服务器派活（2026-10-29）时发现：

1. `assignee: {agent: pi, device: server}` 是嵌套对象，Obsidian 的属性面板编辑不了，手机上只能在源码模式里手打缩进。
2. `workdir` 必须写。大部分"看一眼""查一下"的任务并不在意工作目录，每次都要写一遍。
3. 想用 Obsidian Bases（或以后任何入口）做一个"所有任务"的总览时，frontmatter 里只有 `status` 和 `turn`。
   一轮结束后 `turn` 都回到 `human`，分不出这一轮是"完成"、"有问题等你回答"还是"失败"，只能点进每篇笔记看正文末尾的区块标题。

## 决定

### 1. 负责人写成一行字符串
- 任务的 `assignee` 取值：`human`，或 `<agent>`，或 `<agent>@<执行器名称>`。例如 `pi`、`pi@server`、`codex@mac`。
  - `<agent>` 是 `claude-code`、`codex`、`pi` 之一；`<执行器名称>` 的规则同 `RuntimeName`（小写字母、数字和 `. _ -`）。
  - 不写 `@<执行器>` 时按现行规则挑执行器（ADR 0019）。
- 例行任务的 `assignee` 同样写成 `<agent>` 或 `<agent>@<执行器名称>`（不能是 `human`）。
- 统一只写这一种格式：文档、模板、`lumio routine followup`、自检笔记和 Hub 写出的内容都用字符串。
- **兼容旧写法**：读取时仍接受旧的 `{agent, device}` 对象并等价处理，补全器不改写已有的值；`lumio check` 对旧写法给出提示（不算错误）。
  以后要删掉兼容时另写 ADR。
- 契约：`Assignee` 增加字符串形式并提供解析函数（返回 `{agent, device?}`），Hub、补全器与 CLI 只通过这个函数读取负责人，不各自解析。

### 2. `workdir` 缺省为执行器上的 `~`
- 任务与例行任务的 `workdir` 改为可选；缺省时这一轮在**执行器所在机器**的用户主目录里执行。
  按 ADR 0008，默认值不写进文件；Job 里记录实际使用的工作目录。
- **安全规则收紧**（ADR 0019 第 5 节的补充）：在 Hub 与执行器同一台机器上时，工作目录**既不能在笔记库里，也不能包含笔记库**。
  原因：agent 的沙箱通常允许写工作目录下的所有文件；工作目录是 `~` 而笔记库在 `~` 下面时，agent 就能改笔记库。
  - 因此在 Hub 所在的机器上（作者的 Mac），不写 `workdir` 时默认的 `~` 会被拒绝，错误说明会提示写一个具体目录。
  - 在其他机器上（实验室服务器），`~` 不包含笔记库，可以直接用。

### 3. Hub 在 frontmatter 里写上一轮的结果
- 新增程序字段 `last_round`（任务），由 Hub 在写回一轮结果时与 `turn` 一起写入；取值与区块标题一一对应：
  `done`（完成）、`question`（有问题等你回答）、`failed`（失败）、`unknown`（情况不明）、`cancelled`（已取消）。
- 只由 Hub 写（ADR 0009 程序字段例外）；人改了也会在下一次写回时被覆盖。还没跑过的任务没有这个字段。
- 用途：任何总览（Obsidian Bases、以后的 GUI、飞书）只读 frontmatter 就能分出"轮到我回答"和"已完成待我确认"。

## 后果
- 好处：手机上可以在属性面板里直接改负责人；简单任务只需写正文；总览不用打开每篇笔记。
- 代价：
  - 负责人有两种写法共存一段时间，解析集中在 schema 的一个函数里，降低出错面。
  - 在 Mac 上派活仍然要写 `workdir`（安全上的取舍）。
  - 任务的 frontmatter 多一个由程序维护的字段。
