# ADR 0037：内容自动保存与离开后的草稿恢复

- 状态：Accepted
- 日期：2026-11-06
- 范围：apps/web；沿用现有接口，不修改 packages/schema。
- 批准：用户要求可编辑内容默认保存、去掉保存/取消按钮与退出警告，并补充普通双链的悬浮及点击行为；本次由 Codex 实现。

## 决定

任务、项目标题和说明使用持续可编辑界面；说明复用知识库的实时 Markdown 编辑器。输入停顿约 800 ms 后自动保存，中文输入法组合期间暂停。结构化字段与正文按现有契约分开、串行提交，后续请求以返回的 revision 为准。保存期间的新输入继续排队。属性选择仍立即保存，委派、发布评论、发送 AI 消息、创建记录、改变自动化运行计划等有业务含义的操作仍显式提交。

任务/项目、知识库编辑保存本地恢复副本，包含原始版本、当前输入和结果不明时的原始请求。关闭或切换页面不再弹丢弃确认；离开时尝试保存。断网时恢复草稿，结果不明时重放同一 request_id，不生成第二次写入。版本冲突停止自动覆盖，页面内提供比较及手动合并后继续保存。空标题等不完整输入保留为草稿，不强行写入非法数据。

未发送的讨论、执行反馈、AI 输入、记忆输入和未完成的新建笔记/任务/项目、计划/例行表单保存为浏览器草稿；再次打开同一用途时恢复。退出不等于发布、委派或启用自动化。成功提交后清除对应副本。保留显式删除、替换模板、停止正在运行任务等确认。

草稿以 Hub 与已验证凭据的 SHA-256 派生键隔离，使用 localStorage；不保存密码/密钥控件。只缓存用户正在编辑的内容和用于版本检查的基线，不建立业务数据镜像。副本留在当前设备，同源脚本可读，安全边界与现有会话存储相同。存储受限时保留当前会话内存副本，内容编辑状态明确提示保持页面打开直到服务端保存成功。同一页面旧编辑器的迟到响应不能清除新编辑器的草稿。

任务/项目说明、任务讨论与 AI 对话输入复用知识库的标题/正文候选搜索，支持两种括号、上下键与 Enter 选择。工作内容没有 vault 相对目录，插入稳定 note ID（无 ID 时使用根相对路径）并显示标题别名；评论/消息只插入引用，不自动发送。阅读态的讨论、报告、AI 消息提供普通引用悬浮摘要及跳转。

普通 `[[目标|别名]]` 与 `【【目标|别名】】` 双链显示引用卡片，点击直接跳转；卡片中的“编辑引用”返回源码。上标引用保留相同的悬浮与跳转行为。代码、转义文本和公式中的相似语法不激活。

## 替代方案

- 仅在退出时保存：刷新/关闭时无法保证网络完成，不能覆盖断网情况。
- 继续弹确认：违背持续编辑体验，并不能解决恢复问题。
- 自动发送未完成的评论、AI 请求或启用例行任务：把恢复草稿误当作执行授权，因此保持显式操作。
- 修改写入契约一次更新全部字段：没有必要；复用现有版本和幂等机制即可。

## 验证

合成数据单元测试覆盖保存队列、版本链、保存期间继续输入、恢复后幂等重放、非法输入、账户隔离、存储故障和迟到回调；使用浏览器验证切页、刷新恢复、无退出警告、普通/上标引用交互及 Markdown 表格与公式。完整检查通过后记录于交付说明。
