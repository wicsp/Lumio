# 0027 v0.2 上线：一个程序、Hub 提供 Web、助手模型配置、旧任务笔记直接退役

- 状态：Accepted（2026-11-02 人类在对话中批准）
- 日期：2026-11-02
- 领域：工程基础 | Hub 与运行 | 安全
- 影响：取代 ADR 0021 中「发布三个程序」与 ADR 0026 第 2 节（独立 Web 服务与同源代理）、第 1 节中「Web 自带 Bun 服务」的部分；
  DESIGN 第 2、4.5、4.7、4.8 节；`.dependency-cruiser.cjs`；`install.sh`、`release.yml`、`apps/cli`、`apps/hub`、`apps/runtime`、`apps/web`、`packages/platform`。
  不改 `packages/schema`。
- 实施说明：[R1-0](../tasks/R1-0-v0.2-release.md)

## 背景

四模块重构（ADR 0025）与 Web 工作台（ADR 0026）已合入 main，但作者实际在用的仍是 v0.1.6：

1. 发布包里有 `lumio`、`lumio-hub`、`lumio-runtime` 三个程序，每个都自带一份 Bun 运行时（约 100 MB）；Web 还只能在仓库里 `bun start`。
   多个程序带来版本不一致的问题，`doctor` 里有不少检查就是在防它。
2. Web 作为独立服务时，服务器模式下还要再对外暴露一个服务；同源代理是因为 Web 和 Hub 不在同一个进程才需要的。
3. 助手模型只能靠手动修改 Hub 后台服务的环境变量配置。
4. 从任务笔记切换到数据库要手动执行十余步。作者的旧任务、项目、例行笔记都是 P2 验收时建的测试数据，不需要导入。

作者希望：装好就能在浏览器和「App」里用；单机模式下本机只有一个程序；服务器模式下服务器上 Hub 与执行器是同一个程序。

## 决定

### 1. 发布一个程序 `lumio`，角色用子命令区分
- 发布包只含一个 `lumio`（每个平台一个文件）。原来的命令都成为它的子命令：
  `lumio hub <…>`（原 `lumio-hub <…>`，`lumio hub serve` 启动 Hub）、`lumio runtime <…>`（原 `lumio-runtime <…>`，`lumio runtime serve` 启动执行器），
  其余 `lumio <…>` 不变。
- **兼容旧名字**：安装时在 `~/.local/bin` 建 `lumio-hub`、`lumio-runtime` 两个指向 `lumio` 的符号链接；程序按调用名（argv[0]）分派，
  旧的命令、文档和已安装的服务文件继续可用。新写出的服务文件一律用 `lumio hub serve` / `lumio runtime serve`。
- **程序是一个，进程仍分开**：Hub 与执行器仍是两个后台服务（两个进程），只是用同一个程序启动。
  执行器要在 Hub 离线时继续跑排队的工作，并且执行 agent，崩溃或权限问题不能波及 Hub（ADR 0005、0019 不变）。
- 单机模式：本机装 Hub 与执行器两个服务。服务器模式：服务器装 Hub 与执行器；其他机器（例如作者的 Mac）只装执行器，CLI 用 `lumio login`。
- **代码结构**：`apps/cli` 成为唯一的程序入口。依赖规则调整为：只有 `apps/cli` 可以 import 其他 app 的**入口模块**
  `apps/<hub|runtime|web>/src/entry.ts`；hub、runtime、web 之间仍不得互相 import，hub 与 runtime 仍只通过 HTTP + Job 协议通信。

### 2. Web 由 Hub 提供，不再有独立的 Web 服务和代理
- Hub 在自己的地址上提供网页：`/` 返回页面，`/assets/*` 返回构建好的 JS/CSS、图标与 PWA 清单；浏览器与 Hub 同源，直接调用 `/v1`、`/v2` 接口。
- 网页资源在**构建时**由 `apps/web` 生成，经 `apps/cli` 入口传给 Hub（发布构建嵌入程序；源码运行时即时构建）。Hub 不 import `apps/web`。
- 服务器模式下，网页就在服务器上的 Hub 地址（部署者已经为 Hub 配好的 HTTPS 反向代理或 Tailscale）；单机模式下在 `http://127.0.0.1:7420`。
  不再需要单独的 Web 端口、Web 服务和 `/hub` 代理。
- Hub 对浏览器请求增加原来由代理承担的保护：
  - 页面与静态资源带限制性 CSP、`X-Frame-Options: DENY`、`nosniff`、`no-referrer`；API 响应 `no-store`。
  - **防 DNS 重绑定**（纵深防御；API 本来就要求令牌）：浏览器发出的请求（带 `Origin` 或 `Sec-Fetch-Site` 头）中，Origin（若有）必须是
    Hub 的本机监听地址、`LUMIO_PUBLIC_URL` 或 `LUMIO_WEB_ORIGINS` 额外列出的来源，`Host` 也必须是这些地址之一的主机，否则 403。
    不带这些头的请求（CLI、执行器）照旧只看令牌。
  - Web 使用的令牌仍只能是 human 令牌（ADR 0026 第 4 节的登录保持不变；存储键按 Hub 来源隔离）。
- `apps/web` 的独立服务与代理在 R1-2 完成后删除；`bun run demo:web` 改为启动带网页的临时 Hub。

### 3. App：先做可安装的网页应用（PWA）
- Web 提供 Web App Manifest 与图标（含 iOS 用的 PNG），可在 macOS Safari「添加到程序坞」、Chrome「安装」、iPad/iPhone「添加到主屏幕」，
  以独立窗口和图标运行。
- 不注册 Service Worker、不做离线缓存（业务数据不缓存在浏览器，ADR 0026 不变）。
- 原生 Mac App（菜单栏状态、系统通知、启停本机服务）以后需要时另写 ADR，复用同一套前端。

### 4. 助手模型用命令配置，密钥放在 Hub 服务的环境文件里
- `lumio hub assistant setup`：交互式询问 API 地址、模型名和密钥；密钥用不回显输入读取，非交互时只从标准输入读取（`--api-key-stdin`），
  **不接受命令行参数传入密钥**。地址规则与现有适配器一致。
- 写入 Hub 后台服务的私有环境文件（与 Hub 现有令牌同一文件，权限 600，原子替换），键名沿用 `LUMIO_ASSISTANT_BASE_URL`、
  `LUMIO_ASSISTANT_MODEL`、`LUMIO_ASSISTANT_API_KEY`，然后重启 Hub 服务。这就是 DESIGN 所说「运行时环境注入」的具体做法；
  密钥仍不进入仓库、`~/.config/lumio/config.json`、日志或命令输出。
- 写入前用这组配置发一次最小请求验证；失败时说明是地址、鉴权还是模型名的问题，不写入。`--skip-check` 跳过验证。
- `lumio hub assistant status` 只显示地址、模型和「密钥：已设置/未设置」；`lumio hub assistant clear` 删除这三项并重启。
- `lumio doctor` 显示助手已配置/未配置（未配置是提醒，不是失败）。不预设供应商或模型（ADR 0025 第 7 节不变）。

### 5. 旧任务笔记可以直接退役，不导入
- `lumio hub migrate retire --vault <知识目录>`：**不导入**任何旧 Task/Project/Routine，只写入一条迁移回执，
  使该工作区的旧 Task/Routine 文件控制和 v1 任务派活/追问全部关闭（与首次 `migrate apply` 成功后的效果相同）。
- 要求 Hub 已停止并独占状态目录；自动先做完整业务备份并验证；回执记录备份位置、退役时间和识别到的旧笔记数量与路径摘要。
- 旧笔记文件不改、不移动，继续作为普通知识文件可搜索、可阅读；之后修改旧格式笔记不会触发执行。
- 仍有旧笔记来源、未结束的 Job 时拒绝并列出。`migrate plan/apply` 保留给需要导入的用户；同一工作区 retire 与 apply 只能二选一。

### 6. 一条命令完成切换
- `lumio upgrade` 把旧版的三个程序替换为一个 `lumio` 与两个兼容链接，改写本机服务文件为新写法并重启服务；
  发现 Hub 处于「v2 程序 + 旧笔记模式」时，提示运行 **`lumio hub switch --retire-legacy`**：
  停止 Hub 与本机执行器服务 → 本机执行器 `prepare-migration` → `migrate retire` → 启动服务 → `doctor`。任一步失败即停止并说明已完成的步骤与恢复办法。
- 其他机器上的执行器各自 `lumio-runtime upgrade`（旧名字仍可用；Job 协议仍为 2）。
- `lumio selftest` 改用数据库任务验证派活与写回，不再写 vault。

## 后果

- 好处：一次下载、一个版本，升级只替换一个文件；服务器模式下 Web 与 Hub 共用同一个地址，手机和 iPad 打开就能用；
  少一个服务、少一层代理；PWA 几乎零成本得到「App」。
- 代价：
  - 只装执行器的机器也带着 Hub 与 Web 的代码（程序大小与原来单个程序相近，总下载量减少约三分之二）。
  - Hub 直接面对浏览器，需要自己承担 CSP、Origin/Host 检查；这些规则集中在 Hub 的 HTTP 层，有测试覆盖。
  - 依赖规则多了一条例外（`apps/cli` 可引用其他 app 的入口模块）。
  - Hub 服务环境文件里多了一项第三方密钥，保护强度与 Hub 现有令牌相同，弱于系统钥匙串；需要时另写 ADR。
  - retire 之后旧笔记永远不再执行；找回只能从退役前的业务备份或旧笔记原文手动重建。
