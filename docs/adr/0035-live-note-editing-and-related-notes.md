# 0035 笔记实时预览编辑、相关推荐与引用补全

- 状态：Accepted（第 1–8 节；2026-11-06 人类批准全部实现，本地验收中）
- 日期：2026-11-06
- 领域：知识、Web、存储与权限

## 背景与批准范围

用户要求继续实现：保存后的笔记可直接修改，打开就是编辑与呈现合一的页面，没有「编辑」按钮和「撰写 / Preview」切换；
左侧笔记列表随输入推荐最多 5 篇标题/内容相关的笔记，默认展示前 3 篇；写作中通过 `[[` 搜索并插入引用。
首期使用本地词法/模糊检索，后续再考虑向量检索或 RAG。

ADR 0034 §1–5 仅批准创建，不含更新契约；本 ADR 第 1–7 节的接口、保存语义和编辑器依赖已获批准。
用户同时要求补充「空查询沿用上下文推荐、输入后检索标题和正文、展示命中段落」；本次按该指令修订。
本文件不修改 ADR 0034 已批准内容。用户随后明确要求全部实现，包含第 8 节上标脚注；批准实现不代表人工验收通过。
本次用户明确授权「由 Codex 完成全部代码，覆盖原分工」，包含契约与前端；不调用外部 Claude。

## 1. 用户流程

- 已有笔记打开即能编辑标题与正文，无模式按钮。详情区是一个连续、可选择、可输入的编辑面，绝非左右两个同步窗格。
- 同一编辑面实时呈现标题、粗体/斜体、列表、引用、代码块和链接；光标所在语法范围可以显露必要 Markdown 标记，移开后恢复展示。
  无需先点击「编辑」。不把整个文档切换成源码，也不将渲染后的 HTML 反向序列化为 Markdown。
- 标题、正文停止输入约 800 ms 后保存；中文输入法组合期间不发起保存。状态固定显示「未保存 / 保存中 / 已保存 / 保存失败 / 内容冲突」。
  ⌘/Ctrl+S 立即触发同一保存队列，不触发浏览器保存网页。
- 每篇笔记同一时刻最多一个保存请求；保存期间继续输入留在本地，前一请求成功后用新版本保存最新草稿。
  迟到响应不得覆盖新输入。失败保留草稿，不无限重试或显示虚假的「已保存」。
- 切换笔记、进入别的模块、点击推荐、引用跳转、刷新和关闭都受未保存保护。能完成保存时先保存再导航；失败时留在当前草稿并给出重试/复制。
  浏览器卸载只能触发未保存提示，不能承诺卸载期间可靠提交；本期不新增 localStorage/IndexedDB 正文缓存。
- 新建仍先选择类型及必要字段，然后在知识详情区用同一编辑器写作，左侧推荐同时可用。首次点击「创建笔记」后沿用自动保存；
  标题/作者等尚未填完时不自动创建空文件，重复点击沿用创建请求 ID。取消新建保留既有未保存提醒。
- 本期编辑 `paper/source/idea/experiment/post` 中有合法稳定 ID 的公开知识笔记；旧工作笔记、私密资产、无 ID 或非法元数据笔记保持只读并解释原因。
  不因新增编辑器而扩大扫描类型、私密访问权限、agent 权限或自动修复非法笔记。
- 本期修改标题与正文。其他属性沿用展示，新建时的类型字段不受影响；修改标题不改文件名、路径或论文 citekey，不隐式批量重写引用。

## 2. Markdown 与编辑器

- 行首键入 `》` 加空格兼容为 Markdown `> ` 引用（允许最多三个前导空格）；转换可撤销。组合输入结束后处理，不改写正文中的书名号、代码或粘贴内容。

- Markdown 文件仍是正文权威。编辑器持有原始文本和选择范围，渲染是该文本的视图；打开或未改动时不重新排版全篇。
  未支持的语法、HTML、BibTeX、AI 区块注释和复杂表格保留原文，可安全编辑，不能因显示不支持而消失。
- 人可编辑 AI 区块内容；编辑器本身不生成文字，不删除区块边界，不将 AI 区块中的链接改记为人的链接。
- 使用 CodeMirror 6 作为输入/撤销/选择/组合输入基础，以 decorations 和补全扩展实现实时预览。
  不自研编辑器内核；现行「不自己写编辑器」继续约束内核，本期允许集成成熟编辑器及 Lumio 的展示扩展。
- 计划仅在 `apps/web` 增加直接依赖：`@codemirror/state`、`@codemirror/view`、`@codemirror/commands`、
  `@codemirror/language`、`@codemirror/lang-markdown`、`@codemirror/autocomplete`。实施时核对兼容版本并用 Bun 1.3.x 更新锁文件。
  若必须增加其他直接依赖，先说明理由；PR 描述必须列出实际新增依赖、体积影响和替代方案。
- 替代方案：textarea + 预览不满足本次交互；原生 contenteditable 自行处理 Markdown 往返、输入法和撤销风险高；
  富文本树编辑器需要额外保证未知 Markdown 与 AI 注释的无损往返。本期选择保留源码的编辑器集成。
- Markdown 原始 HTML 不执行，不开放 javascript/data 链接，不自动加载远端图片；沿用 CSP 和私密过滤。
  链接单击可定位光标，⌘/Ctrl+点击或明确的打开操作跳转，避免编辑链接时误导航。
- 当前 CSP 的 `style-src 'self'` 不允许编辑器直接注入样式标签。集成时优先输出同源静态样式；动态样式确有必要时，
  由 Hub 为每个 HTML 响应生成不可预测 nonce，并仅授予编辑器样式标签，页面与 CSP 同响应交付且不得跨响应复用缓存。
  不添加 `unsafe-inline`/`unsafe-eval`，不放宽脚本来源；浏览器验收必须覆盖真实 Hub CSP 下的编辑器样式与补全弹窗。

官方实现依据：[decorations](https://codemirror.net/examples/decoration/)、[输入补全](https://codemirror.net/examples/autocompletion/)。
这两项能力是集成基础，不意味着 CodeMirror 自带完整所见即所得 Markdown 产品。

## 3. 新接口设计（已批准）

所有新请求/响应是严格对象，复用现有 Id、RequestId、NoteRef、NoteDetail、ApiError；现有查询契约与能力目录不变。
新增接口均先鉴权、再解析；仅 human 可用，不注册为 agent 工具。未配置 vault 明确拒绝。正文上限沿用 500000 字符，另设 HTTP 字节上限。

| 接口 | 输入 | 输出 |
|---|---|---|
| `GET /v2/knowledge/notes/:id/document` | 合法知识 ID；无任意路径参数 | `{ document: NoteDetail, revision: string }`，revision 为原文件全部字节的 SHA-256，小写 64 位十六进制 |
| `PUT /v2/knowledge/notes/:id/document` | `{ request_id, expected_revision, title, body }`；标题 trim 后 1–500 字符 | `{ request_id, document: NoteDetail, revision }`，对应本次实际写入的文件版本 |
| `POST /v2/knowledge/related` | `{ exclude_id?: Id, title: string, text: string, focus: string }`；title ≤500、text ≤20000、focus ≤4000 字符 | `{ method: "lexical", hits: [{ note: NoteRef, snippet: string }] }`，最多 5 条，snippet ≤200 字符 |
| `POST /v2/knowledge/references` | `{ source_id?: Id, source_kind?: KnowledgeNoteKind, query: string, context?: { title: string, text: string, focus: string } }`；query ≤200 字符；context 限制同 related；已保存传 source_id，新建传 source_kind，二选一 | `{ hits: [{ note: NoteRef, snippet: string, insert_text: string }] }`；空查询返回上下文前 5 条，非空查询返回最多 10 条；snippet ≤200 字符；插入文本由现有解析规则生成 |

`focus` 是光标所在段落（长段取光标附近窗口），`text` 是其余有界正文；二者允许为空。`query` trim 后为空必须提供 context，
按 related 的同一算法返回同序候选；非空时只以 query 主动搜索整个可见知识范围，不局限于 context 的候选、不让 context 的相关度压过主动查询。
本次新增字段是用户要求的上下文检索和正文搜索的连带契约设计，不新增外部模型调用。

读取 document 直接读取被校验的文件并计算同一份字节的 revision，不能从可能滞后的索引拼接内容版本。
更新只准修改 title/body 和程序维护的 updated。服务端保留 ID、type、created、citekey、其他字段及未知 frontmatter；
默认值不得突然写满文件，YAML 注释/布局在实现支持范围内保留，禁止丢弃未知字段。未知请求字段一律拒绝。

稳定错误 reason 区分：`revision_conflict`、`request_conflict`、`save_uncertain`、`note_not_editable`、`unsafe_note_path`；
沿用 ApiError 代码映射，不依赖翻译后的文字判断。冲突不在错误里泄露另一个版本的正文，客户端通过授权读取重新获取。

## 4. 保存、冲突与恢复

- expected_revision 包含元数据与正文；即使 Obsidian 只改了一个属性，也不能用旧页面覆盖。冲突停止自动保存，保留用户草稿，
  提供查看磁盘版本、复制草稿及重新编辑/合并的流程，不提供无条件强制覆盖按钮。
- 同一 actor + request_id + 请求内容幂等；换内容复用 ID 返回冲突。结果不确定时冻结该次提交快照，用同一 ID 重试，
  新输入另保留为后继草稿。重放已完成请求只返回历史回执，不再次写文件；客户端再读取最新版本后决定是否继续提交后继草稿。
- Storage 预先保存原始字节、预期新字节、请求摘要、版本与审计状态，再发布文件；未知字段检查、敏感信息检查和路径检查在发布前完成。
  记录属于 hub.sqlite 的知识模块并纳入业务备份，不把 Markdown 的权威迁移到数据库。
- Hub 内与 watcher 共享互斥队列。发布前再次检查路径、ID、文件版本，使用同目录临时文件原子替换；目录及最终文件符号链接拒绝。
  外部编辑器不持 Hub 锁，因此不能宣称文件系统操作构成跨编辑器事务：发布前保存原版本并复核，发布后核验结果；
  检测到竞态时保留可恢复版本并报冲突，不循环覆盖。实施须专项审查最后一次校验与替换间的竞态窗口，不能只测试两次顺序保存。
- 进程中断后：磁盘为预期新字节时补齐索引、审计与回执；磁盘仍为原字节时可恢复原请求；第三种字节、文件删除或移动则停止恢复。
  不复活已删除笔记，不覆盖外部更新；成功审计和 ready 回执同事务，文件/索引/Git 的中断状态需要可恢复。
- 成功后更新索引、正反链接与现有 Git 审计。未改内容不生成写入或提交；自动保存应合并输入停顿，避免每个键生成一次 Git 提交。

## 5. 相关推荐

- 推荐区位于左侧列表底部，与手工搜索结果区分；标题「相关笔记」。默认展示前 3 条，提供「展开全部 5 条 / 收起」。
  少于 5 条就显示实际数量，不用无关笔记凑数。保留上面的原有笔记列表；编辑期间推荐区保持固定高度（受视口高度限制），空结果也保留该区域，展开后在区内滚动。推荐变化不能抢走焦点、光标或滚动位置。
- 每行显示笔记标题，以及该笔记实际命中的最相关段落摘要（1–2 行小字，最多 200 字符），而非固定取正文开头。
  摘要是原文片段，不生成改写；只命中标题时显示标题命中说明，不把无关首段伪装成匹配段落。截断加省略号，同篇多段命中仅展示最相关一段。
  可访问的完整标题通过提示/聚焦查看，长标题截断不改变真实引用目标。
- 对标题和正文输入约 400 ms 防抖。客户端提供标题与有界正文窗口；服务端统一分词、去停用词，按标题匹配加权、正文词/短语重叠排序。
  复用 FTS/trigram 与短中文子串能力，补充有限候选的模糊匹配；多词召回使用 OR，不能把整篇正文作为精确短语。
  返回稳定排序、去重、排除自己；词法算法不声称理解语义，不调用模型/嵌入服务。
- 正文窗口优先当前编辑段及附近文本，余量覆盖文章开头；总量限制 20000 字符。无有意义文本时不显示随机推荐。
  代码、模板空标题、纯标点、BibTeX 和 AI 区块标记降低或排除权重，避免模板相同导致推荐全部雷同。
- 上下文推荐优先匹配 focus 的句子/段落，再参考标题与其余正文；移动到不同段落并停顿也更新推荐。
  正在输入的未闭合 `[[查询` 不纳入 focus/text，避免查询关键字污染写作上下文；弹窗主动搜索期间左侧继续代表写作上下文。
- 仅从公开知识候选 `paper/source/idea/experiment/post` 检索，排除私密、旧工作笔记、当前笔记与不可解析项。
  关闭/切换笔记、退出登录会清空推荐并丢弃旧响应；草稿仅发给自己的 Hub，不发送外部服务，不在日志中保存推荐请求正文。
- 点击推荐可打开对应笔记，须完成当前草稿保护；推荐本身不会自动写引用。窄屏提供同一推荐区的抽屉入口，不挤压正文输入。

## 6. `[[` 引用补全

- 在非代码块、非行内代码、非 AI 标记注释的文本中输入 `[[` 打开补全。没有输入查询词时，沿用触发前段落的 A/B/C 上下文推荐，
  与左侧使用相同候选、顺序和命中段落；左侧折叠为 3 条不限制弹窗展示全部最多 5 条。
  打开时捕获上下文与推荐请求代次，必要时等待该上下文的最新结果，不闪现上一段的候选；无结果提示「输入文字搜索笔记」。
- `[[` 后继续输入 `X`，立即进入主动搜索：匹配整个可见知识库的标题、文件名/citekey **及正文**，不是只在 A/B/C 中筛选。
  使用词项/短语、子串及模糊匹配，不要求与完整标题或完整段落一致。输入文字本身就是搜索框，无需额外点击。
  删除所有查询字符回到上下文推荐；搜索无结果时明确提示，不用 A/B/C 冒充 X 的搜索结果。
- 上下键选择、Enter 或点击确认、Escape 关闭。中文输入法选词优先，组合输入未结束时方向键/Enter 不被补全接管。
  列表标注「当前段落相关」或「搜索：X」；每个候选同样显示 1–2 行实际命中正文，纯标题命中按第 5 节处理。
  查询变化时重置选择，按查询和光标位置丢弃旧结果；选中候选不会被随后到达的另一批结果静默替换。
- 候选显示标题和类型，必要时显示目录用于消歧；引用的是存储文件名/citekey，而非把可能不同的展示标题当目标。
  普通插入 `[[文件名|显示标题]]`，展示标题与文件名相同时可省略别名。
- 不能假设 `[[id]]` 或 `[[目录/文件名]]` 已被现行解析器支持。同名文件有歧义或文件名含不安全 wikilink 分隔符时，
  明确标注「路径引用」，插入现有支持的 `[标题](相对路径.md)`。由服务端基于 source_id/source_kind 推导安全相对路径，不接受任意路径输入。
- 新建时普通笔记和论文都位于各自固定类型目录，相对引用按该目录计算；已有笔记支持类型目录下的子目录。
  引用候选即使隐藏了其他同名笔记，也不能误把有歧义的 basename 判成唯一；这种情况使用路径引用，不披露隐藏项。
- 选择候选仅替换当前 `[[...` 范围，补齐闭括号，保留前后文本、撤销栈与光标；不因异步返回修改光标已离开的内容。
  没有候选仍允许手写悬空链接，沿用现有悬空提示；保存后重新计算链接图。

## 7. 实施与验收

按已批准的契约连带切片实施：schema → Knowledge 规则 → Storage 版本与回执 → Hub → API Client → Web。
本次由 Codex 完成全部代码，保持单个会话写仓库。每个 package/app 分别提交，交由用户 review。

验收必须覆盖：

1. 保存后再次打开直接编辑、刷新后保留修改；创建与已有笔记使用同一实时预览编辑器，不存在编辑/预览切换按钮。
2. 中文组合输入、选中替换、跨段粘贴、撤销/重做、代码/BibTeX/未知语法及 AI 注释的无损保留；HTML/XSS 不执行。
3. 外部编辑、两标签页、保存中继续输入、失败/断线、响应丢失、重放、重启恢复和文件删除；不能丢草稿或覆盖已检测到的外部版本。
4. 各入口导航保护及迟到响应；已保存旧回执不能让新草稿错误地显示已保存；无 ID/非法/私密/旧工作笔记不可借新接口写入。
5. 推荐上限 5、默认 3、展开收起、中文短词、当前段优先、标题加权、实际命中段落摘要、排除自己/私密、无匹配、快速输入/切换以及大库有界响应。
6. `[[` 空查询与左侧 A/B/C 一致，`[[X` 可找到原候选之外且仅正文命中的文件，删回空查询恢复 A/B/C；无匹配不回退伪结果。
   键盘和鼠标插入、IME Enter、取消、已有闭括号、别名、同名路径消歧、特殊字符、代码区域不触发；链接可解析。
7. 中英文、深浅色、390 px 窄屏；UI 真实输入验收，不只测字符串工具函数。

测试仅用 fixtures 合成数据和临时目录；运行 `bun run check`、契约导出、浏览器验收。
实现完成后安装本地试用包并保留本机已有修复；提醒人类试用，通过后再提交实现 PR。PDF、RAG、协同编辑与自动改名不在本期。

## 8. 上标引用与脚注（已批准）

### 8.1 两种插入形式

同一个 `[[` 候选弹窗提供「文字链接」和「上标引用」，无需另一套搜索入口。普通 Enter 插入文字链接；
Shift+Enter 或弹窗底部的「插入上标引用」插入脚注，提示快捷键。IME 组合期间不响应这两个提交动作。
文字链接适合在句子里提及某篇笔记，可用别名缩短标题；上标引用适合句末标注依据，避免长标题打断阅读。

示例呈现：`来源信息应和指令区分处理。¹`；同一句引用三个来源呈现独立可点击的 `¹,²,³`，不用含义不清的 `¹²³` 连号。
悬停或键盘聚焦时在标号旁弹出可见浮层，显示完整标题和脚注内容。点击有唯一笔记来源的上标直接打开目标笔记，导航仍受草稿保护；没有来源或含多个来源时显示卡片供选择。文末的编号仍可打开卡片编辑脚注。
文末自动展示按首次出现顺序排列的引用列表，每项可返回其对应正文位置；同一脚注多处引用列出返回入口。

### 8.2 Markdown 保存与编号

正文保存 Markdown 脚注引用，定义保存普通知识链接，示意：

```markdown
来源信息应和指令区分处理。[^lumio-ref-01ABC]

[^lumio-ref-01ABC]: [[Hines_2024_Spotlighting|Defending Against Indirect Prompt Injection Attacks With Spotlighting]]
```

示例标签已缩写，实际自动标签为 `lumio-ref-<ULID>`，仅是文内脚注标识，不是新实体 ID。
显示的 1/2/3 由文中首次出现顺序决定，不是永久标识；插入、删除或移动段落自动重排显示号，不批量改写正文中的标签。
脚注定义中的链接沿用安全 wikilink/相对 Markdown 路径规则，别名只是显示名称，不能用展示序号当笔记链接目标。
脚注定义和引用在一次编辑器事务中插入/撤销，保持光标在句末；不为插脚注跳到文末或抢走写作位置。

重复引用同一目标时，若已有本编辑器创建的「只有来源链接」的脚注则复用同一标签和编号；带用户注释的脚注不擅自合并。
保留手写脚注和任意已有标签，不替换成 Lumio 标签；重名定义、缺少定义等情况显示问题并保留原文。
删除最后一个引用时不静默删除定义或其中的用户注释；标记为未引用，允许用户显式清理。
未引用定义不出现在正文引用列表，但仍保留在 Markdown 中；沿用现有链接提取，定义中的链接依旧可能计入笔记链接图。

### 8.3 段落摘录与边界

候选中的匹配段落用于帮助人选来源，不自动把整段原文复制进笔记，也不把检索片段伪装成用户明确引用的证据。
默认脚注只记录来源链接；用户可以在脚注中添加自己的说明或摘录。匹配段落摘要不被当成永久块 ID，
本期脚注跳到来源笔记，不承诺来源段落改写后仍能精确定位。稳定段落锚点/逐句引文留待后续设计。

上标是 Markdown 文本的视图，不使用 `<sup>` HTML 或 `[[1]]` 伪造引用，不增加实体类型或数据库脚注表。
仅展示/编辑脚注仍需新增安全的解析与渲染；不能声称现有渲染器已经支持。
本设计目标是笔记来源脚注，不是 CSL/Zotero 文献格式管理或自动引文生成；不扩展 PDF/RAG 范围。

额外验收：数字自动重排、重复来源复用、长标题、三来源分别可点击、来源跳转/返回、键盘和触屏操作、
脚注与定义原子撤销、外部编辑脚注、未知标签和复杂定义无损、未定义/重名/未引用提示、AI 区块链接仍按原规则过滤。

## 后果

- 好处：创建、阅读、续写形成一个完整流程，关联资料在写作现场可见，链接仍由人选择。
- 成本：编辑器依赖、浏览器兼容与输入法验收；文件更新比创建需要更严格的版本和恢复处理。
- 兼容：文件结构、已有查询/能力契约、私密边界、外部编辑与原有链接语法保持兼容；新增的是人类写作接口。
