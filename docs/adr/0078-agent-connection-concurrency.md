# 0078 按 Agent 账号与后端限制并发

- 状态：Implemented（2026-11-18，人类批准后实施）
- 领域：连接身份、Work、Execution、Runtime
- 关联：ADR 0052、0054、0070、0077

## 提议

- 在「设置 → AI 模型」的连接配置中设定最多同时执行的轮次。Codex 默认 4，Claude Code 默认 2。Pi 按所用提供商、凭据及上游配额配置，接受包括 100 在内的正整数。尚未配置且无法归到已知后端的 Pi 使用并发 1 作为暂定默认值。多个连接指向同一个配额时，显示并编辑同一个上限。
- 名额按实际账号或后端配额跨 Runtime 合计。Codex 使用上游账号的稳定身份，不使用连接 ID、Runtime ID 或认证代次。Claude Code 和 Pi 复用可验证的上游账号或配额身份。无法核实本机登录、API Key 或第三方网关的真实配额时，由人显式关联到同一配额组。未关联的连接按引擎并入 Hub 的保守默认组，不能用新建连接或换设备自动取得独立额度。共享同一个上游配额的不同引擎可以关联到同一组。对外只展示连接名与限额，不展示凭据或身份指纹。
- Hub 在派发时绑定可验证的执行身份，在交付前原子占用账号或后端名额及项目名额。收到结束结果才释放，重试、断线和重启复用原占用。身份验证失效或与派发绑定不符时不启动，不自动换账号或切模型。由 Lumio 管理且使用同一配额的原生 Agent 轮次与例行任务也共用名额。需要限额的离线例行任务等 Hub 重新可用并取得名额后启动。Lumio 之外直接启动的会话不在计数范围内。
- 保留项目上限，默认 1。移除设备级并发设置及新版 Runtime 对本机并发变量的使用，调度只用项目和连接的可用名额。同一受管 worktree 的写入仍互斥。设置变更从下一次入场判断生效，无需重启。降限让已启动的轮次自然结束。
- 已登记的旧 Runtime 在升级前继续遵循原有本机并发约束，Hub 同样对其派发施加连接与项目限额。现有设备覆盖值停止参与新版调度，不转成账号上限。吸收切换时仍在运行的轮次后，再按新限额发出新任务。实施时同步更新相关设计分册与契约。

## 验收

- 同一 Codex 账号跨两台 Runtime 领取四个名额，第五个等待。另一账号可以独立执行。Claude Code 对应验证两个名额。Pi 后端配置 100，同配额组的另一个连接不能增加该组的容量。
- 提高与降低限额不重启 Runtime，已启动轮次不中断。设备可以同时执行多个账号的工作，项目上限依然生效。
- 覆盖账号换绑、重连、重新登记、重复同步、取消、未确认停止、旧 Runtime，以及例行任务离线恢复。使用合成账号、后端和独立测试目录。
