# 0044 Codex 连接级登录与助手对话控制

- 状态：Accepted（2026-11-09 人类批准）
- 日期：2026-11-09
- 接续：ADR 0041、0042 的 Codex 登录作用域及中断处理

## 问题

首版把官方登录放在每个对话的 `CODEX_HOME` 内，新对话需要重复授权。7420 还出现过保存同一连接后，已授权对话显示「就绪」却因连接修订号改变而被 Hub 拒绝。聊天页也同时显示「停止」和「中断执行」，并要求用户理解底层会话恢复、关闭和压缩。

## 决策

### 1. 一次授权，多段对话

- 设置 → AI 配置 → 连接提供登录、取消待授权、退出和重新授权。连接绑定 Lumio 所有者、Runtime 身份和 Connection ID。Profile 仍负责默认模型、思考强度，多个 Profile 可引用同一个连接。可用模型与档位来自该连接的官方客户端目录，实际能否使用以成功调用为准。
- 每个连接在所属 Runtime 有一份私有的、仅由 Lumio 启动的 Codex 登录进程使用的凭据存储。官方 `account/login/start(chatgptDeviceCode)` 和 `account/logout` 管理授权。登录进程不接收聊天、业务工具或工作区。Runtime 串行管理该连接的登录与刷新，校验账户身份和授权代次。显示名或 Profile 修改不增加授权代次；退出或换账号才增加。重登同一账号后可恢复已绑定该账号的历史；换账号时旧历史仍可查看，需另开对话才能聊天。
- 保留每段对话独立的 app-server、`CODEX_HOME`、thread、工作区、沙箱、审批及 MCP 凭据。会话进程通过官方 app-server 的实验性 `chatgptAuthTokens` 接口接收短期访问令牌，并通过 `account/chatgptAuthTokens/refresh` 向同一 Runtime 请求更新。首版候选方案由 Runtime 只读提取专用登录进程的受管缓存中的短期材料，仍由官方登录进程刷新。严禁传递 refresh token、复制整个缓存、读取个人全局登录或让会话沙箱访问连接凭据目录。访问令牌只在 Runtime 和会话进程间的私有 stdio 中传递，不进 Hub、浏览器、环境变量、日志、会话快照或业务备份。
- 固定版客户端的缓存读取、外部模式持久化和刷新行为是实现前的验证门槛。若不能证明缓存提取、单一刷新、账号校验及隔离均成立，就保留当前隔离模式，另提经过验证的登录方案。不得以共用所有 `CODEX_HOME`、凭据反代或绕过账号限制实现。

### 2. 最小契约范围

- `packages/schema` 定义原生连接登录状态和操作，Hub 提供按连接读取状态与执行登录、取消、退出的 human-only 接口。返回 `offline`、`signed_out`、`authorizing`、`ready` 或 `error`，以及必要的稳定错误码。待授权链接和一次性码仅向连接所有者显示，过期后移除，不进入持久聊天事件。账号标识仅使用 Runtime 计算的不可逆指纹。
- 原生通道协商连接授权能力。连接操作以命令 ID 幂等，状态回执包含连接 ID、Runtime、命令关联及授权代次，Hub 核对归属和新旧状态，忽略迟到回执。保持 Job2 与旧原生通道兼容。旧 Runtime 或离线时如实提示连接不可用。
- 新对话在发送首条消息时创建并绑定已验证的连接身份；打开已有对话时按需恢复底层进程，首轮开始前核验账号、沙箱和工具。保留既有会话和原生历史；旧对话可以继续使用仍有效的会话级授权，或在验证账号一致后改绑连接级授权。迁移绝不把原会话凭据提升为连接授权。连接或上下文不兼容要显示具体处理方式，不再显示可发送的「就绪」。

### 3. 聊天交互与中断

- 默认界面保留新对话、助手/Profile、模型、思考强度、发送及生成时的「停止」。首次发送的创建与接续使用幂等请求，不吞首条草稿；网页离开仅断开显示。空闲进程回收并保留原 thread，访问历史时按需恢复。手动恢复仅在自动恢复失败后出现；手动压缩放在高级菜单；关闭底层会话移出普通聊天界面。
- API 沿用可取消的请求，Codex 走官方 `turn/interrupt`。UI 等待实际终态。匹配该轮的 `interrupted` 事件且没有未确认的工具副作用时，保存已有正文，记为 `cancelled` 并允许在同一对话继续。停止与自然完成同时发生时以第一个已确认的终态为准。正在等待批准的操作拒绝后可安全结束。
- 中断回执丢失、进程未确认停止、未确认的命令或写操作仍按 ADR 0042 冻结和人工核查，禁止自动重发。关闭页面和断线不等价于用户点击停止。已完成的写操作保持原有审计与撤回规则。

## 验证和部署

1. 在合成状态中校验 Hub/Runtime 契约、幂等、并发刷新、过期、掉线、同账号重登及账号切换。验证连接凭据目录无法从两个会话的工具访问；检查短期令牌不出 Runtime，不落会话文件。
2. 真实官方客户端验收一次授权后连续新建两段对话，各自回复；重开第一段保留上下文。修改显示名和 Profile 后继续聊天。模拟退出和授权过期，检查从设置恢复。
3. 验证 API 和 Codex 都使用同一停止入口，停止普通回复后能继续，结果不明的写操作仍冻结。回归既有 API 对话、原生历史、Job2 和 Web 草稿。
4. 隔离环境通过 `bun run check` 后，备份现有 7420 程序、Hub 与 Runtime 状态，成对更新服务。验收现有数据、账号状态及恢复路径，并用纯文本消息试聊。保留回退程序与备份。
