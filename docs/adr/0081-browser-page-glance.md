# 0081 在浏览器所见中附加整页正文

- 状态：Implemented（2026-11-18，人类批准）
- 领域：macOS 捕获、浏览器插件、Inbox、助手
- 关联：ADR 0057、0062、0066、0067、0074、0076、0078

## 背景

macOS 捕获键能读到活动标签页链接，所见仍由窗口截图、OCR 和指点信息组成。Save to Lumio 可以从浏览器已加载的文档取得正文，浏览器自身的登录态与内网连接已足够。需要让同一次按键同时保留整页与指向的那一段。

两种原型对同一个本机登录页面生成了相同的存档正文，Hub 访问原站零次。已连接的插件在本机热态取文中位数约 3 ms，Swift 进程内 Apple Events 约 83 ms。两种方式在页面已经关闭后都无法取得文档，正文到达后台后关页都能入库。选择本地插件通信，复用现有插件的网页提取，并减少取文对特殊浏览器自动化设置的依赖。

## 行为

- 在已连接的浏览器前台按下捕获键时，同时启动浏览器正文快照、原有前台截图和选区读取。鼠标位置仍取按下时刻，长按的轨迹、语音和 Esc 取消沿用现行交互。网页快照使用独立的短超时。按键时的 App、窗口和文档必须一致，切页、导航或私密窗口无法确认时舍弃网页附件。
- 轻点时创建一次所见和一次 Inbox 捕获。对已取到正文的普通网页，用现有插件的网页提取规则生成存档正文，截图按现有方式随资料保存。保留原有指向段落及其判定，将它作为卡片重点。网页正文、截图和指向段落属于同一次捕获。
- 长按时把正文附在现有主对话所见。选区或指向段落优先进入当轮上下文，助手可在同轮按需读取有界的正文片段。明确要求收藏时，仍由现有的收藏所见工具将整页和截图存成一条 Inbox 资料。其余语音记录与工具授权沿用现行规则。
- 取文耗尽时间、扩展未连接、站点未授权或正文提取失败时，沿用原有的截图、OCR 和语音路径。取到正文后可以提示可以关页，Hub 确认入库后再提示收藏成功。整页以按下时浏览器已加载的主文为准，现有插件的普通网页格式和大小回退同样适用。
- 本 Hub 的工作台页面继续解析为 ResourceRef，按现有焦点规则处理。普通非浏览器 App、无附件的现有客户端和已存所见继续使用现有路径。

## 本机通信与权限

- Capture 监听回环地址，已配对的插件主动建立连接。配对由用户在两个客户端显式完成。校验扩展来源、使用独立于 Hub 令牌的本机配对秘密并双向验证连接。请求有一次性编号，带到期时间，只允许由前台设备上的真实捕获手势发出。配对可撤销，连接、请求和响应不转经 Hub。
- 插件只在用户为剪藏明确授权的站点上读 DOM。通过捕获键发来的请求依赖事先授予的站点权限，插件按钮仍可用浏览器提供的临时标签页授权。浏览器窗口和文档在读取前后校验，响应只交给匹配的按键。插件和桌面端都拒绝无痕窗口，沿用本机 App 排除规则。
- 浏览器端清理表单和输入控件，传送剪藏所需的文档正文、标题和来源。浏览器会话凭据、后台标签页及其他窗口与本次采集无关。网页正文按外部不可信资料处理，助手工具和审批权限沿用人发起的原请求。
- 随正文提交的来源网址仅用作资料标识和链接。允许语法有效、无嵌入凭据的内网 HTTP(S) 网址作为本地已读正文的来源。Hub 主动抓取、DNS 与每次重定向的校验仍按现有规则执行，收到正文无需访问原站。

## 契约与生命周期

- 在 `GlanceCreate` 中新增可选 `page` 声明，包含 `format`（`html` 或 `text`）和可选页面标题。来源使用同一记录的 `url`，含正文时要求该字段。沿用 `POST /v2/glances`，添加与声明一一对应的 multipart `page` 部分，正文为 UTF-8。Hub 校验编码、段数、字节、字符数与总请求体上限。正文沿用捕获的 2,000,000 字符限制并增加独立的 6 MiB 上限。更新后的服务继续接受既有的双段上传。
- 服务端复用 Inbox 的网页清洗和 Markdown 提取。原始 HTML 仅用于提取，清洗后的正文进入所见所属的私有托管文件。`Glance.page` 记录文件 ID、格式、字节数和 SHA-256，可记录清理时间。正文摘要参与上传幂等校验。`CaptureCreate.glance` 继续把所见作为一个输入引用，轻点无需额外的网页捕获请求。
- 收藏时将清洗后的整页作为资料原文，与现有截图归属、光标元数据和指向摘录一起发布。资料写入成功并转移截图归属后，回收冗余的临时正文附件。重试可从托管所见恢复，正文提取失败按现有截图路径保存。
- 对话只向当前轮的所有者提供有界的正文读取，使用既有所见与消息的关联校验。生成回复后按 ADR 0076 保留已验证的相关摘录和必要来源，释放临时正文。取消、故障恢复与超时未使用的所见同样清理。完整正文不写入助手请求快照、审计或普通日志。存储变更使用可选字段及既有托管文件，无需迁移旧数据。

## 验收

- 在 ego lite 打开浏览器可访问、Hub 无法访问的合成登录页。轻点一次，Inbox 只有一条捕获。存档正文与 Save to Lumio 对同一页提取的正文一致，包含首屏之外内容，截图、光标或选区仍可核对，Hub 对原站的请求计数为零。
- 在同页长按问选中的一段。正常流式语音、主对话回复和 Idea 存储照常，助手能在需要时取得当前手势的正文片段。只问问题时清理临时全文，要求收藏时保存整页和原有截图。
- 覆盖取文后马上关页、取文中切页、相同 URL 的重新载入、无痕窗口、扩展断线、站点未授权和 Esc。无法证明来自同一文档时保留原有捕获路径，避免把其他文档并入所见。
- 用 `@lumio/schema` 校验既有与新增的 Swift 请求样例。验证缺失、重复、超限的 `page` 部分，文件归属、并发重试、过期清理、主对话外读取拒绝以及工件发布中断后的恢复。实测使用合成页面、临时 Hub 与临时 vault。

## 实施次序

人类批准后，依次实现契约、Hub 的上传与归档、桌面并行采集、浏览器插件本机通信，各切片按模块边界验收。最后用真实物理捕获键在隔离 Inbox 做轻点与长按的端到端验收。
