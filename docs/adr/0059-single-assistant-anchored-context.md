# 0059 单入口助手：锚点式上下文、后台预读与分级提醒

- 状态：Accepted（2026-11-11 人类同意方向并要求先做着试用；同日 Codex 核实第 6 节技术问题。首期只做兼容 API 助手）
- 日期：2026-11-11
- 领域：Assistant、Work、通知
- 关联：ADR 0025 第 5 节（ResourceRef）、0029（能力目录）、0031（通知）、0032（任务模型）、0042（原生会话）、0051（锚点与 AI 笔记）、0060（工作台协议）、0061（判断闸门）
- 参考：[Super-agent 设计探索](https://www.bilibili.com/opus/1265361021143351318)（Router + Worker、Inline & Spill、链式召回、事件驱动、投机执行、Watchdog）

## 背景

现在每件事开一个对话，像 Codex 一样在线程之间切换。进行中的项目常有十个，一个项目里又有十个想法要分开讨论或合在一起讨论；
切换窗口的成本落在人身上，每次切换还要重新交代上下文。把所有内容塞进一个长对话又会互相污染、越聊越贵。

人要的是：**面前只有一个助手和一个工作台，对话不中断；上下文切换由助手完成。** 例：
看着一个待办问"这个优化怎么做" → 讨论几轮后整理成资料、改任务、派给 Codex → 转去聊论文，助手翻出相关邮件和段落 →
期间任务完成，助手在后台读完结果写好摘要，不打断论文讨论 → 人看到未读标记问"那个办得怎样"，助手直接回答。

## 决定

### 1. 一个主对话，线程变成内部索引
- 每个 human 有一个**主对话**，Web 默认进入它；已有的普通对话保留，不迁移。
- 主对话里每条消息关联**话题锚点**（ResourceRef，可以同时挂多个：任务、项目、笔记、资料、对话消息等）。
  锚点由助手在每轮开始时解析：来源是人当前的工作台焦点（ADR 0060）、人的原话、和上一轮锚点；拿不准指的是哪一个时先问。
- 锚点存在 Assistant 的**内部关联表**（消息 ID ↔ ResourceRef），不加到 `AssistantMessage` 契约上；旧消息自然没有锚点。
  以后 Web 需要显示或纠正锚点时，再定义公开字段或命令并走契约审批。
- 话题切换时，对话里出现一条分隔提示（"→ 回到：XX 优化"），人能马上纠正。锚点只用于组装上下文，不改变消息的归属和权限。
- 不做对话内容的语义检索：按锚点 ID 精确找回同一锚点的历史片段（延续 ADR 0051 第 1 节）。

### 2. 每轮按锚点重新组装上下文（Inline & Spill）
每轮发给模型的上下文不是"最近 N 条"，而是按预算组装：

| 放入方式 | 内容 |
|---|---|
| 完整放入 | 显式记忆；当前锚点对象（短的放全文，长的放摘要 + 续读入口）；同锚点历史片段的摘要与最近若干轮；主对话最近几条（保持口语连贯）；待告知的提醒 |
| 只放 ID + 一行摘要 | 锚点的一跳关联：前置/后续任务、引用的笔记、执行轮次、`derived_from` 来源 |
| 按需展开 | 模型用现有读取工具按 ID 取回；取回结果同样只内联下一跳的 ID 和摘要（链式召回） |

- **片段摘要在后台生成**：话题切走时记录离开片段的来源消息范围，后台生成摘要，按来源范围去重。
  切回时摘要还没完成，就在预算内放最近几轮完整交互，工具调用与其结果成对保留；首条回复不等额外的模型调用。
- 摘要是 AI 写的，标注来源消息范围，只作上下文，不进入知识。
- 讨论出结论时，助手提议**沉淀**：写 AI 笔记（ADR 0051，`derived_from` 记消息 ID）或改任务描述，按现有权限与提议规则执行。没有结论的讨论不写入记忆或知识。

### 3. 助手自己做轻活，重活派出去
- 改任务字段、写评论、写 AI 笔记、整理依赖等，助手按 ADR 0029 的 agent 权限直接做。
- 写代码、跑实验、装环境走现有委派（ADR 0056），执行器结果回到任务的轮次，不直接对人说话。
- 委派后对话不等待，执行结果以事件的形式回来（第 4 节）。

### 4. 后台预读与分级提醒
- 事件来源（首期只接 Lumio 内部）：一轮执行结束（交付 / 提问 / 失败）、新的待批准提议、Inbox 捕获完成、Watchdog 报告。
  邮件、日历、群聊等外部事件暂不接入：噪音大，且属于不可信输入。
- **预读**：事件到达后，后台以助手的 agent 身份读取结果，写摘要挂在对应锚点上，不进入主对话正在进行的那一轮。
  摘要优先写成任务评论（`work.task.comment` 是独立记录，不递增任务 revision），以事件 ID 做幂等。
  预读若还要改任务字段，带 `expected_revision`；冲突时重读，重新判断摘要或修改是否仍然成立，不盲目重试。
- **分级**：先用规则判断（ADR 0031 的"需要你处理"一律视为重要），其余交给判断闸门（ADR 0061 第 3 节）分为：
  - 重要：在主对话当前一轮结束后插一条简短提醒，不打断正在聊的话题；同时照常推送。
  - 待处理：进入 Today 的"待处理"列表并在相关对象上标未读，人每天开始时一起过。
  - 静默：只更新对象状态。
- 人问起时（"那个办得怎样"），锚点切到该对象，直接用预读摘要回答。

### 5. Watchdog 与提前探索
- **Watchdog**：一个数据库 Routine，定时检查卡住或空转的轮次、长期无进展却仍在"进行中"的任务、离线的 Runtime。
  它只读、只写一条巡检报告事件，不停止或修改任何东西；处理由人在主对话里决定。
- **提前探索**：人给想法或任务标记"可以帮我探索"后，后台开一个探索片段：查资料、读知识库、在只读或沙箱范围里做小验证，
  产出一份 AI 笔记（可行性、已有工作、最小验证方法），`derived_from` 指向该想法。
  - 只在人标记过的对象上运行，助手不主动扫描全库找可探索的东西。
  - 只读：不改人写的内容，不占用 GPU 跑大实验；需要执行器时按 ADR 0049 声明只读阶段权限。
  - 每次探索有 token 与时间上限，用完即停并汇报。
  - 有价值才提醒（"探索有结果"），没价值记一句"试过，无发现"后归档。结果默认只是 AI 笔记，人决定是否继续。

### 6. 原生 Codex 会话（后续）
- 首期锚点组装只用于兼容 API 助手。
- 原生会话以后在话题切换时用 `thread/inject_items` 追加锚点上下文（Lumio 固定的 Codex CLI 0.166.0 上已用隔离进程验证可用）。
  追加内容会留在线程历史里，旧话题不会消失；来回切换时的回答质量与 token 开销实测后再定是否启用。

## 不做
- 不在界面上按项目或想法切换对话窗口。
- 不把未定论的讨论写入显式记忆或知识。
- 不让后台片段直接对人说话；对人说话只有主对话这一个出口。

## 分期
1. 主对话、内部锚点关联表、按锚点组装上下文、后台片段摘要、话题分隔提示、沉淀提议（兼容 API 助手）。
2. 后台预读与三级提醒（依赖 ADR 0061 第 3 节）。
3. Watchdog Routine 与提前探索。
4. 原生 Codex 会话接入（第 6 节，实测后决定）。
