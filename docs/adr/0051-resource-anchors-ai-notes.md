# 0051 资源锚点、知识来源与独立的 AI 笔记

- 状态：Accepted（2026-11-10 人类批准，并授权直接合并）
- 日期：2026-11-10
- 领域：数据、AI 协作与权限
- 相关：ADR 0012 第 3 节（AI 区块）、0014、0018、0025 第 5 节（ResourceRef）、0029、0034、0035、0038

## 背景

1. **对话和执行记录里有知识，但不应该变成知识库。** 决策过程、实验失败原因经常只出现在 Assistant 对话或某一轮执行里。
   曾考虑把对话串、执行记录也像笔记一样做检索和自动匹配；但原始记录噪音大（寒暄、走错的路、工具日志），
   AI 的错误输出一旦被匹配和引用，就会变成"有出处的错误"。同时，AI 已经能读取任务、对话和知识，也能写入。
2. **人写的和 AI 写的混在同一份正文里。** ADR 0012 第 3 节让 AI 把总结写进笔记正文的 `<!-- lumio:ai -->` 区块。
   实际用下来：区块难以可靠解析，页面很乱；人想区分"我的想法"和"AI 的摘要"时，只能靠注释标记。
   典型场景是：把一篇资料放进来，先让 AI 读一遍写摘要；人看完摘要再看原文、写自己的笔记。这里天然是两份内容。

## 决定

### 1. 只有知识长期保存，其他内容靠锚点回溯
- **知识是唯一要长期整理和检索的内容。** 任务结果、对话里有价值的部分，由 AI（或人）**写成知识**，并在知识里记下来源；
  不把对话串、执行记录本身纳入知识检索或自动匹配。
- 对话、消息、任务、轮次、日志、产物都已有稳定 ID（`<前缀>_<ULID>`，ADR 0025 第 5 节的 ResourceRef），
  **ID 前缀全局唯一，能直接推出所属模块**，所以引用只需要 ID，不需要再写模块或父对象。
  需要回到原始上下文时，按 ID 找回；粒度到消息（`amsg_…`）、Job（`job_…`）或日志事件（`evt_…`）。
- 写入知识的时机由人或任务决定（"把这个记下来"、任务说明或计划要求写入）。**本 ADR 不做自动写入，也不做"是否写入"的自动提议**；以后需要时另议。

### 2. 知识的来源字段 `derived_from`
- 所有知识实体新增可选的公共字段 `derived_from`：字符串数组，每项是 Lumio ID（任何模块）或外部 URL。
  它说明"这条知识是从哪里来的"，不计入链接图（链接图仍只来自正文，ADR 0018）。
- post 已有同名字段（ADR 0012 第 4 节），含义相同，提升为公共字段后放宽为"ID 或 URL"；旧值仍然合法。
- AI 写知识时由 Lumio 填写它的来源（例如当前对话的消息 ID、当前 Job、被总结的资料 ID）；人也可以手动填写。
- 索引保存 `derived_from` 的反向关系，用于"这个对话/资料被哪些知识引用了"。索引可重建。

### 3. 正文里引用非知识资源：`lumio:<ID>` 链接
- 正文里引用对话、消息、任务、Job 等非知识资源，用标准 Markdown 链接：`[当时的讨论](lumio:amsg_01J…)`。
  链接文字由人或 AI 写，资源不可见或已删除时作为提示。
- 存 ID 而不是 Hub 地址：Hub 换机器、换端口后链接仍然有效。Web 渲染为可点击的链接（经 Hub 的权限检查后打开）；
  外部编辑器里点不开，但 ID 可复制查找——用外部编辑器本来就是最不正式的用法（ADR 0022）。
- 知识之间的引用仍用 `[[文件名]]` 或相对路径的 Markdown 链接（ADR 0018、0022），不改。
- `lumio:` 链接进入索引的跨模块引用表，不进入知识链接图和全库图谱（ADR 0040）。

### 4. 独立的 AI 笔记（`ai-note`）
- 新增知识类型 `ai-note`，ID 前缀 `ain`，位于 vault 的新目录 `ai/notes/`。**AI 写的知识一律是 AI 笔记**；
  看文件位置就知道是 AI 写的，不需要在正文里逐句打标签，外部编辑器和 agent 沙箱也能按目录区分。
- 字段：公共字段（`id`、`type`、`title`、`created`、`updated`、`tags`、`derived_from`）以及
  `generated_by`（写入者身份 `act_…`，由 Hub 填写）、`model`（可选，生成所用模型）。
- **一份 AI 笔记就是一件事**：一篇资料的摘要、一次对话的结论、一个任务的结果。重新生成摘要就是更新这份 AI 笔记，ID 不变。
- **人的笔记通过链接嵌入 AI 笔记**：在自己的笔记里单独一段写一个指向 AI 笔记的普通链接
  （`[[文件名]]` 或 `[AI 摘要](../../ai/notes/xxx.md)`）。Web 把"单独成段、指向 AI 笔记的链接"渲染为可折叠的嵌入卡片，
  并标明是 AI 写的；其他编辑器里它就是一个普通链接。不新增嵌入语法。
- **归属规则**：人笔记正文里的文字都是人的；嵌入进来的都不是。想采用 AI 的某句话，就自己改写进正文，改写后归人。
  人的笔记指向 AI 笔记的链接是人写的链接，计入链接图；**AI 笔记正文里的链接不计入人的链接图**，图谱中可按"AI 写的"区分或隐藏，
  导出参考文献时不从 AI 笔记里取引用（延续 ADR 0012 第 3 节、0018 的规则）。
- 人可以在 Web 里修改 AI 笔记（例如改正错误），作者不变。AI 更新 AI 笔记时必须带上它读到的版本（SHA-256，ADR 0035），
  人在此之后改过就返回冲突，由人决定，不静默覆盖。
- 搜索、相关推荐照常包含 AI 笔记，结果标明是 AI 写的。

### 5. AI 区块不再用于知识笔记
- 知识笔记**不再新增** `<!-- lumio:ai -->` 区块；AI 产出改为第 4 节的 AI 笔记。ADR 0012 第 3 节在本 ADR 实现后对知识笔记失效。
- 解析器继续识别已有区块（排除出链接图和引用导出），保证旧文件不出错；旧任务/例行任务笔记的兼容写回（`round-N`、`routine-run` 等）不受影响。
- 现有 vault 主要是测试数据，不做迁移；需要时人可以手动把区块内容移成 AI 笔记。

### 6. 权限
- agent（含内置助手、派出的每轮凭据、用户自己的 agent）新增两项能力，**可直接执行并记录执行者**，与新建任务同级（ADR 0029）：
  - `knowledge.ainote.create`：在 `ai/notes/` 新建 AI 笔记，正文、标题、标签、`derived_from` 由调用方给出，其余元数据由 Lumio 填写。
  - `knowledge.ainote.update`：带版本更新一份 AI 笔记的正文、标题、标签与 `derived_from`。
- agent 仍然**不能新建或修改其他类型的知识**，也不能删除 AI 笔记（删除只有人能做，ADR 0038）。
- `derived_from` 指向 agent 不可见的资源时（例如私密实体）拒绝写入；读取 AI 笔记时，来源可见性按读取者重新检查，
  不可见的来源只显示 ID 与"不可见"，不泄露内容。私密实体规则不变（`life/` 对 agent 不可见）。

### 7. 被引用资源的删除
- 删除对话、任务等资源时（ADR 0038），如果有知识通过 `derived_from` 或 `lumio:` 链接引用它，删除确认里提示引用数量。
  删除仍然允许；知识中的引用保留，打开时显示"已在回收站"或"已删除"，从回收站恢复后自动恢复。
- 对话与执行记录默认长期保留（不因未被引用而自动清理）；它们只是不进知识检索。

## 后果（好处 / 代价）

- 好处：知识库只有经过筛选的内容，检索质量和可信度不被原始记录拖累；所有内容都能从知识回到原始上下文；
  人写和 AI 写在文件层面分开，正文干净，解析简单；agent 有了一个边界清晰、低风险的写知识入口。
- 代价：
  - 契约变更：新增 `ai-note` 类型与 `ain` 前缀、公共字段 `derived_from`、vault 目录 `ai/notes/`、两项 agent 能力。
  - 想把对话内容变成知识，需要人或任务明确要求写入；没写入的内容只能按 ID 找回，搜不到。
  - Web 要实现 AI 笔记的嵌入渲染与 `lumio:` 链接解析；外部编辑器里 `lumio:` 链接点不开。
  - 否决的方案：把对话/执行记录全文索引并自动匹配（噪音大、AI 错误会被当成知识）；
    在人笔记里继续用 AI 区块或逐段来源标签（解析难、页面乱）；给所有类型加 `author` 字段代替独立类型
    （来源只靠字段，agent 写错就无法区分，权限边界也不如按类型和目录清楚）。
