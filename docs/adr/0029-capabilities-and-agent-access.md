# 0029 能力目录与 agent 访问：Lumio 是记录与决策的地方，agent 是可替换的手

- 状态：Accepted（2026-11-04 人类在对话中批准方向与三条权限选择；`packages/schema` 的具体字段在 R3-1 的 PR 中由人类审阅）
- 日期：2026-11-04
- 领域：AI 协作与权限 | Hub 与运行 | 安全 | 客户端
- 影响：修订 ADR 0014 第 2 节（skill 由能力目录生成、覆盖数据库 Work）、ADR 0016 第 3 节的规则表（agent 可读 v2、可做低风险写入）、
  ADR 0025/0027 中「助手默认不启用生产工具」与「模型只用命令配置」；DESIGN 第 4.7、4.8、5、8 节。
  新增 `packages/schema` 契约（能力目录、助手模型配置接口、一轮访问凭据），由 R3-1 起草。
- 实施说明：[R3-0](../tasks/R3-0-capabilities-agent-access.md)

## 背景

内置助手已经有工具循环，但没有接任何工具，Hub 的 v2 Work/Execution 接口也只允许 human，所以助手不知道用户的任务。
`skills/lumio/SKILL.md` 还停留在 v1（查笔记、旧任务笔记），外部 agent（Codex、Claude Code、pi）同样看不到数据库里的任务。
派到执行器上的 agent 拿不到任何令牌（P2-2 有意去掉了执行器令牌）。助手模型只能用 `lumio hub assistant setup` 在命令行配置。

作者的问题是产品方向：做封闭的独立系统（把人留在 Lumio 页面、限制外部 agent），还是做开放的服务（任何 agent 都能接入）。
另外还想以后做自己的 agent / harness。

## 决定

### 1. 定位：Lumio 是记录与决策的地方，agent 是可替换的手
- 会快速贬值的是 agent 本身（模型与 harness 每月换代）；不贬值、越用越有价值的是结构化的任务、知识、执行历史，
  「派出 → 一轮轮汇报 → 人审批」的流程，以及让人一眼看清、快速决定的界面。Lumio 的价值放在后者。
- 数据与规则只在 Hub。内置助手、用户自己的 Codex、别人的 pi、以后作者自己的 agent，都通过**同一套能力**、
  受**同一张权限表**约束进来。不靠限制外部 agent 引流；人做决定的事（总览、审阅、审批、派活、编辑）放在 Lumio 页面上。
- 作者以后的 harness 是能力层的又一个使用者，不与系统深度绑定。

### 2. 能力目录：一处定义，三个出口
- `packages/schema` 新增能力目录：每项有稳定名称、读/写类别、参数与结果契约（复用现有 Work/Execution/查询契约）、给模型看的简短说明（英文为基准、带中文）。
- 首批能力：
  - 读：搜索笔记、读笔记、出链与反链；列出与查看任务、项目；列出与查看执行轮次、例行任务；列出待批准的提议。
  - 写（agent 可直接执行，见第 3 节）：新建任务、新建项目、更新任务与项目字段、评论任务。
- 出口：
  1. **内置助手**：Hub 把目录注册为助手工具，在进程内通过各模块的公开接口执行（ADR 0025 的工具身份规则不变）。
  2. **外部 agent**（有 shell）：`lumio` 命令覆盖全部能力并支持 `--json`；`skills/lumio/SKILL.md` 的命令表由目录生成，
     其余说明手写；测试保证目录里每一项都有对应命令。skill 与 agent 看到的说明用英文（开源用户）。
  3. **MCP**（没有 shell 的客户端，如手机上的对话应用）：以后需要时从同一目录生成薄适配层，不在本 ADR 实施（ADR 0014 第 2 节不变）。
- 每次执行都先经 Hub 的 `authorize`，规则只写在规则表里；出口不重写业务逻辑。

### 3. 权限：按操作的风险定规则，不按调用方
- `agent` 角色（内置助手的工具身份、外部 agent 令牌、一轮访问凭据）：
  - **读**：允许（私密内容按第 4 节）。
  - **低风险写入直接执行**：新建任务与项目、改标题、描述、期限、项目、依赖、负责人、评论；
    任务状态只能在 todo / active / waiting / paused 之间改。
  - **永远拒绝**：把任务标为 done 或 cancelled（ADR 0019：AI 的汇报只是资料，不决定完成）、派出任务、新建或修改例行任务（会触发执行）、
    决定提议、高权限命令（仍只由 runtime 申请）、删除或归档。
- 每次写入记录执行者身份；Web 在任务的讨论与属性变更里显示「由 codex@server」。内置助手的每次写入在对话里显示一张变更卡片，
  带「撤回」按钮（按记录的旧值反向修改，带 `expected_revision`，冲突时说明而不覆盖）。
- 修改负责人仍不派活（ADR 0025）。

### 4. 私密内容：只有内置助手、只在人的对话里可读
- 外部 agent 令牌和一轮访问凭据**任何情况下**都读不到私密实体（ADR 0014 第 6 节不变）。
- 内置助手在**对话所有者是 human** 的对话里，可以按需读取私密实体。这条路径只在 Hub 进程内组装的工具上存在，
  任何 HTTP 令牌都不能通过它获得私密内容。每次私密读取在对话中作为工具调用显示，并记入审计。
- 带来源的记忆仍按 agent 权限重查（ADR 0025）；私密内容不写入记忆。

### 5. 派出的 agent：每轮一把临时访问凭据
- 执行器为一轮启动 agent 时，Hub 在交付该轮时附带一把**只属于这一轮**的 agent 凭据：身份是该负责人（如 `codex@server`，
  不存在时由 Hub 创建 agent 身份），权限同第 3 节；该轮结束、取消或 lease 失效时立即作废，Hub 只存哈希。
- 执行器把它作为 `LUMIO_HUB_URL`、`LUMIO_TOKEN` 只交给这一轮的 agent 进程，并在该轮的 agent 配置里放入 lumio skill；
  执行器自己的令牌仍不交给被执行的程序（P2-2 的规则不变）。
- 凭据只在交付时传输，不写入 Job 记录、日志或结果。

### 6. 用户自己的外部 agent
- `lumio agent add <名称>`（human，经 Hub API，任何已登录的 CLI 可用）创建 agent 身份并显示一次令牌；`lumio agent list / revoke`。
  现有 `lumio hub actor / token` 保留，作为 Hub 本机上的底层管理命令。
- `lumio skill install [--for codex|claude|pi]` 把 skill 装到对应 agent 的 skill 目录，并写入连接 Hub 所需的配置（令牌不写进 skill 文件）。
- Web 设置页增加「已连接的 agent」：列出身份、最近活动，可吊销。

### 7. 助手模型在 Web 设置页配置
- Hub 增加 human 专用的助手配置接口：读取时返回地址、模型、密钥是否已设置；写入时先用最小请求验证，
  再原子写入 Hub 服务的私有环境文件（ADR 0027 的位置与键名不变），并在**进程内重新加载**适配器，不再重启服务。
  密钥只写不读，不出现在响应、日志与审计详情里。`lumio hub assistant setup / status / clear` 改用同一实现。
- 设置页「助手模型」一节：地址、模型、密钥（只显示「已设置」）、「测试连接」。可提供常见服务的地址预设，
  但**仍不预设默认供应商或模型**（ADR 0025 第 7 节不变）。

## 后果

- 好处：用户在 Lumio 页面或在自己常用的 agent 里都能查待办、记任务；别人用别的 agent 也能接入；
  权限只在一张表里，新增出口不增加权限设计；作者以后的 agent 直接获得全部能力。
- 代价：agent 第一次获得写权限，需要可撤回与可追溯的界面；每轮凭据增加了 Job 交付的一个字段与吊销逻辑；
  能力目录与 CLI、skill 要保持同步（由生成与测试保证）。
- 风险：外部 agent 可能被提示注入诱导做低风险写入；由「不能完成、不能派活、不能审批」的硬边界与可撤回界面兜底。
