# 0041 AI 配置底座：Connection、Profile 与用途绑定

- 状态：Implemented（M1-0 首版；明确列为后续的工作仍未实施）
- 日期：2026-11-08
- 关联：ADR 0027、0029、0042；任务 M1-0
- 授权：用户审阅 V0-0 结果与修订交接稿后要求“直接实现……部署在本地……ADR 和代码一起推上去……试用完成之后决定是否合并”。本 ADR 和必要契约连带修改属于该授权；不自动合并或发布。

## 背景

Assistant 的单个 `LUMIO_ASSISTANT_*` 配置与执行器的引擎/模型参数分散。需要一处描述 API 或原生客户端、模型与思考设置，同时保留 Assistant 连续对话和 Job 摘要汇报的不同表现。V0-0 验证表明：模型目录、思考档位、推理续接与恢复配置都依赖供应商，不能把订阅登录当成通用 API。

## 决定

### 1. 三个对象，权限与模型分开

| 对象 | 保存内容 | 边界 |
|---|---|---|
| Connection | 类型、设备、API 地址、凭据状态、revision | 凭据只在调用设备；公有视图不返回密钥 |
| Profile | Connection 引用、引擎、模型、思考模式/原生 effort、revision | 不授予工具、文件或网络权限 |
| 用途绑定 | Profile、用途、工作区、审批/沙箱、工具清单、超时、revision | 每个运行保存独立快照，互不继承权限 |

首个切片支持 `lumio × deepseek/doubao/openai-compatible` 和 `codex × codex-account`。API 在 Hub 调用；Codex 在 Connection 指定的 Runtime 调用。其他设备上的 API、Claude/pi 原生会话与跨引擎组合需要独立验证。Connection 的类型/设备创建后不可更改，换来源新建连接。

API 密钥存入 Hub 私有业务数据库，不进入公开配置、日志或消息；部署备份须按含凭据材料保护。原生官方认证只存在该会话专属 CODEX_HOME，Hub 保存不含邮箱的账户指纹和登录状态，不保存或同步 refresh token。

### 2. 模型与思考设置

- 模型用原生 ID；Codex 的 `default` 明确表示客户端报告的默认模型，不猜目录第一项。
- 思考模式当前为 `default/off/on`，只有已验证 DeepSeek 组合开放 on/off 与 low/high/max；Codex 的 effort 从当前官方模型目录读取。未知兼容服务、豆包的显式思考参数暂不开放，不推测映射。
- 优先级：本轮覆盖 → Profile 默认；用途绑定保留安全配置，当前不提供另一套可编辑模型覆盖。
- 不支持的模型或 effort 拒绝，不静默降档、换服务或换计费来源。换模型后界面要求重新选择有效 effort。
- 修改 Profile 影响下一轮，当前轮冻结交付快照。原生连接、安全和上下文变化需要新环境，不用 Profile 修改绕过权限。

### 3. 事实记录

原生会话保存绑定快照；每轮交付记录保存 Profile revision、请求模型/effort、消息、上下文与 command ID；官方状态事件独立记录实际报告的模型/effort和数值用量。未报告不以请求值冒充。客户端默认模型与逐轮实际模型分开。订阅用量不折算虚构 API 金额。

API 保留现有每步模型请求快照；推理内容和 encrypted state 作为独立协议状态持久化并用于工具续接，不作为聊天正文显示。旧 DeepSeek 配置仍默认关闭思考，新 Profile 可显式启用；只对已验证官方端点发送供应商思考参数。

### 4. 兼容与交付范围

设置页同批交付 Connection/Profile，Assistant 从同一列表选择。旧单 API 配置继续工作，按所有者首次读取配置时生成兼容 Profile，原文件保留。已有 API 对话不强制迁移。

Job/Routine 将沿用同一配置对象，但其 Profile 接线、AgentRun 快照与 Job 协议 3 协商是后续切片；本次不改变 Job 协议 2，也不声称执行器任务已支持所有新 Profile。执行器当前新增的是原生 Assistant 通道，与 Job 版本独立。

所有新增公开对象在 `packages/schema` 定义，JSON Schema 由脚本生成；不新增 packages/ai，不把网络或进程逻辑放进领域包。存储使用新增表，不改写旧对话数据；回退旧程序必须停止试用服务并保留包含新增表的完整备份。

## 取舍

统一配置减少重复设置，但供应商能力仍需逐一验证。首版固定安全绑定，牺牲任意目录、任意网络或插件配置；任务迁移延后，避免把连续会话与可靠 Job 的协议升级混成一次发布。
