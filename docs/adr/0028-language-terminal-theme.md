# 0028 界面语言（默认英文、中文环境用中文）、终端输出样式、Web 主题切换

- 状态：Accepted（2026-11-03 人类在对话中提出并批准）
- 日期：2026-11-03
- 领域：工程基础 | Hub 与运行 | 客户端
- 影响：所有面向人的输出（`apps/cli`、`apps/hub`、`apps/runtime`、`apps/web`、`packages/platform` 及各包抛出的错误说明）；
  DESIGN 第 2、4.8、6 节；ADR 0021、0027 的升级规则补充一条。不改 `packages/schema` 的数据格式（错误仍是 `code` + `message`）。
- 实施说明：[R2-0](../tasks/R2-0-language-terminal-theme.md)

## 背景

Lumio 要开源给其他人使用，但所有命令行输出、Hub 返回的错误说明和 Web 界面目前都只有中文。作者自己用中文。
v0.2 升级时还暴露了终端输出的问题：下载进度一行一行往下刷、不能原地更新，没有进度条，大小按字节显示；
`doctor` 的 ✓/✗ 没有颜色，「提醒」项（例如助手未配置）也显示成 ✓。Web 只能跟随系统的明暗主题，不能手动切换。

## 决定

### 1. 语言：默认英文，中文环境用中文
- 支持两种语言：英文 `en`（默认）与简体中文 `zh`。以后加语言只需增加一份文案表。
- **命令行**（`lumio` 及其所有子命令）：按顺序取第一个非空值决定语言——`LUMIO_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG`；
  以 `zh` 开头（如 `zh_CN.UTF-8`、`zh-Hans`）用中文，其他一律英文。`LUMIO_LANG=en|zh` 可强制指定。
- **后台服务**（Hub、执行器）的日志一律英文，不随系统语言变化，方便检索与报告问题。
- **Hub 返回的错误说明**：按请求的 `Accept-Language` 选择（`zh` 开头用中文，否则英文）。CLI 按自己的语言发送该头，Web 按界面语言发送。
  错误 `code` 不变，客户端不得依赖 `message` 的文字做判断。
- **Web**：首次打开按浏览器语言（`navigator.language`）决定，界面上可以切换「English / 中文」，选择保存在本浏览器（`localStorage`），
  与登录无关；切换立即生效，不刷新页面、不丢草稿。`<html lang>` 随之更新。
- **文案组织**：每个 app 一份按键索引的文案表（英文为基准，中文逐条对应），由测试保证两份表的键完全一致、带参数的占位符一致；
  库代码抛出的错误带 `code` 与参数，由 app 层翻译成文字（AGENTS.md 已要求库只抛带 code 的错误、app 负责输出，这里延续）。
  不引入第三方 i18n 依赖。
- 范围：面向人的界面输出。开发文档（`docs/`、ADR、任务说明）仍用中文；面向用户的 README 以后另行提供英文版，不在本 ADR 内。
  vault 里的内容、用户写的任务正文、agent 的汇报原文不翻译。

### 2. 终端输出样式
- **进度**：标准错误是终端时，下载在同一行原地刷新（`\r` 覆盖，结束时换行），格式为
  `Downloading lumio 0.2.1 (darwin-arm64)  [██████████░░░░░░░░░░]  52%  12.1 MB / 23.2 MB  3.4 MB/s`；
  宽度随终端列数收缩，太窄时省略进度条只保留数字。不是终端时（CI、日志）只在开始与结束各输出一行。
- **大小**：一律按合适的单位显示（B、KB、MB、GB，1024 进制，保留一位小数），不显示原始字节数。时间与速度同理。
- **颜色与符号**：终端支持颜色时，通过为绿色 `✓`，失败为红色 `✗`，提醒为黄色 `!`（例如助手未配置、可选项缺失）；
  汇总行按结果着色。遵循通行约定：设置了 `NO_COLOR`、输出不是终端、或 `TERM=dumb` 时不输出颜色；`FORCE_COLOR` 强制输出。
  符号使用普通 Unicode 字符，不用 emoji（emoji 宽度不一致、部分终端显示为方框）。
- `doctor` 的检查结果分三种：通过、提醒、失败；只有失败计入「未通过」，退出码只在有失败时非零。

### 3. Web 主题
- 界面提供主题切换：「跟随系统 / 浅色 / 深色」，默认跟随系统；选择保存在本浏览器，切换立即生效，PWA 窗口的标题栏颜色（`theme-color`）随之变化。

### 4. 升级不需要逐版进行（补充 ADR 0021、0027）
- `upgrade` 始终直接升级到目标版本（默认最新），不经过中间版本。下载前先确定目标版本，已是该版本且安装布局正确时不下载。
- **发布包格式或安装布局变化时，必须保证上一个已发布版本的升级程序能直接完成升级**（如 v0.2.0 的转发垫片做法），
  新程序首次运行时自行完成剩余的布局调整或给出一条明确提示；不要求用户「先升到某个中间版本」。

## 后果

- 好处：非中文用户可以直接使用；中文用户体验不变；终端输出与常见工具一致；Web 可手动选主题。
- 代价：所有面向人的字符串要迁移进文案表，改动面广但机械；新增文案必须同时写两种语言（测试强制）。
  Hub 的错误说明多了一个依赖请求头的分支。
