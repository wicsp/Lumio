# 0005 Runtime 执行语义

- 状态：Implemented（2026-10-31 补记：P2-2、P2-3 实现；协议见 ADR 0019 与 `packages/schema/src/job.ts` 第 2 版）。第 4 条的 transport 只实现了"每台设备一个执行器"（ADR 0019），`ssh` 不做
- 日期：2026-10-22
- 领域：Hub 与运行

## 背景
Runtime 要在 Mac 和服务器上执行 AI 任务和实验脚本。网络中断、进程崩溃、设备重启都会发生；
有些任务有副作用（发消息、改文件、占用 GPU 跑实验），重复执行的代价很高。

## 决定
1. **一轮 Job 只执行一次。** 一个任务可以有很多轮，每一轮是一个 Job，只执行一次（修订见文末）。
   每次指派带一个 lease；Hub 只接受被指派的执行器、带着当前 lease 的回报，过期的回报不能覆盖新结果。
2. **退出码 0 不等于成功。** Attempt 的输出必须通过该 Job 声明的结果 schema 校验，才能标记为成功。
3. **不自动重试。** Runtime 重启后，如果无法确认某一轮的结果，将其标记为 `unknown`，交给人决定。
   任何失败都不自动重试；想重试由人派出新的一轮（修订见文末）。
4. **engine 与 transport 分开。** engine 是执行什么（`claude-code`、`codex`、`pi`、`script`），
   transport 是在哪里执行（`local`、`ssh`、远端 runtime）。两者独立组合，适配器只负责翻译各自的协议。
5. **适配器锁定 CLI 版本范围。** 每个 agent CLI 的适配器声明自己验证过的版本，
   版本超出范围时拒绝执行，不按旧格式猜测新输出。
6. **执行安全。** 不经过 shell（参数用数组传递）；只执行登记过的程序路径；
   密钥在执行节点上才解析成真实值，不出现在 job、参数和日志里。

## 后果
- 好处：网络和设备不稳定时，不会出现重复执行、结果互相覆盖或"假成功"。
- 代价：job 协议和 Hub 的状态机比"发出去等结果"复杂；P2 之前不需要实现，但协议设计要预留位置。

- 2026-10-26：取消"一个 Job 多次 Attempt"与自动重试，改为"一轮只执行一次，重试由人派出新的一轮"；
