# G1-0 用手柄操作 Lumio

依据：无新 ADR（纯 Web 输入方式，不改契约与权限，按 ADR 0036 只写任务说明）；规则见 `docs/design/web.md`「手柄」一条。
按住说话依赖 [ADR 0055](../adr/0055-speech-input-and-output.md) 与 [S1-0](S1-0-speech.md)。
必读：`docs/DESIGN.md`、`docs/design/web.md`、`apps/web/README.md`。
实现：人类安排 Codex 实现 G1-1～G1-3（2026-11-11）；改动只在 `apps/web`。

## 目标

躺在沙发上只用手柄处理 Lumio 里最常见的决定：在 Today 和任务列表里移动、委托、完成，处理「需要你处理」的验收、提问与批准，按住一个键说话。

## 原则

- **手柄只是另一种输入**：按键映射到 Web 已有的界面命令（与键盘快捷键、命令面板同一组），不新增权限，不绕过任何确认。
- **危险操作不能单键完成**：高权限审批（`exec.privileged`）、彻底删除、批准含 full 权限或钩子的计划，需要长按确认，且卡片照常展示完整内容（完整 argv、job、runtime、理由）。
- **不改现有布局**：本期不做放大字号的"沙发模式"，只在现有界面上加焦点、提示条与按键。以后全局 AI 助手上线、界面重写时再做沙发模式（人类决定，2026-11-11）。
- **键位存在浏览器里**（与主题、语言相同），不进 Hub。

## 交互设计

### 1. 手柄模式
- 收到任何手柄按键或摇杆输入即进入手柄模式：显示焦点框与底部按键提示条。
- 鼠标移动、点击或键盘输入即退出：焦点框与提示条隐藏，界面与现在完全一致。
- 退出再进入时，焦点回到上次的位置；找不到（条目已消失）时落到同一列表最近的一项。

### 2. 两层焦点：区域 → 条目
- **LB / RB** 在模块之间切换（与侧栏顺序一致，首尾不循环）。
- **十字键 / 左摇杆** 在当前区域的条目之间移动；按住连续移动（约 400 ms 后开始，每 100 ms 一步）；左摇杆死区 0.5。
- 到达区域边缘时继续按同方向，按屏幕位置移到相邻区域（例如列表 → 详情、卡片组 → 下方列表）；没有相邻区域时不动，不循环。
- 对话框、菜单、详情抽屉打开时焦点锁在其中；按 **B** 关闭后焦点回到打开前的条目。
- 焦点移动时自动滚动，让焦点条目完整可见。

### 3. 按键含义固定，提示条写具体动作

| 键 | 含义 | 例子 |
|---|---|---|
| A | 主要动作 | 列表条目：打开详情；详情里：该对象的主要动作；验收卡片：接受；提议卡片：批准 |
| B | 返回 / 取消 | 关闭对话框、退出详情、取消录音、长按中途取消 |
| X | 这一项最常用的快捷动作 | 待办：委托（等同 E1-4 的「委托」）；验收或提议卡片：拒绝（G1-4 后自动开始录音说理由） |
| Y | 完整操作菜单 | 完成、取消、换执行者、删除等；菜单用十字键选、A 执行、B 关闭 |
| 右摇杆 | 滚动当前详情、diff、日志 | |
| RT（按住） | 按住说话（G1-4） | |
| View（中间小键） | 执行当前底部提示上的按钮 | 删除后的提示上为「撤销」，委托后的提示上为「查看运行」；没有提示时无效 |
| Menu / Start | 打开命令面板 | 面板内十字键选、A 执行 |

- **在 Today 待办上按 A 是打开详情，不是完成**（人类决定）。完成在 Y 菜单里，或在详情里再按 A。
- 当前焦点上某个键没有动作时，提示条不显示这个键，按了也没有反应（不报错）。
- **底部提示条**只在手柄模式显示，随焦点即时更新，最多列 5 个键。

### 4. 防误触、撤销与反馈
- 需要长按的操作：按住 A 约 1 秒，焦点框上显示进度；中途松开即取消；完成后才发请求。
- 沿用现有带按钮的提示（`dom.ts` 的 toast）：提示可见期间按 View 等同点它的按钮。本期不为原本不能撤销的操作（如委托）新增撤销。
- 手柄支持震动（`vibrationActuator`）时：成功轻震一次，失败或被拒绝震两次；不支持时略过，不提示。

### 5. 文字输入
- 手柄不做屏幕键盘。需要输入文字的地方（拒绝理由、回答提问、给 Assistant 发消息）在 G1-4 之后用 RT 按住说话；之前打开输入框，等待键盘输入。
- 输入框获得焦点时，除 B（退出输入框，焦点回到条目）与 RT（录音）外，手柄不触发界面命令。

### 6. 键位标注
- 首版按 Xbox 布局标注（下 A、右 B、左 X、上 Y），使用 Gamepad API 的标准映射（`mapping === "standard"`）按位置读取按键。
- 非标准映射的手柄：显示提示"这个手柄的按键可能对不上，可在设置里改键"，不阻止使用。
- PlayStation / Switch 的专属标注以后再做。

## 测试

- Gamepad API 用可注入的读取函数封装，单元测试用模拟的手柄状态序列驱动：按下 / 松开 / 长按 / 连发、死区、两个手柄、断开重连。
- 焦点导航测试在 DOM 测试环境中构造区域与条目，验证边缘跨区、对话框锁定与返回原位。
- 长按测试：未满时长松开不发请求；满时长只发一次请求。

## 验收要点

- 手柄断开再连上后继续工作；两个手柄同时连接时只响应最后按过键的那个。
- 页面不可见时停止轮询（不在后台持续占用 CPU）。
- 鼠标一动，焦点框与提示条立即消失；再按手柄回到原焦点。
- 高权限审批、彻底删除：单按 A 不执行，长按完成才执行；中途松开即取消。
- Today 待办上按 A 打开详情而不是完成；X 委托与点「委托」按钮的结果完全一致。
- 改过的键位刷新后保留；「恢复默认」可用。
- 现有键盘快捷键（⌘K、1–6、C、/、J/K、⌘↵）行为不变。
- 只用手柄走一遍：LB/RB 切到 Today → 十字键移到一条待办 → X 委托 → View 查看运行 → B 返回 → 移到「需要你处理」→ A 打开验收 → 右摇杆滚动 → A 接受。

## G1-6 交互统一（2026-11-11，人类确认后由 Claude 实现）

G1-1～G1-4 上线后自查发现：输入框里只有 B 和 RT 有效（说完无法发送）、讨论框和助手输入框走不进去、RT 总是跳到助手、录音时 B 不停止、Y 菜单来源不一且能绕过长按、B 有三种含义、提示条只留 5 个键且按出现顺序截断。统一为以下规则，取代上文与之冲突的部分。

**层级**：页面 → 详情 → 弹层（对话框、菜单、命令面板）→ 输入中 → 录音中。B 永远退一层；提示条左侧显示当前层（浏览、详情、菜单、对话框、输入中、录音中）。

| 键 | 页面 / 详情 | 弹层 | 输入中 | 录音中 |
|---|---|---|---|---|
| A | 打开或主要操作；落在输入区上为进入输入 | 执行选中项 | 提交所在表单（发送、发表、确认）；不在表单里时完成编辑；内容为空时不显示 | 结束并插入 |
| B | 详情回列表；页面回到最近访问的另一个模块，没有记录时回 Today，在 Today 不动 | 关闭 | 退出输入（文字保留） | 取消这一句 |
| X | 这一项的第二个操作，提示条写明（待办上委托，卡片上拒绝） | — | — | — |
| Y | 这一项的全部操作；需要长按确认的操作不进菜单 | — | — | — |
| RT | 按住说话，松开结束（不再区分快按） | 弹层里的输入框 | 当前输入框 | 松开即结束 |

- **输入区是可以移到的一项**：助手输入框、任务讨论、卡片里展开的回答框标记为 `data-pad-input`；焦点在卡片上而卡片里有展开的回答框时，A 先进入输入。
- **RT 的目标**：当前输入框 → 焦点条目里的输入区 → 本页的主输入区 → 打开助手。弹层打开时只用弹层里的输入框，菜单打开时不响应。提示条区分「按住说话」与「按住说给助手」。
- **提示条**：按键顺序固定为 A、X、Y、B、RT、View、LB、RB、Menu；A 与 B 始终显示，其余最多再显示 4 个，空间不够时从后往前省略。长按进度显示在 A 的提示旁，不往页面里插元素。
- 提示框返回（「查看运行」后按 B 回到原处）由页面层 B 的访问记录统一处理，不再单独记录。
