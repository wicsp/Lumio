## 目标

知识管理、工作管理、执行与自动化、内置助手分别拥有业务规则、接口和数据。
知识文档保留 Markdown，Task/Project 等结构化状态由数据库负责，详细过程使用 JSONL/文件。
四个业务模块共用 Hub，Runtime 保持独立。保留可靠执行、权限与隐私边界。

## 后续切片

每个切片开工前写独立任务说明，列明 ADR 小节、具体 package/app、兼容性与测试。
普通切片仅改一个 package/app；契约及其必需的调用方变更作为显式连带切片，不跨包顺手整理。

### R0-1 契约与兼容矩阵

- 范围：schema（Claude 起草）、导出物及精确列出的必要调用方。
- 依据：ADR 0025 第 1、3、4、7、8 节。
- 交付：知识/旧笔记格式与 Work 业务对象分离；Task/Project/Routine、讨论、正文版本、引用、操作结果和查询格式。
  定义 Assistant、日志、备份切片需要的新增格式，允许分批起草批准。
- 先确定旧 v1 客户端可读可写范围、新接口版本与 Runtime 协议兼容矩阵。
- 验收：输入输出 strict/loose 规则明确，旧格式 fixture 仍可解码，版本不兼容明确失败，JSON Schema 从 Zod 生成。
- 门槛：具体字段、ID 前缀、公开导出、助手权限变更均需人类批准。

### R0-2 Knowledge 能力边界

- 范围：先建立 `packages/knowledge` 的真实用例与接口；将 core 调用迁移、Storage 提取和 Hub 接入拆成后续独立切片。
- 依据：ADR 0025 第 1、2、3、4 节。
- 交付：知识元数据、引用与链接规则、查询/编辑用例；文件与索引通过注入接口使用。
  旧 core 可临时转发，保持已批准的现有结果与错误行为。
- 验收：知识测试不启动 Work/Execution/Assistant；链接、私密、卡号过滤、引用导出与外部编辑不回归。
- 不做：读取真实 vault、更改已有人写正文、调整 citekey 或编辑器设置。

### R0-3 Storage、迁移基础与可恢复备份

- 范围：`packages/storage`；接入 Hub、CLI 各自独立切片。
- 依据：ADR 0025 第 2、3、5、6、8 节。
- 交付：基于现有 SQLite 的显式事务接口、版本化迁移、模块表所有权、文件暂存与登记、备份/恢复和清单校验。
  逐步搬移已有实现，避免重写已验证的队列与 SQLite 可靠性逻辑。
- 验收：纯合成库升级失败可恢复，事务回滚不留下半个派活，备份可恢复引用文件，缺失或损坏文件明确报告。
- 门槛：数据库成为业务权威前必须完成备份恢复；不把备份能力留到真实切换之后。

### R0-4 Work 最小可用切片

- 范围：`packages/work`，Storage/Hub/API Client/CLI 的接入按独立任务或批准的契约连带任务推进。
- 依据：ADR 0025 第 1、3、4、5、8 节。
- 交付：Project/Task 创建、列举、查询、更新、讨论、描述编辑、关联与依赖检查。
  状态、负责人和执行情况分开；Work 不直接访问知识目录，不因改负责人自动派活。
- 验收：不挂载知识目录也能使用；描述的版本冲突不会覆盖他人修改；子任务/依赖合法性由 Work 判断。
- 编辑验收：外部编辑副本只包含正文，保存失败保留内容；新描述不改变已派出 Job 的输入快照。

### R0-5 Execution 与跨模块派活

- 范围：`packages/execution`、Storage、Hub 协调、Runtime 适配、CLI/API Client 按切片推进。
- 依据：ADR 0025 第 1、4、5、8 节。
- 交付：Job/Routine 独立于任务笔记，续接与输入快照、显式派活、Work 执行关联、可靠结果通知。
  Task 不要求 Job；Execution 接受没有 Task 的独立工作。
- 验收：同一 Task 不并发派两轮；旧有 lease/ack/outbox、取消/超时、失联恢复和 unknown 行为不回归。
  事务中途失败不交付 Job；重复请求与重复结果不重复创建、执行或更新进展。
- 不做：状态不明自动重跑、跨设备工具路由、自动多 agent 接力或放开派活权限。

### R0-6 JSONL 与文件产物

- 范围：先实现 Storage 日志/文件接口，再逐一接入 Hub 与 Runtime。
- 依据：ADR 0025 第 3、5、6 节。
- 交付：批准格式的 JSONL、原始日志保留、单写入者、分段归档、校验与待交回确认。
- 验收：不完整末行、归档截断、中间损坏分别处理；重复归档不重复登记；Job 完成与归档未完成可分别显示。
  文件准备后、登记前崩溃可恢复，数据库不会把半个文件当成可用产物。

### R0-7 Assistant 最小可用切片

- 范围：`packages/assistant`；模型/工具/Storage/Hub 适配分切片接入。
- 依据：ADR 0025 第 1、2、3、7 节。
- 交付：对话/消息/轮次、流式响应、可注入模型与工具、上下文快照、工具操作记录。
  初版只接批准的能力，不默认升级为 human 身份；记忆策略与真实模型提供方在独立任务中确定。
- 验收：用假的模型和工具可独立测试；失败和重启不重复提交有副作用的操作；来源私密限制不因记忆或快照消失。
  关闭 Assistant 后知识、任务和执行功能照常使用。
- 不做：顺带建设完整权限系统、模型路由、多用户或自行决定模型供应商与密钥。

### R0-8 旧数据导入、版本切换与兼容退出

- 范围：Storage 导入器、Hub 切换、CLI 命令与文档按独立切片完成。
- 依据：ADR 0025 第 4、6、8、9 节。
- 交付：有版本的 dry-run 清单、显式 apply、源内容校验、重复导入去重、旧路径/引用映射、升级与回退说明。
  保留 ID、未知字段、原文、Job、轮次、会话与历史来源。旧 frontmatter 退出控制但保留可核查来源。
- 运行中 Job、待交回结果、ID 冲突、源文件变化、未解决链接映射均需在 apply 前处理，不能悄悄继续。
- 验收：迁移纯 fixture 数据前后逐项核对；启动/导入不派活；重复 apply 不重复建对象；中断后可恢复。
  旧客户端不能误改新对象，旧格式兼容不得给新对象伪造路径或继续文件控制。
- 回退验收：停止新版本后恢复配套数据库/文件快照，核对需要另行保留的新数据，再运行旧版。
- 真实数据切换由人类单独安排，本重构测试不读取真实 vault 或停止已安装服务。

## 最终验收

1. 四个模块都有真实业务入口与测试，不能以新建空目录或空包验收。
2. 每类数据有唯一权威来源；结构化 Work/Execution 不再依赖笔记文件控制。
3. Knowledge 独立可用；Work 无知识目录可用；Execution 无 Task 可用；Assistant 无真实模型可测试。
4. 依赖检查强制模块隔离与原有边界；schema 仍只依赖 zod；业务核心不做网络请求。
5. 关键跨模块用例有授权、契约、事务、重放、恢复与兼容测试，原有高权限和私密保护不回归。
6. 备份恢复、JSONL/文件损坏处理、迁移 dry-run/apply 和回退用合成数据通过。
7. Bun 固定 1.3.x；每个提交前 `bun run check` 通过；无未解释的新依赖。
8. 各实现 PR 同步更新 DESIGN 与 ADR 已实现的小节，交叉 review 后再合并；不改旧 Implemented ADR 原文。
