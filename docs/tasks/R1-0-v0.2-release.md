# R1-0 v0.2 上线：一个程序，Hub 自带 Web，助手接上，一条命令切到数据库任务

- 依据：[ADR 0027](../adr/0027-v0.2-rollout.md)（Accepted，2026-11-02），以及 ADR 0021、0022、0025、0026
- 契约：不改 `packages/schema`
- 目标：作者在 Mac（Hub + 本机执行器）和实验室服务器（执行器）上从 v0.1.6 升到 v0.2.0 后：
  本机只有一个程序 `lumio`；浏览器打开 Hub 地址就是 Web 工作台，并可「添加到程序坞」当 App 用；助手可以对话；
  任务在数据库里，派给 `pi@server` 能跑通。整个过程只需要 `lumio upgrade`、`lumio hub switch --retire-legacy`、
  `lumio hub assistant setup` 和服务器上的 `lumio-runtime upgrade`。

## R1-1 Web 资源入口（Claude）

- `apps/web/src/entry.ts`：供 `apps/cli` 引用的唯一入口，导出：
  - `buildWebAssets(): Promise<WebAssets>`：构建浏览器 JS/CSS；
  - `webFiles(assets, options): Map<路径, { body, type }>`：`/`（页面）、`/assets/app.js`、`/assets/app.css`、`/manifest.webmanifest`、
    `/assets/icon.svg`、`/assets/icon-192.png`、`/assets/icon-512.png`、`/assets/apple-touch-icon.png`、`/favicon.svg`；
  - `WEB_CSP`：页面使用的 CSP 字符串。
  页面里的 API 地址通过 `<meta name="lumio-api-base">` 告诉浏览器（Hub 提供时为空，即同源根路径；旧的独立 Web 服务为 `/hub`），
  登录存储按页面所在来源隔离。
- PWA：清单含名称、短名、图标、`display: standalone`、主题色；iOS 需要的 `apple-touch-icon` 与 `apple-mobile-web-app-*` meta；不注册 Service Worker。
- 旧的 `apps/web` 独立服务与代理在本切片保持可用（R1-2 删除）。
- 测试：`webFiles` 的内容与类型；清单可解析且图标路径都存在；同源模式下浏览器端请求不带 `/hub` 前缀（单元测试 + 浏览器端会话测试）。

## R1-2 一个程序与 Hub 提供 Web（Codex）

照 ADR 0027 第 1、2、6 节实现。要点：

- **入口**：`apps/cli/src/main.ts` 按 argv[0] 的文件名（`lumio` / `lumio-hub` / `lumio-runtime`）和第一个参数（`hub` / `runtime`）分派到
  `apps/hub/src/entry.ts`、`apps/runtime/src/entry.ts`（把现有 `main.ts` 的逻辑搬进可调用的 `run(argv)`），其余走原 CLI。
  `--version` 在各种调用方式下一致。`.dependency-cruiser.cjs` 只为 `apps/cli/src/` → `apps/(hub|runtime|web)/src/entry.ts` 开例外。
- **Web 资源**：发布构建时由构建脚本调用 `apps/web` 的 `buildWebAssets()`，以文本方式嵌入程序（做法可参考已关闭的 #66 的 `build-binary.ts`）；
  源码运行（`bun apps/cli/src/main.ts hub serve`）时即时构建。资源经 `startHub` 的新选项传入，Hub 不 import `apps/web`。
  没有传入资源时（测试、旧调用）Hub 的 `/` 返回 404，其余行为不变。
- **Hub 的浏览器保护**：照 ADR 0027 第 2 节；页面与资源使用 `WEB_CSP`。Hub 现有的 API 路由、鉴权与审计不变。
- **发布与安装**：`release.yml` 每个平台只编译一个 `lumio`（嵌入 Web 资源），压缩包内含 `lumio`；`install.sh` 安装它并建立
  `lumio-hub`、`lumio-runtime` 两个符号链接；`install.sh runtime` 同样只装一个程序。
- **setup / upgrade**：新写出的 launchd/systemd 服务用 `lumio hub serve`、`lumio runtime serve`；`upgrade` 从 v0.1.x 升级时
  替换程序、建立链接、改写本机服务文件并重启；结束时打印 Web 地址（Hub 的本机地址，以及设置了 `LUMIO_PUBLIC_URL` 时的对外地址）
  和「运行 `lumio login-code --name web` 获取配对码」。
- **doctor**：检查 `GET <Hub>/` 返回页面、`/assets/app.js` 可用、版本一致；三个调用名都指向同一程序。
- **清理**：删除 `apps/web/src/server.ts`、`proxy.ts`、`config.ts` 与对应测试、ADR 0026 相关的 Web 配置变量文档；
  `scripts/web-demo.ts` 改为启动带网页的临时 Hub（单端口）；`apps/web/README.md` 与 DESIGN 4.8 同步。
- **验收**：合成环境（临时 HOME、假 launchctl/systemctl，沿用现有 setup 测试）中验证：三种调用名分派、服务文件新写法、
  从 v0.1.x 布局升级（旧服务文件被改写、旧程序被替换为链接）、Hub 提供页面与资源、CSP 与 Origin/Host 检查（允许本机地址与对外地址，拒绝其他来源）、
  编译出的程序在空目录中能提供网页。

## R1-3 助手模型配置（Codex）

照 ADR 0027 第 4 节实现，补充：

- 交互式输入时，地址给出示例（`https://api.openai.com/v1`、`http://127.0.0.1:8080/v1`），不内置供应商列表。
- 验证请求：一次非流式的最小 Chat Completions 请求（单条 user 消息「ping」、限制输出长度），超时 30 秒；
  按 401/403、404、其他 4xx、5xx、网络错误分别提示；任何输出都不包含密钥。
- 环境文件读写复用 setup 现有的私有文件与原子写入，保留其他项不变；重启服务复用 setup 的 launchctl/systemctl 逻辑；
  非托管环境时说明需要手动重启。
- `docs/assistant.md` 的「配置模型」改为以这条命令为主，环境变量写法保留为高级用法。
- 验收：合成 HTTP 服务模拟成功、401、404、超时；环境文件权限 600、其他项保留、密钥不出现在 stdout/stderr/日志；`status` 与 `clear`。

## R1-4 退役旧笔记与一条命令切换（Codex）

照 ADR 0027 第 5、6 节实现，补充：

- `migrate retire` 的回执与 `migrate apply` 写同一张回执表，使现有 `legacyControlDisabled` 判断直接生效；
  回执区分 `kind: retire | apply`（只在存储层，不进 schema）。已有任何回执时 retire 与 apply 都拒绝，并说明何时以何种方式切换过。
- 拒绝条件只有：Hub 未停止 / 状态目录被占用；仍有旧笔记来源的 Job 处于 queued/assigned/running/waiting_for_human。
  不检查旧笔记里的开关字段和未暂停的旧例行任务（退役后它们不再生效）。
- `switch --retire-legacy` 按 ADR 0027 第 6 节的顺序执行，每一步打印一行进度；本机执行器的状态目录从 setup 写入的配置读取。
  服务由 setup 管理时自动停/启；非托管时说明需要人手动停止，不继续。
- `upgrade` 完成后检测到旧笔记模式时，打印两种选择与对应命令（退役 / 按 `docs/migration-v2.md` 导入）。
- `selftest`：派活与写回改为创建数据库任务（标题带「自检」与时间），完成后设为 done；`--notes` 保留为兼容别名，不再写 vault。
- 验收：合成 vault（含 fixtures 里的旧 Task/Routine 笔记，带打开的派活开关）retire 后，修改旧笔记不产生 Job；回执与备份存在且备份可 verify；
  有未结束的旧 Job 时拒绝；`switch` 任一步失败时停止并输出已完成步骤；selftest 在合成执行器上通过。

## R1-5 发布与真实切换（人类 + Claude）

1. R1-1 至 R1-4 合并后打 `v0.2.0` 标签，CI 在 macOS 上跑检查并发布。
2. Mac：`lumio upgrade` → 按提示运行 `lumio hub switch --retire-legacy` → `lumio hub assistant setup`。
3. 实验室服务器：`lumio-runtime upgrade`。
4. 按 [`README.md`](README.md)「等人类回来处理」中的 v0.2 验收清单逐项确认，结果记入该节。
