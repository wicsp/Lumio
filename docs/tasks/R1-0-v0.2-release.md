# R1-0 v0.2 上线：装好就能用 Web 和助手，一条命令切到数据库任务

- 依据：[ADR 0027](../adr/0027-v0.2-rollout.md)（Accepted，2026-11-02），以及 ADR 0021、0022、0025、0026
- 契约：不改 `packages/schema`
- 目标：作者在 Mac（Hub + 本机执行器）和实验室服务器（执行器）上从 v0.1.6 升到 v0.2.0 后，
  浏览器直接打开 Web 工作台，助手可以对话，任务在数据库里，派给 `pi@server` 能跑通。整个过程只需要
  `lumio upgrade`、`lumio-hub switch --retire-legacy`、`lumio-hub assistant setup` 和服务器上的 `lumio-runtime upgrade`。

## R1-1 `lumio-web` 单程序（Claude）

- `apps/web/src/main.ts`：读取环境配置（ADR 0026 的三个变量）并启动；`--version` 打印版本（与其他程序一样用 `LUMIO_VERSION` 编译常量，开发时为 `dev`）。
- 资源嵌入：构建脚本先生成浏览器 JS/CSS，编译入口通过生成的模块把它们作为字符串带进程序；运行时 `startWeb` 使用嵌入资源，不调用 `Bun.build`、不读源码。
  `bun start`（开发）保持即时构建。
- 测试：编译出的程序在空目录（没有仓库源码）中启动，`/`、`/assets/app.js`、`/assets/app.css` 正常返回，`/hub/health` 经代理到达合成 Hub；`--version` 正确。
- `apps/web/package.json` 增加 `build:binary`，给 R1-2 的 `release.yml` 调用。

## R1-2 安装与升级管理 Web（Codex）

- `release.yml`：每个平台额外编译 `lumio-web`，打进同一个压缩包；macOS 同样 ad-hoc 签名。
- `install.sh`：安装第四个程序到 `~/.local/bin`；`install.sh runtime` 不变。
- `lumio-hub setup`：在 Hub 机器上写入并启动 Web 服务（macOS `io.lumio.web`，Linux `lumio-web.service`），环境为
  `LUMIO_WEB_LISTEN=127.0.0.1:4317`、`LUMIO_WEB_HUB_URL=<本机 Hub 的本地地址>`；可重复运行；结束时打印 Web 地址和
  「运行 `lumio login-code --name web` 获取配对码」。端口被占用时说明是谁占用（沿用 P2-12「另一个 Hub」的做法）。
  `--no-web` 跳过（给只想用 CLI 的用户）。
- `upgrade`：替换 `lumio-web` 并重启 Web 服务；没装过 Web 服务的旧安装在升级后自动补装（与 setup 相同的写法）。
- `lumio doctor`：Web 服务在运行；`/health`（Web 自己的）版本与 Hub 一致；经 Web 代理访问 Hub `/health` 成功。失败时给出修复命令。
- 验收：在合成环境（临时 HOME、假 launchctl/systemctl，沿用现有 setup 测试的做法）中验证服务文件内容、重复运行、升级补装与 doctor 各分支。

## R1-3 助手模型配置（Codex）

照 ADR 0027 第 2 节实现，补充：

- 交互式输入时，地址给出示例（`https://api.openai.com/v1`、`http://127.0.0.1:8080/v1`），不内置供应商列表。
- 验证请求：一次非流式的最小 Chat Completions 请求（单条 user 消息「ping」、限制输出长度），超时 30 秒；
  按 401/403、404、其他 4xx、5xx、网络错误分别给出提示；任何输出都不包含密钥。
- 环境文件读写复用 setup 现有的私有文件与原子写入；保留文件里其他所有项不变。重启服务复用 setup 的 launchctl/systemctl 逻辑；
  非托管环境（没有 systemd 用户服务）时说明需要手动重启。
- `docs/assistant.md` 的「配置模型」改为以这条命令为主，环境变量写法保留为高级用法。
- 验收：合成 HTTP 服务模拟成功、401、404、超时；检查环境文件权限 600、其他项保留、密钥不出现在 stdout/stderr/日志；`status` 与 `clear`。

## R1-4 退役旧笔记与一条命令切换（Codex）

照 ADR 0027 第 3、4 节实现，补充：

- `migrate retire` 的回执与 `migrate apply` 写同一张回执表，使现有 `legacyControlDisabled` 判断直接生效；
  回执内容区分 `kind: retire | apply`（只在存储层，不进 schema）。已有任何回执时 retire 与 apply 都拒绝，并说明已在何时以何种方式切换。
- 拒绝条件只有两个：Hub 未停止 / 状态目录被占用；仍有旧笔记来源的 Job 处于 queued/assigned/running/waiting_for_human。
  不检查旧笔记里的开关字段、未暂停的旧例行任务（退役后它们本来就不再生效）。
- `lumio-hub switch --retire-legacy`：按 ADR 0027 第 4 节的顺序执行，每一步打印一行进度；本机执行器的状态目录从 setup 写入的配置读取。
  服务由 setup 管理时自动停/启；非托管时说明需要人手动停止并退出，不继续。
- `lumio upgrade` 完成后检测到旧笔记模式时，打印两种选择与对应命令（退役：`lumio-hub switch --retire-legacy`；导入：`docs/migration-v2.md`）。
- `lumio selftest`：派活与写回改为创建数据库任务（标题带「自检」与时间），完成后设为 done；`--notes` 的含义改为「保留自检任务」（默认完成后保留，所以 `--notes` 可作为兼容别名，不再写 vault）。
- 验收：合成 vault（含 fixtures 里的旧 Task/Routine 笔记，带打开的派活开关）上 retire 后，修改旧笔记不产生 Job；
  回执与备份存在且备份可 verify；有未交回的旧 Job 时拒绝；`switch` 任一步失败时停止并输出已完成步骤；selftest 在合成执行器上通过。

## R1-5 发布与真实切换（人类 + Claude）

1. R1-1 至 R1-4 合并后打 `v0.2.0` 标签，CI 在 macOS 上跑检查并发布。
2. Mac：`lumio upgrade` → 按提示运行 `lumio-hub switch --retire-legacy` → `lumio-hub assistant setup`。
3. 实验室服务器：`lumio-runtime upgrade`。
4. 按 [`README.md`](README.md)「等人类回来处理」中的 v0.2 验收清单逐项确认，结果记入该节。
