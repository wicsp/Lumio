# P2-6 高权限命令的门：`lumio sudo`

- 负责：后端（Codex）　Review：Claude
- 相关 ADR：0019（第 7 节）、0016（需要批准的操作、提议）
- 涉及：`packages/schema`（把 `ExecPrivileged` 加入 `Operation`，已批准）、`apps/runtime`、`apps/hub`、`apps/cli`
- 依赖：P2-4

## 目标
在人类自己的服务器上，agent 需要 root 时只能通过 `lumio sudo <命令>` 申请；人批准后由执行器以 root 执行一次。
P2 中只能在 Mac 上用命令批准；P3 加入飞书批准与审批模型。

## 范围
1. **执行器侧**：
   - `lumio sudo <程序> [参数…]`（随执行器一起安装的小程序）：只能在执行器派出的一轮之内使用
     （通过执行器设置的环境变量 `LUMIO_JOB` 和一个只对这一轮有效的本地凭据定位当前 Job）；
     向执行器本地发起申请，阻塞等待结果，最长等待时间可配置（默认 30 分钟），超时则以非 0 退出并打印"未获批准"。
   - 执行器把申请作为 `exec.privileged` 操作提交给 Hub，携带 runtime、job、argv。
   - 批准后：执行器通过一个**只允许执行器账号调用、只接受已批准申请**的 root 助手程序执行这条命令
     （安装方式写进 `infra/` 说明：sudoers 中只给这个助手程序免密），输出返回给 `lumio sudo` 的调用者。
2. **Hub 侧**：`exec.privileged` 的授权结果一律为"需要批准"→ 生成提议；`lumio proposals` 列出；
   `lumio proposals accept|reject <ID>`（只有 human）；结果通过 `RuntimeSync` 交给执行器（在契约外增加字段需先提 ADR，
   优先复用提议查询）。
3. **审计**：申请、批准或拒绝、执行结果都记录；命令原文记入审计，不记录输出。
4. 学校服务器这类没有 root 的执行器：不安装助手程序，`lumio sudo` 直接返回"此执行器不支持提权"。

## 不做
- 不做审批模型、飞书批准（P3）；不做"同类命令自动批准"的规则。

## 验收标准
1. `bun run check` 通过。
2. 测试（用一个假的 root 助手程序记录收到的命令）：批准 → 执行一次；拒绝 → 不执行，调用者退出非 0；
   等待超时 → 不执行；不在一轮之内调用 → 拒绝；agent 令牌不能批准；同一申请不能被执行两次。
3. 人类在自己的服务器上手动验证一次：让 agent 安装一个软件包，在 Mac 上批准，确认安装成功。
