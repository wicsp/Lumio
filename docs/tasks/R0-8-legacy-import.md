# R0-8 旧工作数据的显式导入与回退

- 依据：ADR 0025 第 3、4、5、6、8 节；既有 MigrationPlan/Entry、Work 与 Execution v2 契约。
- 范围：Storage 导入器；Work/Execution 的历史导入用例；Hub 管理命令、旧文件控制隔离；Runtime 离线准备与独占租约。
  这些是批准迁移契约的必要调用方，不改变 v1 或 Job 协议，不引入第三方依赖。
- 状态：分支内完成，最终交叉审查待完成；只测试合成数据，不运行真实数据迁移或操作已安装服务。

## 流程与边界

先在旧兼容路径暂停例行任务并完成执行和结果/文件交回；停止每台 Runtime，运行显式 prepare-migration，
校验没有未完成/待交付数据后仅清空派生计划缓存。再停止 Hub，做完整业务备份，dry-run 后显式 apply。
apply 必须确认执行器准备完成，并校验备份与当前数据库逻辑内容匹配、源内容与清单匹配。

保留稳定 ID、全部原始字节、未知字段、正文、历史 Job、轮次与会话。历史执行只导入 settled 关联，
修订 1 表示迁移基准；历史输入从 Job 中保存的真实 prompt/argv 取得，不伪造当时的 Markdown 修订。
例行任务以原来已经暂停的状态导入，由人后续显式恢复。导入不派活，不重放结果，不写知识文件。

原文件保留作只读兼容来源；数据库保存原字节和路径映射。旧文件即使改了 ID、正文或开关，也不能覆盖数据库、派新 Job 或写回新结果。
新内容通过 Work/Execution 入口修改，源快照可单独导出。已有 Markdown 链接仍指向原文件，路径到业务 ID 的清单可查询。
首次完整 apply 在同一事务写入切换回执；随后整个工作区关闭旧 Task/Routine 文件控制和旧派活/追问接口，
新建、复制、移动或更换 ID 的 Markdown 也不会恢复旧控制。知识文件仍可读写，不因此失去知识能力。

## 验收

- dry-run 不写业务数据；活动执行、待派活、活动 Routine、重复 ID、缺失项目、源变化与旧备份均拒绝 apply。
- 同一事务保存来源档案、Work/Execution 对象、历史关联与回执；故障回滚；同一清单重放不重复导入。
- 轮次缺号时下一轮仍取最高轮次 + 1；完整 Job/会话记录不变，不生成虚假的历史执行。
- Runtime 未停止或有待交付数据时不能清缓存；进程退出自动释放独占租约。
- 合成 Hub 重启后修改旧文件不派活；旧接口不能操作新对象；回退恢复迁移前备份与原文件。
- CLI 和全部测试不使用真实 vault、模型、设备或安装服务；提交前 bun run check。
